# MC 1702 — the IBM PC coprocessor of the МС 0585 (reverse-engineering knowledge base)

Status: **hardware reconstructed from the factory drawings, software and
documentation catalogued.** Everything known about the «Электроника МС 1702»
coprocessor board, gathered from three independent kinds of sources: the
factory documentation (ТО/ПС/Э3/СБ scans), the disassembly of a host program
(`MSDOS.EXE`, RT-11), and the original software trove recovered from tis.kz
(the ПРОС-side host, the factory board diagnostic, the ЭЛДОС distribution).
The goal is an authentic, buildable description of the real board: schematic,
netlist, microcode and the host protocol — see
[`mc1702-schematic.md`](mc1702-schematic.md), [`mc1702/netlist.csv`](mc1702/netlist.csv),
[`mc1702/d44-prom.txt`](mc1702/d44-prom.txt) and [`hw/mc1702/`](../../hw/mc1702/README.md).

## 1. What the board is

A single-board coprocessor (3.098.002) built around the **КМ1810ВМ86 (8086
clone) @ 5 MHz** plus a **КМ1810ВМ87 (8087 FPU)**. Made by the Voronezh
"Процессор" plant **for the МС 0585** («Электроника-85», a DEC Professional-350
clone) — the ПВК of its manuals. On board:

- 512 KB DRAM with Hamming SECDED (the "СОКОО" error-correction pair of BIS).
- 16 KB ROM at 8086 physical `FC000–FFFFF` (power-on monitor/BIOS).
- **16 KB static VIDEO RAM at `B8000–BBFFF`** — the PC CGA text-buffer address.
- 2 KB test ROM readable from the host (identification/self-test).
- One-connector interface to the host system bus (БКО.305.111 ТУ).

8086 memory map (ТО §5.1.1.6): `00000–7FFFF` DRAM, `B8000–BBFFF` video,
`FC000–FFFFF` ROM, rest reserved.

The board shipped with **ОС ЭЛДОС 2.0** (MS-DOS 3.30 compatible, Ш33.060.021
ТУ); **МОС-86** (CP/M-86 compatible) also existed. Host launch commands:
`DOS85` (ЭЛДОС; an MS-DOS diskette goes into DZ0:) and `INIMOC` (МОС-86).
DOS boots **from a floppy through the host**, not from the board ROM.

## 2. The model: a bus-servant, not shared memory

The board has no peripherals of its own. When the 8086 runs a bus cycle it
cannot satisfy locally (I/O, or memory outside DRAM/video/ROM), it stalls in
wait states and interrupts the host. The host program then **acts as the whole
PC**: reads the stalled cycle's address/data/status through a register file,
services it (disk, keyboard, printer, timer…), feeds the result back, releases
the CPU. The PC text screen is the board's video RAM, which the host redraws on
the machine's own display with an IBM font.

ТО Таблица 2 — the host command decoder outputs:

| Out | Function |
|-----|----------|
| Y0  | read the test ROM at the host-side counter address; auto-increment |
| Y1  | read the 8086 **status word** (register D36) |
| Y2  | read the stalled 8086 **address** (A0–A15 + BHE) |
| Y3  | read the stalled cycle **data** |
| Y4  | assert **NMI** |
| Y5  | reset the test-ROM address counter |
| Y6  | write the **interrupt vector** (for an INTR the host injects) |
| Y7  | write **data** back onto the 8086 bus |

ТО Таблица 3 — the status word (also raised to the host as interrupts 30А/30Б):

| Bit | Meaning |
|-----|---------|
| ADL00 | BHE line state |
| ADL01 | 0 = /RES asserted |
| ADL02 | 0 = a **video-RAM write** happened (host must redraw) |
| ADL03 | 0 = MP entered **WAIT** |
| ADL04 | INTR present |
| ADL05 | 0 = MP in **HALT** |
| ADL06 | 0 = MP writing **I/O or video** (IRQ 30Б) |
| ADL07 | 0 = MP **reading I/O** (IRQ 30А) |

How the drawing implements this — Y0–Y7 from the command register D8 and
decoder D15, the status register D36, the address read-back latches D22/D23,
the data path D6/D7 ↔ D12/D13, the vector register D14 — is in
[`mc1702-schematic.md`](mc1702-schematic.md).

## 3. The host-side register contract (from the MSDOS.EXE disassembly)

`MSDOS.EXE` (60 blocks, RT-11 SAV, start `002506`; a copy survives on the vvv
disk4 volume of our collection: `disk_recovery/work/corpus/export/vvv104/disk4/MSDOS.EXE`)
is the RT-11 host program of the board. It does file/terminal I/O through
standard RT-11 requests and touches the board only through a raw I/O window.
Masks below are octal `BIT #N` literals exactly as in the listing (`#001` =
bit 0, `#002` = bit 1, `#200` = bit 7).

| Addr | Use |
|------|-----|
| `0173000,004,010,014,016,020,022,024` | 8-word register file — the stalled cycle's address / data / byte-enable / cycle-type, both directions |
| `0173026` | control: **`#200` = update latch** (raise → write regs → drop = commit); `#002`, `#004` = handshake status |
| `0173030` | stall/interrupt cause — the vector-230 ISR reads it first |
| `0173202` | command strobes — byte pairs `071/072` (probe path) and `051/052` (exit path) |
| `0173206` | mode byte (`050`/`070`) |
| `0173212` | per-unit config byte |
| `0173500` | byte data channel |
| `0173502` | byte channel status — `#001` = TX ready (sender at `003212`), `#002` = RX ready |
| `0173024` | bit 7 = busy; wait until clear before a register-file read-back |
| vector `0230` | board interrupt; ISR at `001356` |

Verified sequences (re-disassembled from exact addresses, byte-checked):

- **Probe receive**: clear flag `002446`, poll `0173502 #002` with timeout,
  read `0173500`, expect **`0252` (0xAA)** → set flag.
- **Latched write** (`032564`): `BIS #200,@#173026` → `MOV …,@#173000/004/010`
  → `BIC #200,@#173026`.
- **Read-back** (`044200`): wait `TSTB @#173024 / BMI .` → read
  `173022/020/016/010/004/000` → check `#004` in `173026`.

*Gaps of the static analysis:* the read site of the `002446` flag was not
found (only CLR/INC); the «Нет платы адаптера МС 1702» string (`034300`) is
reached via a pointer table at `047426` whose selector was not traced; the
probe's *send* routine `003414` decodes to garbage in-file (likely filled at
run time) — the byte-channel sender proper is `003212`. These addresses are
host-side (the 0585's I/O page); their board-side counterparts are the XS1
lines МОБМ/МD/МАЦВ/МDЧТ/ВАД/ПМВ and the command decoder of §2.

What `MSDOS.EXE` is, per its own strings: the "**эмулятор IBM PC**" — a
virtual hard disk in the host file `DW0:IBMDSK.IBM` (1 cyl = 68 blocks, max
305 ≈ 10 MB), MS-DOS boots from a floppy in `DZ0:`, the PC screen is redrawn
from board video RAM with `SY:ALPIBM.FNT`, PLAS directives `.CRRG`/`.CRAW` map
the board memory, a video-controller memory extender is required, exit prints
«Конец работы эмулятора IBM PC».

FAT geometry on these RX50-class diskettes: **80 tracks × 9 sectors × 512, one
side** — DOS uses 9 of the 10 physical sectors (the "КНГМД limitations").

`EL85.rar` — a Windows build of an xhomer-based МС-0585 emulator
(`United.exe`, `boot_ROM_image = mc0585.rom` 16K): `pc.rom` **2048 bytes** —
exactly the МС1702 test-ROM size (2К×8), header format like the Pro-350 slot
ID ROMs (`mem.rom`, `decna.rom`) — *candidate for the board's test ROM, to be
verified*; `dw0/dw1.rd` = 20 MB ПРОС winchester images.

## 5. The MS-0585 floppy format — cracked

The ПРОС diskettes (`EMDOS*`, `FD20`, the `4.800.015-xx` sets) use **our own
osa-skew layout** — interleave `[0,2,4,6,8,1,3,5,7,9]`, +2 sectors skew per
track, cylinder 0 last — i.e. the "формат DZ" of the 0515, byte-identical
addressing (`lbnToByte(lbn, 0, false)` reads them as-is). What differs is the
**filesystem: Files-11 ODS-1** (ПРОС = P/OS clone), not RT-11:

- LBN 0 — boot block («ЭТОТ ТОМ НЕ СОДЕРЖИТ АППАРАТНО ЗАГРУЖАЕМОЙ СИСТЕМЫ…»).
- LBN 1 — ODS-1 home block: H.IBSZ=1, H.IBLB=2, H.FMAX=200, volume name
  (`MC1702`), owner `[128,128]`, format string `D?CFILE11A` (one bit off
  `DECFILE11A` in this dump).
- LBN 2 — index bitmap; LBN 3… — index file headers (file 1 = `INDEXF.SYS`,
  2 = `BITMAP.SYS`, 3 = `BADBLK.SYS`, 4 = `000000.DIR` MFD, 5 = `CORIMG.SYS`).
- Header layout (as found on these disks): byte 0 = ident-area word offset,
  byte 1 = map-area word offset; file number/sequence words at +2/+4; filename
  3×RAD50 + type at ident; map area: CTSZ,LBSZ at +6/+7, USE at +8, retrieval
  pointers from +10 in the (1,3) format **`[lbn-hi:1][count-1:1][lbn-lo:2]`**.
- Directories: 16-byte entries `(fnum, fseq, rvn, name 3×RAD50, ext)`.

An extractor (`ods1_extract.py`, kept next to the data) unpacked all three
ПРОС volumes into `ms0515_data\tis_kz\extracted\` (61 files). This also means
the `4.800.015-xx` ПРОС distribution sets are readable the same way, and an
ODS-1 reader is a candidate `disk`-library feature (same geometry, new
filesystem parser).

## 6. What the trove gives the MC1702 effort

Extracted highlights (`ms0515_data\tis_kz\extracted\`):

- **`EMUL.TSK` v1.0 (80 blk) and v1.3 (74 blk)** — the ПРОС-side host
  ("Эмулятор PC"), sibling of `MSDOS.EXE` (same «НЕТ СИСТЕМНОГО ДИСКА» /
  «ПРОДОЛЖ» prompts, Alfa/OldLex/NewLex keyboard indicator).
- **`D00049.TSK` + `D00049.MSG` — the factory board diagnostic v1.0**:
  «СОПРОЦЕССОР МС-1702… Ошибка видео ОЗУ / регистра состояния / обмена данных /
  выполнения команд ЦП / ПЗУ сопроцессора / ОЗУ», down to «неправильное
  содержимое регистра состояния ЦП после снятия сигнала RESET» — an
  independent, node-by-node protocol source.
- **`FONTXX.TSK`** (28 KB) — the font task, the ALPIBM.FNT analogue candidate.
- **`OPPRIM.TXT`** v1.0/v1.3 — «Эмулятор PC. Описание применения» (1990,
  10 листов); saved as UTF-8 `OPPRIM_v10.txt` / `OPPRIM_v13.txt`.
- `ATD0.C` (a C source on the v1.3 disk), `SHAG2/MODIF/PRINT.TSK`,
  install scripts (`*.INS`).

So the protocol can be cross-verified from **three independent sides**:
`MSDOS.EXE` (RT-11 host) ↔ `EMUL.TSK` (ПРОС host) ↔ `D00049.TSK` (factory
test). ЭЛДОС and MS-DOS 3.30 boot media exist. The only artifact still truly
missing is the **16 KB board ROM** (FC000–FFFFF) — its behaviour is
constrained by the diagnostic's error list and the hosts' expectations;
`pc.rom` from the EL85 kit may cover the 2 KB test ROM.

## 9. Why the board is not an MS-0515 device

The МС 1702 is a device of the МС 0585 bus, and nothing on the 0515 side can
host it:

- Its host register window `0173000–0173777` (§3) is **ROM** on the MS-0515 —
  the 0515's I/O page starts at `0177400`; the board's registers cannot even be
  decoded there without redesigning the 0515.
- The host program expects the 0585 environment (PLAS memory-mapping
  directives, a video-controller memory extender, `DW0:` winchester, the
  IBM font redraw on the 0585 display); the same program run on the 0515
  stops at its environment check and prints «Нет платы адаптера МС 1702»
  before touching any hardware.
- Any "MS-0515 variant" of the board would be an invention, not a
  reconstruction, and would still lack the 8086-side monitor ROM.

So the MC 1702 belongs to a future МС 0585 model; for this project it is a
hardware-archaeology result — the schematic, netlist and microcode above.
