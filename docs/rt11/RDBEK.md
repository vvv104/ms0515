## АННОТАЦИЯ

РЕЛЯЦИОННАЯ СИСТЕМА УПРАВЛЕНИЯ БАЗАМИ ДАННЫХ (СУБД) ПРЕДНАЗНАЧЕНА ДЛЯ СОЗДАНИЯ И УПРАВЛЕНИЯ БАЗАМИ ДАННЫХ НА МИКРО- И МИНИ-ЭВМ. СИСТЕМА ПРЕДЛАГАЕТ ДЛЯ ПОЛЬЗОВАТЕЛЯ-НЕПРОГРАММИСТА УДОБНЫЙ И НАГЛЯДНЫЙ ЭКРАННЫЙ ИТЕРФЕЙС ДОСТУПА К БАЗЕ ДАННЫХ, БЛАГОДАРЯ КОТОРОМУ СУБД С ПОДКЛЮЧЕННОЙ К НЕЙ БАЗОЙ ДАННЫХ СОСТАВЛЯЕТ ГОТОВУЮ ИНФОРМАЦИОННО-ПОИСКОВУЮ СИСТЕМУ. ПРЕДЛАГАЕМЫЙ СУБД ПРОГРАММНЫЙ  ИНТЕРФЕЙС  ПОЗВОЛЯЕТ СОЗДАВАТЬ НА ЕЕ ОСНОВЕ  СПЕЦИАЛИЗИРОВАННЫЕ СИСТЕМЫ ОБРАБОТКИ ИНФОРМАЦИИ. СУБД ПРЕДНАЗНАЧЕНА ДЛЯ МИКРО-ЭВМ  "ЭЛЕКТРОНИКА 60", ДВК-2, ДВК-3, А ТАКЖЕ ДЛЯ МИНИ-ЭВМ ТИПА СМ-4  С ОПЕРАЦИОННОЙ СИСТЕМОЙ РАФОС (ФОДОС, ОС ДВК, NTS).

# НАЗНАЧЕНИЕ И УСЛОВИЯ ПРИМЕНЕНИЯ

РЕЛЯЦИОННАЯ СУБД ПРЕДНАЗНАЧЕНА ДЛЯ СОЗДАНИЯ И УПРАВЛЕНИЯ РЕЛЯЦИОННЫМИ БАЗАМИ ДАННЫХ НА МИКРО-ЭВМ ТИПА "ЭЛЕКТРОНИКА-60", ДВК-2, ДВК-3, А ТАКЖЕ НА МИНИ-ЭВМ СМ-4 В ОПЕРАЦИОННОЙ СИСТЕМЕ РАФОС (ФОДОС, NTS, ОС ДВК). В КАЧЕСТВЕ ВНЕШНЕЙ ПАМЯТИ ДЛЯ ХРАНЕНИЯ ДАННЫХ ИСПОЛЬЗУЮТСЯ МАГНИТНЫЕ ДИСКИ (МД).

СУБД МОЖЕТ ИСПОЛЬЗОВАТЬСЯ ДЛЯ СОЗДАНИЯ РАЗЛИЧНЫХ ИНФОРМАЦИОННО-СПРАВОЧНЫХ СИСТЕМ, В СИСТЕМАХ АВТОМАТИЧЕСКОГО И АВТОМАТИЗИРОВАННОГО СБОРА, ХРАНЕНИЯ И ОБРАБОТКИ ДАННЫХ, В СИСТЕМАХ АВТОМАТИЗАЦИИ ПРОЕКТИРОВАНИЯ И Т.П. СУБД ПОЗВОЛЯЕТ ОБСЛУЖИВАТЬ ОДНУ ИЛИ НЕСКОЛЬКО БАЗ ДАННЫХ.

СУБД ИМЕЕТ ДВА УРОВНЯ ИНТЕРФЕЙСА - ДИАЛОГОВЫЙ ЭКРАННЫЙ ИНТЕРФЕЙС, РАСЧИТАННЫЙ НА ПОЛЬЗОВАТЕЛЯ-НЕПРОГРАММИСТА, И ПРОГРАММНЫЙ ИНТЕРФЕЙС.

ДИАЛОГОВЫЙ ЭКРАННЫЙ ИНТЕРФЕЙС ОБЕСПЕЧИВАЕТ НАГЛЯДНЫЙ И ОПЕРАТИВНЫЙ ДОСТУП К БАЗЕ ДАННЫХ, ВЫВОДЯ НА ЭКРАН ЕЕ СОДЕРЖИМОЕ В ВИДЕ ТАБЛИЦЫ. ЭКРАННЫЙ ИНТЕРФЕЙС ПОЗВОЛЯЕТ ИСПОЛЬЗОВАТЬ СУБД С ПОДКЛЮЧЕННОЙ К НЕЙ БАЗОЙ ДАННЫХ В КАЧЕСТВЕ ГОТОВОЙ ИНФОРМАЦИОННО-ПОИСКОВОЙ СИСТЕМЫ.

ПРОГРАММНЫЙ ИНТЕРФЕЙС ПОЗВОЛЯЕТ РАБОТАТЬ С БАЗОЙ ДАННЫХ (СОЗДАВАТЬ, ЗАПОЛНЯТЬ, МОДИФИЦИРОВАТЬ БАЗУ ДАННЫХ, ИЗВЛЕКАТЬ ИНФОРМАЦИЮ ИЗ БАЗЫ ДАННЫХ) ИЗ ПРОГРАММ, НАПИСАННЫХ НА ЯЗЫКАХ ПАСКАЛЬ И ГРАФИЧЕСКИЙ ПАСКАЛЬ (ОДИН ИЗ ВХОДНЫХ ЯЗЫКОВ КОМПЛЕКСА РТК МИКРО). ПРОГРАММНЫЙ ИНТЕРФЕЙС ИСПОЛЬЗУЕТСЯ ПРИ СОЗДАНИИ СПЕЦИАЛИЗИРОВАННЫХ СИСТЕМ ОБРАБОТКИ ДАННЫХ. В НАСТОЯЩЕМ ДОКУМЕНТЕ ПРОГРАММНЫЙ ИНТЕРФЕЙС НЕ РАССМАТРИВАЕТСЯ.

РЕЛЯЦИОННАЯ СУБД ЯВЛЯЕТСЯ СОСТАВНОЙ ЧАСТЬЮ ТЕХНОЛОГИЧЕСКОГО КОМПЛЕКСА РТК МИКРО. ОНА РАЗРАБОТАНА ПО Р-ТЕХНОЛОГИИ ПРОГРАММИРОВАНИЯ НА ЯЗЫКЕ ГРАФИЧЕСКИЙ ПАСКАЛЬ.

# ХАРАКТЕРИСТИКИ ПРОГРАММЫ

## СТРУКТУРА БАЗЫ ДАННЫХ

ПОДДЕРЖИВАЕМЫЕ СУБД БАЗЫ ДАННЫХ ПРЕДСТАВЛЯЮТСЯ В ВИДЕ ДВУМЕРНОЙ ТАБЛИЦЫ. ТАБЛИЦА СОСТОИТ ИЗ ЗАПИСЕЙ С ФИКСИРОВАННЫМ НАБОРОМ СТОЛБЦОВ. КАЖДЫЙ СТОЛБЕЦ ИМЕЕТ ИМЯ И ОПРЕДЕЛЕННЫЙ ТИП, ЕДИНЫЕ ДЛЯ ВСЕХ ЗАПИСЕЙ БАЗЫ ДАННЫХ. ДОПУСТИМЫ СЛЕДУЮЩИЕ ТИПЫ СТОЛБЦОВ:

1 - ЦЕЛОЕ ЧИСЛО В ДИАПАЗОНЕ -32768..32767;

2 - ВЕЩЕСТВЕННОЕ ЧИСЛО;

3 - ТЕКСТ ПРОИЗВОЛЬНОЙ ДЛИНЫ;

4 - СИМВОЛЬНАЯ СТРОКА ФИКСИРОВАННОЙ ДЛИНЫ,

```

```

МАКСИМАЛЬНОЕ ЧИСЛО СТОЛБЦОВ В БАЗЕ ДАННЫХ - 48.

ОБРАЩЕНИЕ К БАЗЕ ДАННЫХ В СУБД ПРОИСХОДИТ ПО ИМЕНИ - ИДЕНТИФИКАТОРУ ДЛИНОЙ НЕ БОЛЕЕ 6 СИМВОЛОВ (ДОПУСТИМЫ ТОЛЬКО ЛАТИНСКИЕ БУКВЫ).

### СИМВОЛЬНЫЕ ТИПЫ ДАННЫХ

ЗНАЧЕНИЕМ СТОЛБЦА ТИПА 3 МОЖЕТ БЫТЬ ТЕКСТ ПРОИЗВОЛЬНОЙ ДЛИНЫ (ОРИЕНТИРОВОЧНО ДО 2000 СИМВОЛОВ), СОСТОЯЩИЙ ИЗ НЕСКОЛЬКИХ СТРОК. ДЛИНА ОДНОЙ ТЕКСТОВОЙ СТРОКИ НЕ МОЖЕТ ПРЕВЫШАТЬ 79 СИМВоЛОВ.

ЗНАЧЕНИЕМ СТОЛБЦА ТИПА 4 ЯВЛЯЕТСЯ СТРОКИ ФИКСИРОВАННОЙ ДЛИНЫ. ЕСЛИ ПРИ ЗАДАНИИ ЗНАЧЕНИЯ СТОЛБЦА ВВОДИТСЯ СТРОКА МЕНЬШЕЙ ДЛИНЫ, ОСТАВШИЕСЯ ПОЗИЦИИ АВТОМАТИЧЕСКИ ЗАПОЛНЯЮТСЯ ПРОБЕЛАМИ.

ДЛЯ ПРЕДСТАВЛЕНИЯ ТЕКСТОВЫХ ДАННЫХ НЕБОЛЬШОГО ОБ'ЕМА СЛЕДУЕТ ОТДАВАТЬ ПРЕДПОЧТЕНИЕ ТИПУ 4, ТАК КАК ЭТО В ДАЛЬНЕЙШЕМ МОЖЕТ СУЩЕСТВЕННО УСКОРИТЬ ПОИСК ИНФОРМАЦИИ В БАЗЕ ДАННЫХ, А ТАКЖЕ ПРОЦЕДУРУ СОРТИРОВКИ БАЗЫ ДАННЫХ.

## ОРГАНИЗАЦИЯ ДИАЛОГА В СУБД

ДИАЛОГ В СУБД СТРОИТСЯ ТАКИМ ОБРАЗОМ, ЧТОБЫ МИНИМИЗИРОВАТЬ И ОБЛЕГЧИТЬ ВВОД, ИСКЛЮЧИВ ПРИ ЭТОМ БОЛЬШИНСТВО ВОЗМОЖНЫХ ОШИБОК. СИСТЕМА САМА ЗАПРАШИВАЕТ В КАЖДОМ КОНКРЕТНОМ СЛУЧАЕ ВСЮ НЕОБХОДИМУЮ ДЛЯ РАБОТЫ ИНФОРМАЦИЮ, ВЫДАВАЯ ПОДСКАЗКИ, КОТОРЫЕ ЧАСТО СОДЕРЖАТ И НАБОР ДОПУСТИМЫХ ОТВЕТОВ. ЭТО ПОЗВОЛЯЕТ ИСПОЛЬЗОВАТЬ СИСТЕМУ ПОЛЬЗОВАТЕЛЯМ С МИНИМАЛЬНОЙ ПОДГОТОВКОЙ.

### ФУНКЦИОНАЛЬНЫЕ КЛАВИШИ

ДЛЯ РАБОТЫ С СУБД ИСПОЛЬЗУЮТСЯ ФУНКЦИОНАЛЬНЫЕ КЛАВИШИ, КОТОРЫЕ В ТЕКСТЕ ДАННОГО ДОКУМЕНТА ПРЕДСТАВЛЕНЫ ВЗЯТЫМИ В КАВЫЧКИ ИМЕНАМИ, НАПРИМЕР "СТРЕЛКА ВВЕРХ". СООТВЕТСВУЮЩИЕ ИМ КОНКРЕТНЫЕ КЛАВИШИ ДИСПЛЕЯ ПРИВЕДЕНЫ В ПРИЛОЖЕНИИ, ПРИ ЭТОМ РЯД ДЕЙСТВИЙ ЗАДАЕТСЯ ПОСЛЕДОВАТЕЛЬНЫМ НАЖАТИЕМ ДВУХ КЛАВИШ.

КРОМЕ ТОГО ФУНКЦИОНАЛЬНЫЕ КЛАВИШИ ПРОДУБЛИРОВАНЫ АЛФАВИТНЫМИ КЛАВИШАМИ, НАЖИМАЕМЫМИ СОВМЕСТНО СО СЛУЖЕБНОЙ КЛАВИШЕЙ "CTRL" (НА НЕКОТОРЫХ ТИПАХ ДИСПЛЕЕВ ЭТА КЛАВИША ОБОЗНАЧАЕТСЯ КАК "цУ", "Уц", "СЛУЖ.КОД"). ЭТО ПОЗВОЛЯЕТ ИСПОЛЬЗОВАТЬ СУБД БЕЗ ПЕРЕНАСТРОЙКИ ПОД КОНКРЕТНЫЕ КОДЫ КЛАВИАТУРЫ НА БОЛЬШИНСТВЕ ТИПОВ ДИСПЛЕЕВ.

### ВВОД СТРОК

ЛЮБОЙ ЭЛЕМЕНТАРНЫЙ ВВОД (СТРОК, ЧИСЕЛ, КОМАНД) ЗАКАНЧИВАЕТСЯ НАЖАТИЕМ КЛАВИШИ "ВК". ДЛЯ СТИРАНИЯ ПОСЛЕДНЕГО ВЫВЕДЕННОГО СИМВОЛА ИСПОЛЬЗУЕТСЯ КЛАВИША "ЗАБОЙ". С ПОМОЩЬЮ КЛАВИШ "ВСТАВИТЬ СИМВОЛ" И "УДАЛИТЬ СИМВОЛ" МОЖНО СДВИНУТЬ СТРОКУ ВПРАВО ИЛИ ВЛЕВО ОТ ПОЗИЦИИ МАРКЕРА.

ДЛЯ ПЕРЕМЕЩЕНИЯ МАРКЕРА ВВЕРХ И ВНИЗ ПО СТРОКАМ ИСПОЛЬЗУЮТСЯ КЛАВИШИ "СТРЕЛКА ВВЕРХ", "СТРЕЛКА ВНИЗ". ДЛЯ ВСТАВКИ МЕЖДУ СТРОК ПУСТОЙ СТРОКИ И УДАЛЕНИЯ СТРОКИ - КЛАВИШИ "ВСТАВИТЬ СТРОКУ" И "УДАЛИТЬ СТРОКУ".

## ЗАЩИТА БАЗЫ ДАННЫХ ПАРОЛЕМ

БАЗА ДАННЫХ МОЖЕТ БЫТЬ ЗАЩИЩЕНА ПАРОЛЕМ. ПАРОЛЬ СОДЕРЖИТ ОТ 1 ДО 4 СИМВОЛОВ. ПАРОЛЬ, СОСТОЯЩИЙ ИЗ ОДНИХ ПРОБЕЛОВ, РАССМАТРИВАЕТСЯ КАК ОТСУТСТВИЕ ПАРОЛЯ. ПАРОЛЬ ВВОДИТСЯ ПРИ СОЗДАНИИ БАЗЫ ДАННЫХ ИЛИ ПРИ ЕЕ РЕДАКТИРОВАНИИ И МОЖЕТ БЫТЬ ИЗМЕНЕН ПРИ РЕДАКТИРОВАНИИ БАЗЫ ДАННЫХ.

### КЛАВИШИ И КОМАНДЫ УПРАВЛЕНИЯ

УПРАВЛЕНИЕ РЕДАКТОРОМ ОСУЩЕСТВЛЯЕТСЯ С ПОМОЩЬЮ НАЖАТИЯ ФУНКЦИОНАЛЬНЫХ КЛАВИШ ИЛИ ВВОДА КОМАНД В ПОЛЕ КОМАНДНОЙ СТРОКИ ЭКРАННОЙ ТАБЛИЦЫ.

ФУНКЦИОНАЛЬНЫЕ КЛАВИШИ:

**"СТРЕЛКА ВНИЗ"**

СДВИГ МАРКЕРА НА СЛЕДУЮЩУЮ ЗАПИСЬ. ЕСЛИ МАРКЕР НАХОДИТСЯ В ПоСЛЕДНЕЙ СТРОКЕ, ТО НА ЭКРАН ВЫВОДИТСЯ СЛЕДУЮЩАЯ СТРАНИЦА (15 ЗАПИСЕЙ) И МАРКЕР УСТАНАВЛИВАЕТСЯ НА ЕЕ ПЕРВУЮ ЗАПИСЬ

**"СТРЕЛКА ВВЕРХ"**

СДВИГ МАРКЕРА ВВЕРХ НА ПРЕДЫДУЩУЮ ЗАПИСЬ. ЕСЛИ МАРКЕР НАХОДИТСЯ В ПЕРВОЙ СТРОКЕ, ТО НА ЭКРАН    ВЫВОДИТСЯ ПРЕДЫДУЩАЯ СТРАНИЦА И МАРКЕР УСТАНАВЛИВАЕТСЯ НА ЕЕ ПОСЛЕДНЮЮ ЗАПИСЬ

**"СЛЕДУЮЩАЯ СТРАНИЦА"**

ВЫВОД НА ЗКРАН СЛЕДУЮЩЕЙ СТРАНИЦЫ, МАРКЕР УСТАНАВЛИВАЕТСЯ НА ПЕРВУЮ ЗАПИСЬ

**"В НАЧАЛО БД"**

ПЕРЕХОД В НАЧАЛО БАЗЫ ДАННЫХ. ИНФОРМАЦИОННАЯ ЧАСТЬ ТАБЛИЦЫ ГАСНЕТ.

**"В КОНЕЦ БД"**

ПЕРЕХОД В КОНЕЦ БАЗЫ ДАННЫХ. НА ЭКРАН ВЫВОДИТСЯ ПОСЛЕДНЯЯ ЗАПИСЬ И МАРКЕР УСТАНАВЛИВАЕТСЯ ЗА ПОСЛЕДНЕЙ ЗАПИСЬЮ, Т.Е. ПРИГОТОВЛЕН ДЛЯ ВВОДА В "ХВОСТ" БАЗЫ ДАННЫХ НОВОЙ ЗАПИСИ

**"ВЫХОД"**

ВЫХОД ИЗ РЕДАКТОРА БЕЗ СОХРАНЕНИЯ ТЕКУЩЕГО СОСТОЯНИЯ БАЗЫ ДАННЫХ

КОМАНДЫ:

**В**

ВВЕСТИ ЗАПИСЬ В СТРОКУ, УКАЗЫВАЕМУЮ МАРКЕРОМ. ЕСЛИ МАРКЕР НАХОДИТСЯ ЗА ПОСЛЕДНЕЙ ЗАПИСЬЮ, ТО НОВАЯ ЗАПИСЬ ДОПИСЫВАЕТСЯ В "ХВОСТ"  БАЗЫ ДАННЫХ.
