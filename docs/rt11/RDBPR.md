## АННОТАЦИЯ

РЕЛЯЦИОННАЯ СУБД РБД-МИКРО ПРЕДНАЗНАЧЕНА ДЛЯ СОЗДАНИЯ И УПРАВЛЕНИЯ БАЗАМИ ДАННЫХ НА МИКРО-ЭВМ ТИПА "ЭЛЕКТРОНИКА 60" И "ЭЛЕКТРОНИКА НЦ 80-20". В ДАННОМ ДОКУМЕНТЕ ПРИВЕДЕНО ОПИСАНИЕ ПРОГРАММНОГО ИНТЕРФЕЙСА СУБД, ПОЗВОЛЯЮЩЕГО РАБОТАТЬ С БАЗАМИ ДАННЫХ ИЗ ПРОГРАММ, НАПИСАННЫХ НА ЯЗЫКАХ ПАСКАЛЬ И ГРАФИЧЕСКИЙ ПАСКАЛЬ. ПРОГРАММНЫЙ ИНТЕРФЕЙС ПОЗВОЛЯЕТ СОЗДАВАТЬ НА ОСНОВЕ СУБД СПЕЦИАЛИЗИРОВАННЫЕ СИСТЕМЫ ОБРАБОТКИ ИНФОРМАЦИИ.

# ОБЩИЕ СВЕДЕНИЯ

СУБД РБД-МИКРО ПРЕДНАЗНАЧЕНА ДЛЯ СОЗДАНИЯ И УПРАВЛЕНИЯ РЕЛЯЦИОННЫМИ БАЗАМИ ДАННЫХ НА МИКРО-ЭВМ ТИПА "ЭЛЕКТРОНИКА 60". "ЭЛЕКТРОНИКА НЦ 80-20" В ОПЕРАЦИОННОЙ СИСТЕМЕ РАФОС (ФОДОС, ОС ДВК). В КАЧЕСТВЕ ВНЕШНЕЙ ПАМЯТИ ДЛЯ ХРАНЕНИЯ ДАННЫХ ИСПОЛЬЗУЮТСЯ ГИБКИЕ МАГНИТНЫЕ ДИСКИ (ГМД).

СУБД МОЖЕТ ИСПОЛЬЗОВАТЬСЯ ДЛЯ СОЗДАНИЯ РАЗЛИЧНЫХ ИНФОРМАЦИОННО-СПРАВОЧНЫХ СИСТЕМ, В СИСТЕМАХ АВТОМАТИЧЕСКОГО И АВТОМАТИЗИРОВАННОГО СБОРА, ХРАНЕНИЯ И ОБРАБОТКИ ДАННЫХ, В СИСТЕМАХ АВТОМАТИЗАЦИИ ПРОЕКТИРОВАНИЯ, В СИСТЕМАХ АВТОМАТИЗИРОВАННОЙ ОБРАБОТКИ РЕЗУЛЬТАТОВ ЭКСПЕРЕМЕНТОВ И Т.П. СУБД ПОЗВОЛЯЕТ ОБСЛУЖИВАТЬ ОДНУ ИЛИ НЕСКОЛЬКО БАЗ ДАННЫХ.

СУБД ИМЕЕТ ДВА УРОВНЯ ИНТЕРФЕЙСА - ДИАЛОГОВЫЙ ЭКРАННЫЙ ИНТЕРФЕЙС, РАСЧИТАННЫЙ НА ПОЛЬЗОВАТЕЛЯ-НЕПРОГРАММИСТА, И ПРОГРАММНЫЙ ИНТЕРФЕЙС.

ДИАЛОГОВЫЙ ЭКРАННЫЙ ИНТЕРФЕЙС ОБЕСПЕЧИВАЕТ НАГЛЯДНЫЙ И ОПЕРАТИВНЫЙ ДОСТУП К БАЗЕ ДАННЫХ, ПОЗВОЛЯЮЩИЙ ИСПОЛЬЗОВАТЬ СУБД В КАЧЕСТВЕ ГОТОВОЙ ИНФОРМАЦИОННО-СПРАВОЧНОЙ СИСТЕМЫ. В НАСТОЯЩЕМ ДОКУМЕНТЕ ДИАЛОГОВЫЙ НЕ РАССМАТРИВАЕТСЯ.

ПРОГРАММНЫЙ ИНТЕРФЕЙС ПОЗВОЛЯЕТ РАБОТАТЬ С БАЗОЙ ДАННЫХ (СОЗДАВАТЬ, ЗАПОЛНЯТЬ, МОДИФИЦИРОВАТЬ БАЗУ ДАННЫХ, ИЗВЛЕКАТЬ ИЗ НЕЕ ИНФОРМАЦИЮ) ИЗ ПРОГРАММ, НАПИСАННЫХ НА ЯЗЫКАХ ПАСКАЛЬ И ГРАФИЧЕСКИЙ ПАСКАЛЬ. ПРОГРАММНЫЙ ИНТЕРФЕЙС ИСПОЛЬЗУЕТСЯ ПРИ СОЗДАНИИ СПЕЦИАЛИЗИРОВАННЫХ СИСТЕМ ОБРАБОТКИ ДАННЫХ.

СУБД РБД-МИКРО ЯВЛЯЕТСЯ СОСТАВНОЙ ЧАСТЬЮ ТЕХНОЛОГИЧЕСКОГО КОМПЛЕКСА РТК МИКРО. ОНА РАЗРАБОТАНА ПО Р-ТЕХНОЛОГИИ ПРОГРАММИРОВАНИЯ НА ЯЗЫКЕ ГРАФИЧЕСКИЙ ПАСКАЛЬ.

# ПРЕДСТАВЛЕНИЕ БАЗЫ ДАННЫХ НА ФИЗИЧЕСКОМ УРОВНЕ

БАЗА ДАННЫХ ВО ВНЕШНЕЙ ПАМЯТИ НА ГМД ПРЕДСТАВЛЯЕТСЯ ТРЕМЯ ФАЙЛАМИ С РАСШИРЕНИЯМИ DEF, TBF, ADF. ИМЕНА ЭТИХ ТРЕХ ФАЙЛОВ СОВПАДАЮТ С ИМЕНАМИ БАЗЫ ДАННЫХ.

НАПРИМЕР:

## KADRY.DEF

## KADRY.TBF

## KADRY.ADF

ФАЙЛ С РАСШИРЕНИЕМ DEF, ОБ'ЕМОМ 1-2 БЛОКА, СОДЕРЖИТ ОПИСАНИЕ БАЗЫ ДАННЫХ (СМ.П.5).

ФАЙЛ С РАСШИРЕНИЕМ TBF СОДЕРЖИТ ВЫРАВНЕННЫЕ ПО ДЛИНЕ ЗАПИСИ. В ЗАПИСИ КАЖДОМУ ТИПУ СТОЛБЦА СООТВЕТСТВУЕТ ФИКСИРОВАННОЕ ЧИСЛО БАЙТОВ.

```
ТИП 1 - 2 БАЙТА
ТИП 2 - 4 БАЙТА
ТИП 3 - 6 БАЙТОВ
ТИП 4 - ЧИСЛО БАЙТОВ, СОВПАДАЮЩЕЕ С ЧИСЛОМ СИМВОЛОВ
        В СТРОКЕ ФИКСИРОВАННОЙ ДЛИНЫ
```

ДЛЯ СТОЛБЦОВ ТИПА 1, 2, 4 В ЗАПИСИ СОДЕРЖИТСЯ НЕПОСРЕДСТВЕННО САМО ЗНАЧЕНИЕ СТОЛБЦА - ЦЕЛОЕ ИЛИ ВЕЩЕСТВЕННОЕ ЧИСЛО, СТРОКА СИМВОЛОВ ФИКСИРОВАННОЙ ДЛИНЫ. ДЛЯ СТОЛБЦА ТИПА 3 В ЗАПИСИ СОДЕРЖИТСЯ ССЫЛКА НА СТРОКУ ПРОИЗВОЛЬНОЙ ДЛИНЫ. САМА СТРОКА НАХОДИТСЯ В ФАЙЛЕ АЛФАВИТНЫХ ДАННЫХ С РАСШИРЕНИЕМ ADF. ССЫЛКА ПРЕДСТАВЛЯЕТ СОБОЙ ТРИ ЦЕЛЫХ ЧИСЛА (6 БАЙТОВ), СОДЕРЖАЩИЕ НОМЕР БЛОКА ФАЙЛА ADF, В КОТОРОМ РАСПОЛОЖЕНО НАЧАЛО СТРОКИ, СМЕЩЕНИЕ НАЧАЛА СТРОКИ В БЛОКЕ И ДЛИНУ СТРОКИ.

ФАЙЛ АЛФАВИТНЫХ ДАННЫХ С РАСШИРЕНИЕМ ADF СОДЕРЖИТ ИМЕНА СТОЛБЦОВ И СТРОКИ ПРОИЗВОЛЬНОЙ ДЛИНЫ.

# СТРУКТУРА ПРОГРАММНОГО ИНТЕРФЕЙСА СУБД

РАБОТА С БАЗОЙ ДАННЫХ ИЗ ПРОГРАММ, НАПИСАННЫХ НА ЯЗЫКАХ ПАСКАЛЬ И ГРАФИЧЕСКИЙ ПАСКАЛЬ, ОРГАНИЗУЕТСЯ КАК РАБОТА С ПЕРЕМЕННОЙ СПЕЦИАЛЬНОГО ТИПА, ЗАДАВАЕМОГО ИДЕНТИФИКАТОРОМ ТИПА DEFREL.

ПРОГРАММНЫЙ ИНТЕРФЕЙС СУБД СОДЕРЖИТ ОПИСАНИЕ ТИПА DEFREL И НАБОР ПРОЦЕДУР И ФУНКЦИЙ, РЕАЛИЗУЮЩИХ ОПЕРАЦИИ НАД БАЗОЙ ДАННЫХ.

ОПИСАНИЕ ТИПА DEFREL НАХОДИТСЯ В ФАЙЛЕ DEFRDB.RAS, КОТОРЫЙ ПРИСОЕДИНЯЕТСЯ К ПРОГРАММЕ ПОЛЬЗОВАТЕЛЯ НА ЭТАПЕ ТРАНСЛЯЦИИ С ЯЗЫКА ПАСКАЛЬ. ПЕРЕМЕННАЯ ТИПА DEFREL ЯВЛЯЕТСЯ СТРУКТУРНОЙ ПЕРЕМЕННОЙ, СОДЕРЖАЩЕЙ ССЫЛКИ НА ВНЕШНИЕ ФАЙЛЫ БАЗЫ ДАННЫХ, ИНФОРМАЦИЮ О ЕЕ ВНУТРННЕЙ СТРУКТУРЕ И ТЕКУЩЕМ СОСТОЯНИИ.

ИСПОЛЬЗУЕМЫЕ ДЛЯ ДОСТУПА К БАЗЕ ДАННЫХ ПРОЦЕДУРЫ И ФУНКЦИИ В ПРОГРАММЕ ПОЛЬЗОВАТЕЛЯ ОПИСЫВАЮТСЯ КАК ВНЕШНИЕ И ПРИСОЕДИНЯЮТСЯ НА ЭТАПЕ РЕДАКТИРОВНИЯ СВЯЗЕЙ ИЗ БИБЛИОТЕКИ СУБД С ИМЕНЕМ LIBRDB.OBJ.

НИЖЕ ПРЕДСТАВЛЕН ПРИМЕР ПРОТОКОЛА ТРАНСЛЯЦИИ ПРОГРАММЫ НА ГРАФИЧЕСКОМ ПАСКАЛЕ, СОДЕРЖАЩЕЙ ОБРАЩЕНИЕ К БАЗЕ ДАННЫХ.

```
R GPA
ВХОДНОЙ ФАЙЛ? NAME
ВЫХОДНОЙ ФАЙЛ? NAME
R PASCAL
NAME=DEFRDB,NAME
MAC NAME
LINK NAME,LIBRDB
RU NAME
```

ПОМИМО СРЕДСТВ ОБРАЩЕНИЯ К БАЗЕ ДАННЫХ ПРОГРАММНЫЙ ИНТЕРФЕЙС СОДЕРЖИТ РЯД ДОПОЛНИТЕЛЬНЫХ ВОЗМОЖНОСТЕЙ.

ДЛЯ ОБМЕНА ДАННЫМИ С БАЗОЙ ДАННЫХ ИСПОЛЬЗУЕТСЯ СПЕЦИАЛЬНЫЙ ТИП ДАННЫХ, НАЗЫВАЕМЫЙ ВИРТУАЛЬНЫМ МАССИВОМ (ИДЕНТИФИКАТОР ТИПА VSTR), ЗНАЧЕНИЕМ КОТОРОГО ЯВЛЯЕТСЯ ПОСЛЕДОВАТЕЛЬНОСТЬ БАЙТОВ ПРОИЗВОЛЬНОЙ ДЛИНЫ. ОПИСАНИЕ ТИПА VSTR СОДЕРЖИТСЯ В ФАЙЛЕ ОПИСАНИЙ DEFRDB.PAS, А ПРОЦЕДУРЫ ДЛЯ РАБОТЫ С ВИРТУАЛЬНЫМ МАССИВОМ - В БИБЛИОТЕКЕ LIBRDB.

БИБЛИОТЕКА LIBRDB ДОПОЛНИТЕЛЬНО СОДЕРЖИТ ПРОЦЕДУРЫ, ОБЛЕГЧАЮЩИЕ ВВОД С КЛАВИАТУРЫ ДИСПЛЕЯ.

# ВИРТУАЛЬНЫЙ МАССИВ

РАБОТА С ДАННЫМИ ВСЕХ 4-Х ТИПОВ СУБД (ЗАПИСЬ, ВЫБОРКА ДАННЫХ) ОСУЩЕСТВЛЯЕТСЯ С ПОСЛЕДОВАТЕЛЬНОСТЬЮ БАЙТОВ СООТВЕТСТВУЮЩЕЙ ДЛИНЫ. ДЛЯ ЭТОГО ВВЕДЕН СПЕЦИАЛЬНЫЙ ТИП ДАННЫХ VSTR (ВИРТУАЛЬНЫЙ МАССИВ). В ОТЛИЧИИ ОТ ОБЫЧНОГО ОДНОМЕРНОГО СИМВОЛЬНОГО МАССИВА ДЛИНА ВИРТУАЛЬНОГО МАССИВА МОЖЕТ ИЗМЕНЯТЬСЯ ДИНАМИЧЕСКИ В ПРОЦЕССЕ ЗАПИСИ В НЕГО ПОСЛЕДОВАТЕЛЬНОСТЕЙ БАЙТОВ. ВИРТУАЛЬНЫЙ МАССИВ МОЖЕТ ХРАНИТЬ ЦЕПОЧКУ БАЙТОВ ДЛИНОЙ ОТ 0 ДО 32767. ВНУТРЕННЕЕ ПРЕДСТАВЛЕНИЕ ВИРТУАЛЬНОГО МАССИВА ЗАДАЕТСЯ ОПРЕДЕЛЕНИЕМ ТИПА VSTR, НАХОДЯЩИМСЯ В ФАЙЛЕ DEFRDB.PAS. ДОСТУП К ВИРТУАЛЬНОМУ МАССИВУ ОСУЩЕСТВЛЯЕТСЯ С ПОМОЩЬЮ ПРОЦЕДУР И ФУНКЦИЙ, НАХОДЯЩИХСЯ В БИБЛИОТЕКЕ LIBRDB.

## ПРЕДСТАВЛЕНИЕ ВИРТУАЛЬНОГО МАССИВА

ПРЕДСТАВЛЕНИЕ ВИРТУАЛЬНОГО МАССИВА ЗАДАЕТСЯ ОПРЕДЕЛЕНИЕМ ТИПА VSTR, ПРИВЕДЕННЫМ НИЖЕ

```
CONST
  MAXBF=80; /* РАЗМЕР БУФЕРА ВИРТУАЛЬНОГО МАССИВА */
TYPE
  ITEMVS=RECORD /* ОПИСАНИЕ ЭЛЕМЕНТА МАССИВА */
           AD:^ITEMVS; /* ССЫЛКА НА СЛЕДУЮЩИЙ ЭЛЕМЕНТ */
           BF:ARRAY[1..MAXBF] OF CHAR /* БУФЕР СИМВОЛОВ */
         END;
  VSTR=RECORD
         LV:INTEGER; /* ЧИСЛО СИМВОЛОВ В МАССИВЕ */
         FV:ITEMVS   /* ПЕРВЫЙ ЭЛЕМЕНТ МАССИВА */
       END;
```

ПРИМЕР ОПИСАНИЯ ПЕРЕМЕННОЙ ТИПА ВИРТУАЛЬНЫЙ МАССИВ:

```
VAR  V:VSTR;  /* V - ВИРТУАЛЬНЫЙ МАССИВ */
```

ВИРТУАЛЬНЫЙ МАССИВ СОСТОИТ ИЗ ПОЛЯ LV, ОПРЕДЕЛЯЮЩЕГО ДЛИНУ ВИРТУАЛЬНОГО МАССИВА И СПИСКА ЭЛЕМЕНТОВ. КАЖДЫЙ ЭЛЕМЕНТ СОСТОИТ ИЗ БУФЕРА И ССЫЛКИ НА СЛЕДУЮЩИЙ ЭЛЕМЕНТ (СМ. РИС.). ВСЕ ЭЛЕМЕНТЫ МАССИВА, КРОМЕ ПЕРВОГО, ЗАПРАШИВАЮТСЯ ДИНАМИЧЕСКИ ПРИ ЗАПОЛНЕНИИ ОЧЕРЕДНОГО БУФЕРА. ПРИ ОБНУЛЕНИИ ВИРТУАЛЬНОГО МАССИВА ВСЕ ЭЛЕМЕНТЫ, КРОМЕ ПЕРВОГО, ВОЗВРАЩАЮТСЯ НАЗАД ОПЕРАЦИОННОЙ СИСТЕМЕ.

```

!LV         !
!___________!

 ___________         ___________                   ___________
!AD         !------>!           !----- - - - ---->!        NIL!
!___________!       !___________!                 !___________!
!BF         !       !           !                 !           !
!           !       !           !                 !           !
!           !       !           !                 !           !
!___________!       !___________!                 !___________!
```

## ДОСТУП К ВИРТУАЛЬНОМУ МАССИВУ

РАБОТА С ВИРТУАЛЬНЫМ МАССИВОМ ОСУЩЕСТВЛЯЕТСЯ С ПОМОЩЬЮ НАБОРА ВНЕШНИХ ПРОЦЕДУР И ФУНКЦИЙ.

КАЖДЫЙ ВИРТУАЛЬНЫЙ МАССИВ ДОЛЖЕН БЫТЬ В НАЧАЛЕ РАБОТЫ ИНИЦИАЛИЗИРОВАН ПРОЦЕДУРОЙ INITVS

```
PROCEDURE  INITVS(VAR V:VSTR)
```

ПРОЦЕДУРА INITVS ОБНУЛЯЕТ ДЛИНУ ВИРТУАЛЬНОГО МАССИВА И ПРИСВАИВАЕТ ЗНАЧЕНИЕ NIL ПОЛЮ ССЫЛКИ ПЕРВОГО ЭЛЕМЕНТА ВИРТУАЛЬНОГО МАССИВА.

ПРИМЕР:

## INITVS(V)

ПРОЦЕДУРА NULVS СЛУЖИТ ДЛЯ ОБНУЛЕНИЯ ВИРТУАЛЬНОГО МАССИВА.

```
PROCEDURE  NULVS(VAR V:VSTR)
```

ПРОЦЕДУРА ОБНУЛЯЕТ ДЛИНУ ВИРТУАЛЬНОГО МАССИВА И ВОЗВРАЩАЕТ ВСЕ ЭЛЕМЕНТЫ МАССИВА, КРОМЕ ПЕРВОГО, ОПЕРАЦИОННОЙ СИСТЕМЕ.

ФУНКЦИЯ LVS ИМЕЕТ ЗНАЧЕНИЕ, РАВНОЕ ТЕКУЩЕЙ ДЛИНЕ ВИРТУАЛЬНОГО МАССИВА.

```
FUNCTION  LVS(VAR V:VSTR):INTEGER
```

ПРОЦЕДУРА CHRVS СЛУЖИТ ДЛЯ ЗАПИСИ СИМВОЛА В ВИРТУАЛЬНЫЙ МАССИВ.

```
PROCEDURE  CHRVS(C:CHAR;VAR V:VSTR)
```

ЗАДАННЫЙ ПЕРВЫМ ПАРАМЕТРОМ СИМВОЛ ДОПИСЫВАЕТСЯ К УЖЕ ЗАПИСАННОЙ В МАССИВ ПОСЛЕДОВАТЕЛЬНОСТИ СИМВОЛОВ.

ПРИМЕР:

```
CONST
  ZERO='0';
VAR
  I:INTEGER;
  C:CHAR; 
  M:ARRAY[1..10] OF CHAR;
  V:VSTR;

BEGIN
  INITVS(V);
  CHRVS('A',V);
  CHRVS(ZERO,V);
  CHRVS(C,V);
  CHRVS(M[I+1],V)
END.
```

ФУНКЦИЯ ВЫБОРКИ СИМВОЛА ИЗ ВИРТУАЛЬНОГО МАССИВА.

```
FUNCTION  VSCHR(VAR V:VSTR; N:INTEGER):CHAR
```

ЗНАЧЕНИЕ ФУНКЦИИ РАВНО СИМВОЛУ, НОМЕР КОТОРОГО ЗАДАЕТСЯ ПАРАМЕТРОМ N. ЕСЛИ N ПРЕВЫШАЕТ ДЛИНУ МАССИВА, ТО ЗНАЧЕНИЕ ФУНКЦИИ РАВНО ЗНАЧЕНИЮ ПОСЛЕДНЕГО СИМВОЛА МАССИВА.

ПРИМЕРЫ:

```
C:=VSCHR(V,5)
M[I]:=VSCHR(V,I+1)
```

ПРОЦЕДУРА ПЕРЕСЫЛКИ СИМВОЛОВ ИЗ ОДНОГО ВИРТУАЛЬНОГО МАССИВА В ДРУГОЙ.

```
PROCEDURE  MOVVS(VAR VR,VW:VSTR)
```

ПРОЦЕДУРА ВЫПОЛНЯЕТ ПЕРЕСЫЛКУ СТРОКИ, СОДЕРЖАЩЕЙСЯ В МАССИВЕ, ЗАДАВАЕМЫМ ПЕРВЫМ ПАРАМЕТРОМ, В МАССИВ, ЗАДАВАЕМЫЙ ВТОРЫМ ПАРАМЕТРОМ. ПЕРЕСЫЛКА ВО ВТОРОЙ МАССИВ ОСУЩЕСТВЛЯЕТСЯ ДОЗАПИСЬЮ К УЖЕ СУЩЕСТВУЮЩЕМУ ЗНАЧЕНИЮ МАССИВА.

ПРОЦЕДУРА ПЕРЕСЫЛКИ ПОДСТРОКИ ИЗ ОДНОГО МАССИВА В ДРУГОЙ.

```
PROCEDURE  PARTVS(VAR VR:VSTR; N,L:INTEGER; VAR VW:VSTR)
```

ПРОЦЕДУРА ВЫПОЛНЯЕТ ПЕРЕСЫЛКУ ПОДСТРОКИ НАЧИНАЯ С СИМВОЛА С НОМЕРОМ N ДЛИНОЙ L  ИЗ МАССИВА, ЗАДАВАЕМОГО ПЕРВЫМ ПАРАМЕТРОМ, В МАССИВ, ЗАДАВАЕМЫЙ ЧЕТВЕРТЫМ ПАРАМЕТРОМ. ВТОРОЙ МАССИВ ПЕРЕД ПЕРЕСЫЛКОЙ ОБНУЛЯЕТСЯ.

ФУНКЦИЯ СРАВНЕНИЯ СТРОК, СОДЕРЖАЩИХСЯ В ДВУХ ВИРТУАЛЬНЫХ МАССИВАХ.

```
FUNCTION  CHRVS(VAR V1,V2:VSTR):INTEGER 
```

ВЫПОЛНЯЕТСЯ ЛЕКСИКОГРАФИЧЕСКОЕ СРАВНЕНИЕ ДВУХ МАССИВОВ. ЗНАЧЕНИЕ ФУНКЦИИ РАВНО:

```
-1,  ЕСЛИ V1<V2,
 0,  ЕСЛИ V1=V2,
 1,  ЕСЛИ V1>V2.
```

ПРОЦЕДУРА ВЫВОДА ВИРТУАЛЬНОГО МАССИВА НА ЭКРАН.

```
PROCEDURE  EKRVS(VAR V:VSTR)
```

## СРЕДСТВА ПРЕОБРАЗОВАНИЯ ДАННЫХ

ОБМЕН ДАННЫМИ С БАЗОЙ ДАННЫХ ОСУЩЕСТВЛЯЕТСЯ ЧЕРЕЗ ВИРТУАЛЬНЫЙ МАССИВ, ПРИ ЭТОМ ЦЕЛОЕ ЧИСЛО РАССМАТРИВАЕТСЯ КАК ПОСЛЕДОВАТЕЛЬНОСТЬ 2 БАЙТОВ, ВЕЩЕСТВЕННОЕ ЧИСЛО - ПОСЛЕДОВАТЕЛЬНОСТЬ 4 БАЙТОВ. ДЛЯ ПРЕОБРАЗОВАНИЯ ЧИСЕЛ В ПОСЛЕДОВАТЕЛЬНОСТЬ БАЙТОВ И ОБРАТНО ИСПОЛЬЗУЮТСЯ ПРОЦЕДУРЫ И ФУНКЦИИ, ОПИСАННЫЕ В НАСТОЯЩЕМ РАЗДЕЛЕ.

```
PROCEDURE  IB(I:INTEGER; VAR V:VSTR)
```

ПРОЦЕДУРА IB ПРЕОБРАЗУЕТ ЦЕЛОЕ ЧИСЛО В ДВА БАЙТА, КОТОРЫЕ ПЕРЕСЫЛАЮТСЯ (ДОЗАПИСЬЮ) В ВИРТУАЛЬНЫЙ МАССИВ.

```
FUNCTION  BI(VAR V:VSTR; J:INTEGER):INTEGER
```

ФУНКЦИЯ BI ПРЕОБРАЗУЕТ 2 БАЙТА ИЗ ВИРТУАЛЬНОГО МАССИВА, НАЧИНАЯ С БАЙТА, НОМЕР КОТОРОГО ОПРЕДЕЛЯЕТСЯ ПАРАМЕТРОМ J, В ЦЕЛОЕ, ЯВЛЯЮЩЕЕСЯ ЗНАЧЕНИЕМ ФУНКЦИИ.

```
PROCEDURE  RB(R:REAL; VAR V:VSTR)
```

ПРОЦЕДУРА RB ПРЕОБРАЗУЕТ ВЕЩЕСТВЕННОЕ ЧИСЛО В 4 БАЙТА, КОТОРЫЕ ПЕРЕСЫЛАЮТСЯ (ДОЗАПИСЬЮ) В ВИРТУАЛЬНЫЙ МАССИВ.

```
FUNCTION  BR(VAR V:VSTR):REAL
```

ФУНКЦИЯ BR ПРЕОБРАЗУЕТ 4 БАЙТА, НАХОДЯЩИЕСЯ В ВИРТУАЛЬНОМ МАССИВЕ, В ВЕЩЕСТВЕННОЕ ЧИСЛО, КОТОРОЕ ЯВЛЯЕТСЯ ЗНАЧЕНИЕМ ФУНКЦИИ.

# ПРЕДСТАВЛЕНИЕ БАЗЫ ДАННЫХ В ПРОГРАММЕ

БАЗА ДАННЫХ В ПРОГРАММЕ ОПИСЫВАЕТСЯ КАК ПЕРЕМЕННАЯ ТИПА DEFREL. оПРЕДЕЛЕНИЕ ТИПА ПРИВЕДЕНО НИЖЕ.

```
CONST
  MAXCOL=32; /* МАКСИМАЛЬНОЕ ЧИСЛО СТОЛБЦОВ */
TYPE
  /* ОПИСАНИЕ ФАЙЛА ПРЯМОГО ДОСТУПА (TBF И ADF) */

  BLOCK=ARRAY[0..511] OF CHAR;
  FILEBL=FILE OF BLOCK;

  /* ОПИСАНИЕ СТОЛБЦА */
  DEFCOL=RECORD
           TC:INTEGER; /* ТИП СТОЛБЦА */
           SC:INTEGER; /* СМЕЩЕНИЕ НАЧАЛА СТОЛБЦА В ЗАПИСИ */
           BN:INTEGER; /* НОМЕР БЛОКА ADF С ИМЕНЕМ СТОЛБЦА */
           SN:INTEGER; /* СМЕЩЕНИЕ ИМЕНИ В БЛОКЕ */
           LN:INTEGER  /* ДЛИНА ИМЕНИ СТОЛБЦА */
         END;
  DEFREL=RECORD
           NMDB:ALFA; /* ИМЯ БАЗЫ ДАННЫХ */
           FT:FILEBL; /* ФАЙЛ ЗАПИСЕЙ */
           FA:FILEBL; /* ФАЙЛ АЛФАВИТНЫХ ДАННЫХ */
           LDB:INTEGER; /* КОЛИЧЕСТВО ЗАПИСЕЙ В БД */
           LRC:INTEGER; /* ДЛИНА ЗАПИСИ В БАЙТАХ */
           NCL:INTEGER; /* ЧИСЛО СТОЛБЦОВ */
           NBA:INTEGER; /* НОМЕР БЛ. В ADF С ПЕРВЫМ СВОБОДНЫМ БАЙТОМ */
           SHA:INTEGER; /* СМЕЩЕНИЕ БАЙТА В БЛОКЕ */
           MC:ARRAY[1..MAXCOL] OF DEFCOL; /* ОПИСАНИЕ СТОЛБЦОВ */
           FC:ARRAY[1..MAXCOL,1..4] OF INTEGER; /* ОПИС. ЭКРАННЫХ ТАБЛИЦ */
           PRL:ARRAY[1..4] OF CHAR; /* ПАРОЛЬ */
           ERDB:INTEGER  /* КОД ОШИБКИ */
         END;
```

ПРИМЕР ОПИСАНИЯ БАЗЫ ДАННЫХ В ПРОГРАММЕ:

## W:DEFREL;

С ПОМОЩЬЮ ПЕРЕМЕННОЙ ТИПА DEFREL ОСУЩЕСТВЛЯЕТСЯ ДОСТУП К ДАННЫМ, ХРАНЯЩИМСЯ В БАЗЕ ДАННЫХ, И К ОТДЕЛЬНЫМ ЕЕ ПАРАМЕТРАМ.

ОСНОВНЫЕ ПАРАМЕТРЫ БАЗЫ ДАННЫХ:

```
W.LDB  -ТЕКУЩАЯ ДЛИНА БАЗЫ ДАННЫХ В ЗАПИСЯХ;
W.NCL  -ЧИСЛО СТОЛБЦОВ В БАЗЕ ДАННЫХ;
W.LRC  -ДЛИНА ЗАПИСИ В БАЙТАХ;
W.MC[I].TC  -ТИП I-ГО СТОЛБЦА. ДЛЯ ТИПА 1,2,3 ПЕРЕМЕННАЯ
             СОДЕРЖИТ НОМЕР ТИПА, ДЛЯ ТИПА 4 ( СТРОКА
             ФИКСИРОВАННОЙ ДЛИНЫ ) ПЕРЕМЕННАЯ СОДЕРЖИТ
             ДЛИНУ ФИКСИРОВАННОЙ СТРОКИ ПЛЮС 20;
W.MC[I].SC  -СМЕЩЕНИЕ ПЕРВОГО БАЙТА I-ГО СТОЛБЦА
             ОТНОСИТЕЛЬНО НАЧАЛА ЗАПИСИ.
```

ПОЛЕ FC ПРЕДСТАВЛЯЕТ ДВУМЕРНЫЙ МАССИВ, СОДЕРЖАЩИЙ ОПИСАНИЕ 4-Х СТАНДАРТНЫХ ЭКРАННЫХ ТАБЛИЦ. ПЕРВЫЙ ИНДЕКС МАССИВА ОПРЕДЕЛЯЕТ НОМЕР СТОЛБЦА, ВТОРОЙ - НОМЕР ЭКРАННОЙ ТАБЛИЦЫ. ЦЕЛОЧИСЛЕННОЕ ЗНАЧЕНИЕ ЭЛЕМЕНТА МАССИВА FC ОПРЕДЕЛЯЕТ ШИРИНУ СООТВЕТСТВУЮЩЕГО СТОЛБЦА ПРИ ВЫВОДЕ НА ЭКРАН. ЕСЛИ ОНО РАВНО 0, СТОЛБЕЦ НА ЭКРАН НЕ ВЫВОДИТСЯ. ВЕЩЕСТВЕННОЕ ЧИСЛО (ТИП 2) МОЖЕТ ВЫВОДИТЬСЯ КАК В ФОРМАТЕ С ПЛАВАЮЩЕЙ ТОЧКОЙ, НАПРИМЕР

## 1.255430E+01

ТАК И В ФОРМАТЕ С ФИКСИРОВАННОЙ ТОЧКОЙ, НАПРИМЕР

## 12.5543

В ЭТОМ СЛУЧАЕ В СТАРШИХ 8 РАЗРЯДАХ СОДЕРЖИТСЯ ЧИСЛО ЦИФР, ВЫВОДИМЫХ ПОСЛЕ ТОЧКИ.

ПОЛЕ PRL СОДЕРЖИТ ПАРОЛЬ, В СЛУЧАЕ ЗАЩИТЫ БАЗЫ ДАННЫХ ПАРОЛЕМ.

ПОЛЕ ERDB ИСПОЛЬЗУЕТСЯ ОТДЕЛЬНЫМИ ПРОЦЕДУРАМИ ДОСТУПА К БАЗЕ ДАННЫХ ДЛЯ СООБЩЕНИЯ ОБ ОШИБКАХ. ЕСЛИ ЕГО ЗНАЧЕНИЕ РАВНО НУЛЮ, ОШИБОК НЕ БЫЛО, В ПРОТИВНОМ СЛУЧАЕ ПОЛЕ СОДЕРЖИТ КОД ОШИБКИ.

ПРИ ИНИЦИАЛИЗАЦИИ БАЗЫ ДАННЫХ (СМ.П.6.1) ПРОИСХОДИТ СЧИТЫВАНИЕ ИЗ ФАЙЛА С РАСШИРЕНИЕМ DEF ЭЛЕМЕНТОВ ОПИСАНИЯ БАЗЫ ДАННЫХ И ЗАПОЛНЕНИЕ ПОЛЕЙ ПЕРЕМЕННОЙ ТИПА DEFREL. ПРИ ЗАКРЫТИИ БАЗЫ ДАННЫХ ЗНАЧЕНИЯ ЭТИХ ПОЛЕЙ ОБРАТНО ПЕРЕПИСЫВАЮТСЯ В ФАЙЛ ОПИСАНИЯ БАЗЫ ДАННЫХ.

В ПРОГРАММЕ МОЖНО РАБОТАТЬ С НЕСКОЛЬКИМИ БАЗАМИ ДАННЫХ,ОПИСАВ СООТВЕТСТВЕННО НЕСКОЛЬКО ПЕРЕМЕННЫХ ТИПА DEFREL.

ПРИМЕР:

```
U,W,Z:DEFREL; /* ОПИСАНИЕ ТРЕХ БАЗ ДАННЫХ */
```

# ДОСТУП К БАЗЕ ДАННЫХ

ДОСТУП К БАЗЕ ДАННЫХ ИЗ ПРОГРАММ НА ЯЗЫКАХ ПАСКАЛЬ И ГРАФИЧЕСКИЙ ПАСКАЛЬ ОСУЩЕСТВЛЯЕТСЯ С ПОМОЩЬЮ НАБОРА ПРОЦЕДУР И ФУНКЦИЙ, КОТОРЫЕ ОПИСЫВАЮТСЯ В ПРОГРАММЕ ПОЛЬЗОВАТЕЛЯ КАК ВНЕШНИЕ. НА ЭТАПЕ РЕДАКТИРОВАНИЯ СВЯЗЕЙ ОНИ ПОДКЛЮЧАЮТСЯ К ПРОГРАММЕ ИЗ БИБЛИОТЕКИ СУБД С ИМЕНЕМ LIBRDB.

## ОТКРЫТИЕ, ЗАКРЫТИЕ, СОЗДАНИЕ БАЗ ДАННЫХ

ПЕРЕД РАБОТОЙ БАЗА ДАННЫХ ДОЛЖНА БЫТЬ ИНИЦИАЛИЗИРОВАНА (ОТКРЫТА) ОДНОЙ ИЗ ДВУХ ПРОЦЕДУР. ПРИ ИНИЦИАЛИЗАЦИИ ОТКРЫВАЮТСЯ ФАЙЛ ЗАПИСЕЙ И ФАЙЛ АЛФАВИТНЫХ ДАННЫХ, А ОПИСАНИЕ БАЗЫ ДАННЫХ ИЗ ФАЙЛА С РАСШИРЕНИЕМ DEF ПЕРЕПИСЫВАЕТСЯ В ОПЕРАТИВНУЮ ПАМЯТЬ, ЗАПОЛНЯЯ СООТВЕТСТВУЮЩИЕ ПОЛЯ ПЕРЕМЕННОЙ ТИПА DEFREL.

```
PROCEDURE  INITDB(VAR W:DEFREL; VAR NM:ALFA; RW:CHAR)
```

ПРОЦЕДУРА INITDB СВЯЗЫВАЕТ ПЕРЕМЕННУЮ ТИПА DEFREL С БАЗОЙ ДАННЫХ ВО ВНЕШНЕЙ ПАМЯТИ С ИМЕНЕМ, ОПРЕДЕЛЯЕМЫМ ПАРАМЕТРОМ NM. БАЗА ДАННЫХ МОЖЕТ БЫТЬ ОТКРЫТА ДЛЯ ЧТЕНИЯ, В ЭТОМ СЛУЧАЕ ПАРАМЕТР RW ДОЛЖЕН ИМЕТЬ ЗНАЧЕНИЕ 'R', ИЛИ ДЛЯ ЧТЕНИЯ И ДЛЯ ЗАПИСИ, В ЭТОМ СЛУЧАЕ ПАРАМЕТР RW ДОЛЖЕН ИМЕТЬ ЗНАЧЕНИЕ 'W'. ПРИ ИНИЦИАЛИЗАЦИИ БАЗЫ ДАННЫХ С ПАРАМЕТРОМ 'W' ФАЙЛ ЗАПИСЕЙ И ФАЙЛ АЛФАВИТНЫХ ДАННЫХ ПЕРЕПИСЫВАЮТСЯ ВО ВРЕМЕННЫЕ ФАЙЛЫ С ВОЗМОЖНОСТЬЮ ИХ ПОСЛЕДУЮЩЕГО РАСШИРЕНИЯ. В ПЕРВОМ СЛУЧАЕ ТАКОЙ ПЕРЕПИСИ НЕ ПРОИЗВОДИТСЯ.

П_Р_И_М_Е_Ч_А_Н_И_Е.  ОТКРЫТИЕ БАЗЫ ДАННЫХ ТОЛЬКО ДЛЯ ЧТЕНИЯ ТЕМ НЕ МЕНЕЕ ПОЗВОЛЯЕТ ЗАПИСЫВАТЬ В НЕЕ ЗНАЧЕНИЯ, ЕСЛИ ТОЛЬКО ЭТО НЕ ВЕДЕТ К РАСШИРЕНИЮ ФАЙЛОВ, Т.Е. ДОПУСКАЕТСЯ МОДИФИКАЦИЯ ЗНАЧЕНИЙ СТОЛБЦОВ ТИПА 1,2,4 УЖЕ СУЩЕСТВУЮЩИХ ЗАПИСЕЙ.

ЕСЛИ БАЗА ДАННЫХ ЗАЩИЩЕНА ПАРОЛЕМ, ТО ПЕРЕД ВЫПОЛНЕНИЕМ ПРОЦЕДУРЫ INITDB ПОЛЮ PRL ПЕРЕМЕННОЙ, ЗАДАВАЕМОЙ ПАРАМЕТРОМ W, ДОЛЖНО БЫТЬ ПРИСВОЕНО ЗНАЧЕНИЕ ПАРОЛЯ.

ЕСЛИ ОТКРЫТИЕ БАЗЫ ДАННЫХ ПРОИЗОШЛО УСПЕШНО, ТО ЗНАЧЕНИЕ КОДА ЗАВЕРШЕНИЯ ERDB РАВНО НУЛЮ. ЕСЛИ ЕГО ЗНАЧЕНИЕ РАВНО 1,2,3, ТО ВО ВНЕШНЕЙ ПАМЯТИ ОТСУТСТВУЮТ ФАЙЛЫ БАЗЫ ДАННЫХ СООТВЕТСТВЕННО С РАСШИРЕНИЯМИ DEF, TBF, ADF. ЕСЛИ ЗНАЧЕНИЕ КОДА ЗАВЕРШЕНИЯ РАВНО 4, ПАРОЛЬ ЗАЩИТЫ БАЗЫ ДАННЫХ НЕ СОВПАЛ С ПАРОЛЕМ, ЗАПИСАННЫМ В ПОЛЕ PRL.

```
PROCEDURE  INIDDB(VAR W:DEFREL; VAR NM:ALFA; RW:CHAR)
```

ПРОЦЕДУРА INIDDB РАБОТАЕТ ТАКЖЕ КАК INITDB, НО В ОТЛИЧИЕ ОТ НЕЕ В СЛУЧАЕ, ЕСЛИ БАЗА ДАННЫХ ЗАЩИЩЕНА ПАРОЛЕМ, ПРОЦЕДУРА INIDDB ЗАПРАШИВАЕТ ПАРОЛЬ В ДИАЛОГЕ, ВЫДАВАЯ НА ЭКРАН ЗАПРОС:

## ПАРОЛЬ?

В ОТВЕТ НА КОТОРЫЙ ДОЛЖЕН БЫТЬ ВВЕДЕН ПАРОЛЬ. ЕСЛИ ПАРОЛЬ НЕВЕРЕН, ВЫВОДИТСЯ ДИАГНОСТИКА:

## ПАРОЛЬ НЕВЕРЕН

И ЗАПРОС ПАРОЛЯ ПОВТОРЯЕТСЯ. ПРИ ПОВТОРНОМ ВВОДЕ НЕВЕРНОГО ПАРОЛЯ ОПЯТЬ ВЫВОДИТСЯ ДИАГНОСТИКА И ВЫПОЛНЕНИЕ ПРОЦЕДУРЫ ЗАВЕРШАЕТСЯ С КОДОМ 4.

```
PROCEDURE  CLOSEDB(VAR W:DEFREL)
```

ПРОЦЕДУРА CLOSEDB ПЕРЕПИСЫВАЕТ ОПИСАНИЕ БАЗЫ ДАННЫХ В ФАЙЛ С РАСШИРЕНИЕМ DEF, ДОЗАПИСЫВАЕТ БУФЕРА И ЗАКРЫВАЕТ ФАЙЛЫ БАЗЫ ДАННЫХ. ПРОЦЕДУРА ВСЕГДА ДОЛЖНА ИСПОЛЬЗОВАТЬСЯ В КОНЦЕ РАБОТЫ С БАЗОЙ ДАННЫХ, ЕСЛИ ВЫПОЛНЯЛИСЬ ЕЕ МОДИФИКАЦИЯ ИЛИ РАСШИРЕНИЕ.

НИЖЕ, В КАЧЕСТВЕ ПРИМЕРА, ПРИВЕДЕН ФРАГМЕНТ ПРОГРАММЫ НА ГРАФИЧЕСКОМ ПАСКАЛЕ, В КОТОРОЙ ВЫПОЛНЯЕТСЯ ЗАПРОС ИМЕНИ БАЗЫ ДАННЫХ, ОТКРЫТИЕ БАЗЫ ДАННЫХ, ВЫДАЧА ДИАГНОСТИКИ В СЛУЧАЕ ОТСУТСТВИЯ ОДНОГО ИЗ ФАЙЛОВ БАЗЫ ДАННЫХ ИЛИ НЕВЕРНОГО ЗАДАНИЯ ИМЕНИ БАЗЫ ДАННЫХ С ПОВТОРНЫМ ЗАПРОСОМ ИМЕНИ, ВЫХОД ИЗ ПРОГРАММЫ В СЛУЧАЕ НЕВЕРНОГО ЗАДАНИЯ ПАРОЛЯ, ЗАКРЫТИЕ БАЗЫ ДАННЫХ В КОНЦЕ РАБОТЫ.

```
CONST
  Z1=' ИМЯ БАЗЫ ДАННЫХ? ';
  Z2=' БАЗА ДАННЫХ НЕ НАЙДЕНА ';
  RUS=16B;  /* КОД РУССКОЙ КЛАВИАТУРЫ */
  LAT=17B;  /* КОД ЛАТИНСКОЙ КЛАВИАТУРЫ */
VAR
  W:DEFREL;
  NM:ALFA;  /* МАССИВ ДЛЯ ВВОДА ИМЕНИ БД */
/* ОПИСАНИЕ ДВУХ ВНЕШНИХ ПРОЦЕДУР */
PROCEDURE  INIDDB(VAR W:DEFREL; VAR NM:ALFA; RW:CHAR); EXTERNAL;
```

```
PROCEDURE  CLOSEDB(VAR W:DEFREL); EXTERNAL;
/* ГОЛОВНОЙ ГРАФ ПРОГРАММЫ */
```

```
                            W.ERDB=4 
$------------------------->$------------------------------>$
!WRITE(CHR(RUS),Z1)        !                               ! 
!WRITE(CHR(LAT))           !------------------------------>!
!READLN(NM)                !/* РАБОТА С БАЗОЙ ДАННЫХ */ 
!INIDDB(W,NAME,'W')        !          . . .
!                          !CLOSEDB(W) 
!(W.ERDB>0)AND(W.ERDB<4)   !
!<-------------------------!
 WRITELN(CHR(RUS),Z2)       
```

НОВУЮ БАЗУ ДАННЫХ МОЖНО СОЗДАТЬ ПРОГРАММНО С ПОМОЩЬЮ ПРОЦЕДУРЫ CREDB.

```
PROCEDURE  CREDB(VAR W:DEFREL; VAR NM:ALFA; VAR V:VSTR)
```

ПЕРЕД ВЫПОЛНЕНИЕМ ПРОЦЕДУРЫ ДОЛЖНЫ БЫТЬ ЗАПОЛНЕНЫ ОТДЕЛЬНЫЕ ПОЛЯ ПЕРЕМЕННОЙ-ОПИСАНИЯ БАЗЫ ДАННЫХ, ЗАДАВАЕМОЙ ПЕРВЫМ ПАРАМЕТРОМ - ПОЛЕ NCL ДОЛЖНО СОДЕРЖАТЬ ЧИСЛО СТОЛБЦОВ СОЗДАВАЕМОЙ БАЗЫ ДАННЫХ И ДЛЯ КАЖДОГО СТОЛБЦА ЗАПОЛНЯЮТСЯ ПОЛЯ TC И LN (ТИП СТОЛБЦА И ДЛИНА ИМЕНИ СТОЛБЦА) МАССИВА ОПИСАНИЯ СТОЛБЦОВ MC. ИМЕНА СТОЛБЦОВ В ПОРЯДКЕ СЛЕДОВАНИЯ СТОЛБЦОВ ДОЛЖНЫ БЫТЬ ЗАПИСАНЫ В ВИРТУАЛЬНЫЙ МАССИВ, ЗАДАВАЕМЫЙ ТРЕТЬИМ ПАРАМЕТРОМ. ВТОРОЙ ПАРАМЕТР ОПРЕДЕЛЯЕТ ИМЯ БАЗЫ ДАННЫХ.

ПРОЦЕДУРА СОЗДАЕТ ФАЙЛЫ БАЗЫ ДАННЫХ И ЗАПОЛНЯЕТ ОСТАВШИЕСЯ ПОЛЯ ЕЕ ОПИСАНИЯ.

ПРОЦЕДУРА ЗАПОЛНЯЕТ ПОЛЕ ПАРОЛЯ PRL ПРОБЕЛАМИ (ЧТО ОЗНАЧАЕТ ОТСУТСТВИЕ ПАРОЛЯ). ДЛЯ ВВОДА ПАРОЛЯ ЗАЩИТЫ БАЗЫ ДАННЫХ ПОСЛЕ ВЫПОЛНЕНИЯ ПРОЦЕДУРЫ CRERDB В ПОЛЕ PRL ДОЛЖЕН БЫТЬ ЗАПИСАН ПАРОЛЬ.

ПОСЛЕ ВЫПОЛНЕНИЯ ПРОЦЕДУРЫ БАЗА ДАННЫХ СОЗДАНА И ОТКРЫТА ДЛЯ РАБОТЫ. ДЛЯ СОХРАНЕНИЯ БАЗЫ ДАННЫХ ВО ВНЕШНЕЙ ПАМЯТИ ПОСЛЕ ОКОНЧАНИЯ РАБОТЫ С НЕЙ ДОЛЖНА БЫТЬ ВЫПОЛНЕНА ПРОЦЕДУРА CLOSEDB.

## ЗАПОЛНЕНИЕ И МОДИФИКАЦИЯ БАЗЫ ДАННЫХ

ДЛЯ ДОБАВЛЕНИЯ ЗАПИСЕЙ В БАЗУ ДАННЫХ СЛУЖАТ ПРОЦЕДУРЫ ADDREC И INSREC.

```
PROCEDURE  ADDREC(VAR W:DEFREL; VAR V:VSTR)
```

ПРОЦЕДУРА ADDREC ДОБАВЛЯЕТ ЗАПИСЬ, НАХОДЯЩУЮСЯ В МАССИВЕ, ЗАДАВАЕМОМ ПАРАМЕТРОМ V, В ХВОСТ БАЗЫ ДАННЫХ, ЗАДАВАЕМОЙ ПАРАМЕТРОМ W. ДЛИНА БАЗЫ ДАННЫХ УВЕЛИЧИВАЕТСЯ НА 1.

```
PROCEDURE  INSREC(VAR W:DEFREL; T:INTEGER; VAR V:VSTR)
```

ПРОЦЕДУРА INSREC ДОБАВЛЯЕТ НОВУЮ ЗАПИСЬ, НАХОДЯЩУЮСЯ В МАССИВЕ, ЗАДАВАЕМОМ ПАРАМЕТРОМ V, В БАЗУ ДАННЫХ, ЗАДАВАЕМУЮ ПАРАМЕТРОМ W, ПОД НОМЕРОМ T. ЕСЛИ ЗНАЧЕНИЕ T ПРЕВЫШАЕТ ДЛИНУ БАЗЫ ДАННЫХ, ЗАПИСЬ ДОБАВЛЯЕТСЯ В ХВОСТ БАЗЫ ДАННЫХ. В ПРОТИВНОМ СЛУЧАЕ ОТТЯГИВАЕТСЯ ХВОСТ БАЗЫ ДАННЫХ, НАЧИНАЯ С ЗАПИСИ С НОМЕРОМ T, И В ОСВОБОДИВШЕЕСЯ МЕСТО ВСТАВЛЯЕТСЯ НОВАЯ ЗАПИСЬ. ДЛИНА БАЗЫ ДАННЫХ УВЕЛИЧИВАЕТСЯ НА 1.

ЕСЛИ ЗНАЧЕНИЕ ПАРАМЕТРА T МЕНЬШЕ 1, КОД ОШИБКИ РАВЕН 1. ЕСЛИ ПРИ ВЫПОЛНЕНИИ ОБЕИХ ПРОЦЕДУР ДЛИНА МАССИВА V НЕ СОВПАДАЕТ С ДЛИНОЙ ЗАПИСИ, КОД ОШИБКИ РАВЕН 2.

ЗАПИСЬ В ВИРТУАЛЬНОМ МАССИВЕ МОЖЕТ БЫТЬ СФОРМИРОВАНА ПРОЦЕДУРАМИ CHRVS, MOVVS, IB, RB. ДЛЯ ТОГО ЧТОБЫ СТРОКУ ПРОИЗВОЛЬНОЙ ДЛИНЫ (ТИП=3) ЗАПИСАТЬ В ФАЙЛ АЛФАВИТНЫХ ДАННЫХ, А ССЫЛКУ НА НЕЕ ИМЕТЬ ВОЗМОЖНОСТЬ ЗАНЕСТИ В ЗАПИСЬ, СЛУЖИТ ПРОЦЕДУРА WRALFA

```
PROCEDURE  WRALFA(VAR W:DEFREL; VAR V:VSTR)
```

ПРОЦЕДУРА ПЕРЕСЫЛАЕТ СТРОКУ СИМВОЛОВ, НАХОДЯЩУЮСЯ В МАССИВЕ, ЗАДАВАЕМОМ ПАРАМЕТРОМ V В ФАЙЛ АЛФАВИТНЫХ ДАННЫХ БАЗЫ ДАННЫХ W. ПОСЛЕ ВЫПОЛНЕНИЯ ПРОЦЕДУРЫ МАССИВ V СОДЕРЖИТ 3 ЦЕЛЫХ ЧИСЛА (6 БАЙТОВ), ОПРЕДЕЛЯЮЩИХ ПОЛОЖЕНИЕ СТРОКИ В ФАЙЛЕ АЛФАВИТНЫХ ДАННЫХ. ЭТИ 6 БАЙТОВ МОГУТ БЫТЬ ЗАНЕСЕНЫ В ЗАПИСЬ В КАЧЕСТВЕ ЗНАЧЕНИЯ СТОЛБЦА ТИПА 3.

УДАЛЕНИЕ ЗАПИСЕЙ ИЗ БАЗЫ ДАННЫХ ВЫПОЛНЯЕТСЯ ПРОЦЕДУРОЙ DELREC.

```
PROCEDURE  DELREC(VAR W:DEFREL; T,N:INTEGER)
```

ПРОЦЕДУРА УДАЛЯЕТ ИЗ БАЗЫ ДАННЫХ, ЗАДАВАЕМОЙ ПАРАМЕТРОМ W, N ЗАПИСЕЙ НАЧИНАЯ С ЗАПИСИ, НОМЕР КОТОРОЙ ОПРЕДЕЛЯЕТСЯ ПАРАМЕТРОМ T. ЕСЛИ УДАЛЯЕМЫЕ ЗАПИСИ НЕ ЯВЛЯЮТСЯ ПОСЛЕДНИМИ, ПОДТЯГИВАЕТСЯ ХВОСТ БАЗЫ ДАННЫХ. НА ВЕЛИЧИНУ N УМЕНЬШАЕТСЯ ДЛИНА БАЗЫ ДАННЫХ.

ЕСЛИ ПАРМЕТР T ЗАДАЕТ НЕСУЩЕСТВУЮЩИЙ НОМЕР ЗАПИСИ, КОД ОШИБКИ УСТАНАВЛИВАЕТСЯ РАВНЫМ 1.

ДЛЯ ВЫБОРКИ И ЗАМЕНЫ ЗАПИСИ В ПРЕДЕЛАХ БАЗЫ ДАННЫХ СЛУЖАТ ПРОЦЕДУРЫ RREC И WREC.

```
PROCEDURE  RREC(VAR W:DEFREL; T:INTEGER; VAR V:VSTR)
```

ПРОЦЕДУРА RREC ВЫБИРАЕТ ЗАПИСЬ С НОМЕРОМ T ИЗ БАЗЫ ДАННЫХ, ЗАДАВАЕМОЙ ПАРАМЕТРОМ W, В МАССИВ, ЗАДАВАЕМЫЙ ПАРАМЕТРОМ V.

```
PROCEDURE  WREC(VAR W:DEFREL; T:INTEGER; VAR V:VSTR)
```

ПРОЦЕДУРА WREC ПЕРЕСЫЛАЕТ ЗАПИСЬ ИЗ МАССИВА В БАЗУ ДАННЫХ, ЗАДАВАЕМУЮ ПАРАМЕТРОМ W, ПОД НОМЕРОМ T. СТАРОЕ ЗНАЧЕНИЕ ЗАПИСИ СТИРАЕТСЯ.

ЕСЛИ В ОБЕИХ ПРОЦЕДУРАХ ЗАДАЕТСЯ НЕСУЩЕСТВУЮЩИЙ НОМЕР ЗАПИСИ, КОД ОШИБКИ РАВЕН 1. ЕСЛИ ПРИ ВЫПОЛНЕНИИ ПРОЦЕДУРЫ WREC ДЛИНА МАССИВА НЕ СОВПАДАЕТ С ДЛИНОЙ ЗАПИСИ, КОД ОШИБКИ РАВЕН 2.

ДЛЯ ВЫБОРКИ И ЗАМЕНЫ ЗНАЧЕНИЯ СТОЛБЦА В ПРЕДЕЛАХ БАЗЫ ДАННЫХ СЛУЖАТ ПРОЦЕДУРЫ RCOL И WCOL.

```
PROCEDURE  RCOL(VAR W:DEFREL; T,NC:INTEGER; VAR V:VSTR)
```

ПРОЦЕДУРА RCOL ВЫБИРАЕТ СОДЕРЖИМОЕ СТОЛБЦА С НОМЕРОМ NC ЗАПИСИ С НОМЕРОМ T ИЗ БАЗЫ ДАННЫХ, ЗАДАВАЕМОЙ ПАРАМЕТРОМ W, В МАССИВ, ЗАДАВАЕМЫЙ ПАРАМЕТРОМ V.

```
PROCEDURE  WCOL(VAR W:DEFREL; T,NC:INTEGER; VAR V:VSTR)
```

ПРОЦЕДУРА WCOL ПЕРЕСЫЛАЕТ ДАННЫЕ ИЗ МАССИВА, ЗАДАВАЕМОГО ПАРАМЕТРОМ V, В СТОЛБЕЦ С НОМЕРОМ NC ЗАПИСИ С НОМЕРОМ T БАЗЫ ДАННЫХ, ЗАДАВАЕМОЙ ПАРАМЕТРОМ W. СТАРОЕ ЗНАЧЕНИЕ СТОЛБЦА ТЕРЯЕТСЯ.

ПРИ РАБОТЕ СО СТОЛБЦОМ ТИПА 3 ПРОЦЕДУРЫ RCOL И WCOL САМИ ОСУЩЕСТВЛЯЮТ ОБРАЩЕНИЕ К ФАЙЛУ АЛФАВИТНЫХ ДАННЫХ, ВЫБИРАЯ ИЗ ФАЙЛА В ВИРТУАЛЬНЫЙ МАССИВ СТРОКУ ПРОИЗВОЛЬНОЙ ДЛИНЫ ИЛИ ПЕРЕСЫЛАЯ ЕЕ ИЗ МАССИВА В ФАЙЛ.

ПРИ ЗАДАНИИ НЕСУЩЕСТВУЮЩЕГО НОМЕРА ЗАПИСИ В ОБЕИХ ПРОЦЕДУРАХ КОД ОШИБКИ РАВЕН 1, ПРИ ЗАДАНИИ НЕСУЩЕСТВУЮЩЕГО НОМЕРА СТОЛБЦА КОД ОШИБКИ РАВЕН 2. ЕСЛИ ПРИ ВЫПОЛНЕНИИ ПРОЦЕДУРЫ WCOL ДЛИНА МАССИВА V НЕ СОВПАДАЕТ С ДЛИНОЙ СТОЛБЦА, КОД ОШИБКИ РАВЕН 3.

ИМЯ СТОЛБЦА МОЖЕТ БЫТЬ ПОЛУЧЕНО С ПОМОЩЬЮ ПРОЦЕДУРЫ RNMCOL.

```
PROCEDURE RNMCOL(VAR W:DEFREL; NC:INTEGER; VAR V:VSTR)
```

ПРОЦЕДУРА ПЕРЕСЫЛАЕТ ИМЯ СТОЛБЦА, НОМЕР КОТОРОГО ЗАДАЕТСЯ ПАРАМЕТРОМ NC, В ВИРТУАЛЬНЫЙ МАССИВ, ЗАДАВАЕМЫЙ ПАРАМЕТРОМ V. ПРИ ЗАДАНИИ НЕСУЩЕСТВУЮЩЕГО НОМЕРА СТОЛБЦА КОД ОШИБКИ РАВЕН 1.

# СРЕДСТВА ВВОДА С КЛАВИАТУРЫ ДИСПЛЕЯ

## ОБЩИЕ СВЕДЕНИЯ

ПРЕДЛАГАЕМЫЕ ОС РАФОС СРЕДСТВА ВВОДА С КЛАВИАТУРЫ (ОПИРАЮЩИЕСЯ НА ИСПОЛЬЗОВАНИЕ СТАНДАРТНОГО ДРАЙВЕРА ТЕРМИНАЛА) ИМЕЮТ РЯД СУЩЕСТВЕННЫХ НЕДОСТАТКОВ, ОСНОВНЫМИ ИЗ КОТОРЫХ ЯВЛЯЮТСЯ: ТРУДНОСТИ ПРИ РЕАЛИЗАЦИИ ПЕРЕМЕННОГО ВВОДА РУССКОГО И ЛАТИНСКОГО ТЕКСТА, ВЫДАЧА ДИАГНОСТИКИ НА АНГЛИЙСКОМ ЯЗЫКЕ, СОПРОВОЖДАЕМОЙ В РЯДЕ СЛУЧАЕВ АВАРИЙНЫМ ЗАВЕРШЕНИЕМ ПРОГРАММЫ.

ОПИСАННЫЕ НИЖЕ СРЕДСТВА НАСТРОЕНЫ НА ДИСПЛЕЙ ТИПА 15ИЭ-00-013 И ОБЕСПЕЧИВАЮТ:

ВВОД ТЕКСТА С КЛАВИАТУРЫ С ИСПОЛЬЗОВАНИЕМ РУССКИХ И ЛАТИНСКИХ БУКВ НЕЗАВИСИМО ОТ СОСТОЯНИЯ КЛАВИАТУРЫ "ВЕРХНИЙ РЕГИСТР - НИЖНИЙ РЕГИСТР", С ВЫВОДОМ ВВОДИМЫХ СИМВОЛОВ НА ЭКРАН (ЭХОСИГНАЛ) И БЕЗ ВЫВОДА;

ВВОД КОДОВ ФУНКЦИОНАЛЬНЫХ КЛАВИШ;

ВВОД ЦЕЛЫХ И ВЕЩЕСТВЕННЫХ ЧИСЕЛ С ВЫДАЧЕЙ ДИАГНОСТИЧЕСКИХ СООБЩЕНИЙ НА РУССКОМ ЯЗЫКЕ.

СРЕДСТВА ВВОДА ИСПОЛЬЗУЮТ ДВЕ СТАНДАРТНО ОПИСАННЫЕ В ФАЙЛЕ DEFRDB.PAS ЦЕЛОЧИСЛЕННЫЕ ПЕРЕМЕННЫЕ.

ПЕРЕМЕННАЯ LATRUS СОДЕРЖИТ КОД, ХАРАКТЕРИЗУЮЩИЙ СОСТОЯНИЕ КЛАВИАТУРЫ "РУССКИЙ РЕГИСТР" - КОД 16В, "ЛАТИНСКИЙ РЕГИСТР" - 17В. ПРИ ПРОГРАММНОМ ПЕРЕКЛЮЧЕНИИ КЛАВИАТУРЫ В ОДНО ИЗ ЭТИХ СОСТОЯНИЙ НЕОБХОДИМО В ПЕРЕМЕННУЮ LATRUS ЗАСЫЛАТЬ СООТВЕТСТВУЮЩИЙ КОД ЛИБО ПОЛЬЗОВАТЬСЯ ОПИСАННЫМИ НИЖЕ ПРОЦЕДУРАМИ WRUS И WLAT.

ПЕРЕМЕННАЯ PRKLR ИСПОЛЬЗУЕТСЯ ДЛЯ УПРАВЛЕНИЯ РЕЖИМОМ ВВОДА И ДЛЯ ПЕРЕДАЧИ ИНФОРМАЦИИ ОБ ОШИБКАХ.

НОЛЬ МЛАДШИХ РАЗРЯДАХ ПЕРЕМЕННОЙ ОЗНАЧАЕТ ВВОД С ЭХОМ НА ЭКРАН, 1 - БЕЗ ЭХА.

НОЛЬ В СТАРШИХ РАЗРЯДАХ (СТАРШЕМ БАЙТЕ) ПЕРЕМЕННОЙ ОЗНАЧАЕТ ОТСУТСТВИЕ ОШИБОК ПРИ ВВОДЕ, 1 - ПРИ ВВОДЕ ЧИСЕЛ БЫЛИ ОБНАРУЖЕНЫ ОШИБКИ.

ВВОД ТЕКСТА С КЛАВИАТУРЫ ДОЛЖЕН ЗАКАНЧИВАТЬСЯ НАЖАТИЕМ КЛАВИШИ "ВК".

ПРИ ВВОДЕ ЦЕЛЫХ И ВЕЩЕСТВЕННЫХ ЧИСЕЛ ОПРЕДЕЛЕНО ПОНЯТИЕ ПУСТОГО ЗНАЧЕНИЯ ЧИСЛА, КОТОРОЕ ЯВЛЯЕТСЯ РЕЗУЛЬТАТОМ ВВОДА В СЛУЧАЕ, ЕСЛИ ЛИБО БЫЛА НАЖАТА ТОЛЬКО ОДНА КЛАВИША "ВК", ЛИБО ПРИ ВВОДЕ ЧИСЛА БЫЛИ ЗАРЕГИСТРИРОВАНЫ ОШИБКИ. ПУСТОЕ ЗНАЧЕНИЕ ЦЕЛОГО И ВЕЩЕСТВЕННОГО ЧИСЛА ОПРЕДЕЛЯЕТСЯ ОПИСАННЫМИ В ФАЙЛЕ DEFRDB.PAS КОНСТАНТАМИ

```
EMPINT=-MAXINT
EMPREAL=-1.0E-38
```

## ПРОЦЕДУРЫ ВВОДА

ПЕРЕКЛЮЧЕНИЕ ОТ СТАНДАРТНЫХ СРЕДСТВ ВВОДА С КЛАВИАТУРЫ ОС НА СРЕДСТВА ВВОДА СУБД И ОБРАТНО ВЫПОЛНЯЮТ ДВЕ ПРОЦЕДУРЫ BEGKLR И ENDKLR.

ПРОЦЕДУРА BEGKLR ОТКЛЮЧАЕТ РЕЖИМ ПРЕРЫВАНИЯ ОТ КЛАВИАТУРЫ И УСТАНАВЛИВАЕТ КЛАВИАТУРУ В НАЧАЛЬНОЕ СОСТОЯНИЕ "РУССКИЙ РЕГИСТР".

ПРОЦЕДУРА ENDKLR ВОССТАНАЛИВАЕТ РЕЖИМ ПРЕРЫВАНИЯ КЛАВИАТУРЫ, ВОЗВРАЩАЯ ТЕМ САМЫМ ФУНКЦИИ ОБРАБОТКИ ВВОДА СТАНДАРТНОМУ ДРАЙВЕРУ, И УСТАНАВЛИВАЕТ КЛАВИАТУРУ В СОСТОЯНИЕ "ЛАТИНСКИЙ РЕГИСТР".

ПЕРЕД ОБРАЩЕНИЕМ К ПРОЦЕДУРАМ ВВОДА СУБД ДОЛЖНА БЫТЬ ВЫПОЛНЕНА ПРОЦЕДУРА BEGKLR. ПЕРЕД ВЫХОДОМ ИЗ ПРОГРАММЫ ИЛИ ПРИ НЕОБХОДИМОСТИ ВВОДА ЧЕРЕЗ СТАНДАРТНЫЙ ДРАЙВЕР ОС ДОЛЖНА БЫТЬ ВЫПОЛНЕНА ПРОЦЕДУРА ENDKLR.

ОСНОВНОЙ ПРОЦЕДУРОЙ ВВОДА С КЛАВИАТУРЫ ЯВЛЯЕТСЯ ПРОЦЕДУРА RDTX.

```
PROCEDURE RDTX(VAR V:VSTR)
```

ПРОЦЕДУРА ОСУЩЕСТЛЯЕТ ВВОД ТЕКСТА ИЛИ КОДА ФУНКЦИОНАЛЬНОЙ КЛАВИШИ С КЛАВИАТУРЫ В ВИРТУАЛЬНЫЙ МАССИВ. ВВОД ТЕКСТА ЗАКАНЧИВАЕТСЯ НАЖАТИЕМ КЛАВИШИ "ВК". КОД ФУНКЦИОНАЛЬНОЙ КЛАВИШИ СЧИТЫВАЕТСЯ ТОЛЬКО ПРИ ПЕРВОМ НАЖАТИИ. ВНУТРИ ТЕКСТА КОДЫ ФУНКЦИОНАЛЬНЫХ КЛАВИШ ИГНОРИРУЮТСЯ ЗА ИСКЛЮЧЕНИЕМ КЛАВИШ "РУС", "ЛАТ", "ЗАБ".

ВИРТУАЛЬНЫЙ МАССИВ ПЕРЕД ВВОДОМ АВТОМАТИЧЕСКИ ОБНУЛЯЕТСЯ. КОД КЛАВИШ "ВК" В МАССИВ НЕ ЗАНОСИТСЯ. СЧИТАННЫЙ КОД ФУНКЦИОНАЛЬНОЙ КЛАВИШИ МОЖЕТ БЫТЬ ИЗВЛЕЧЕН ИЗ ВИРТУАЛЬНОГО МАССИВА, НАПРИМЕР, С ПОМОЩЬЮ ФУНКЦИИ VSCHR.

ПРИМЕР:

```
V:VSTR;
C:INTEGER;
. . .
RDTX(V)
C:=ORD(VSCHR(V,1))
```

В ЗАВИСИМОСТИ ОТ ЗНАЧЕНИЯ ПЕРЕМЕННОЙ PRKLR (СМ.П.7.1) ВВОД СИМВОЛОВ С КЛАВИАТУРЫ МОЖЕТ СОПРОВОЖДАТЬСЯ ВЫВОДОМ ИХ НА ЭКРАН ИЛИ НЕ СОПРОВОЖДАТЬСЯ.

ЧТЕНИЕ С КЛАВИАТУРЫ ЦЕЛОГО ЧИСЛА ОСУЩЕСТВЛЯЕТСЯ ПРОЦЕДУРОЙ RDINT

```
PROCEDURE RDINT(VAR I:INTEGER)
```

ПРОЦЕДУРА ВЫПОЛНЯЕТ ЧТЕНИЕ ЧИСЛА В ЦЕЛОЧИСЛЕННУЮ ПЕРЕМЕННУЮ, ЗАДАВАЕМУЮ ПАРАМЕТРОМ I. ЕСЛИ ЧИСЛО ЗАДАНО НЕВЕРНО, ВЫДАЕТСЯ ДИАГНОСТИЧЕСКОЕ СООБЩЕНИЕ:

```
НЕВЕРНОЕ ЧИСЛО
```

ЕСЛИ ЗНАЧЕНИЕ ВВОДИМОГО ЧИСЛА ПРЕВЫШАЕТ ДОПУСТИМОЕ (-32768..32767), ВЫДАЕТСЯ ДИАГНОСТИЧЕСКОЕ СООБЩЕНИЕ:

```
ЧИСЛО ПРЕВЫШАЕТ ДОПУСТИМОЕ
```

В СЛУЧАЕ ОШИБКИ, В ПЕРЕМЕННУЮ PRKLR ЗАНОСИТСЯ ПРИЗНАК ОШИБКИ (1 В СТАРШЕМ БАЙТЕ). ПРИ НАЛИЧИИ ОШИБКИ, А ТАКЖЕ ПРИ НАЖАТИИ ТОЛЬКО ОДНОЙ КЛАВИШИ "ВК", ПЕРЕМЕННОЙ, ЗАДАВАЕМОЙ ПАРАМЕТРОМ I, ПРИСВАИВАЕТСЯ ЗНАЧЕНИЕ EMPINT (СМ.П.7.1).

ЧТЕНИЕ С КЛАВИАТУРЫ ВЕЩЕСТВЕННОГО ЧИСЛА ОСУЩЕСТВЛЯЕТСЯ ПРОЦЕДУРОЙ RDREAL

```
PROCEDURE RDREAL(VAR R:REAL)
```

ПРОЦЕДУРА ВЫПОЛНЯЕТ ЧТЕНИЕ ВЕЩЕСТВЕННОГО ЧИСЛА В ПЕРЕМЕННУЮ ТИПА REAL, ЗАДАВАЕМУЮ ПАРАМЕТРОМ R. ПРИ ОШИБКЕ В ЗАПИСИ МАНТИСЫ И ПОРЯДКА ЧИСЛА, ВЫДАЕТСЯ ДИАГНОСТИЧЕСКОЕ СООБЩЕНИЕ:

```
НЕВЕРНОЕ ЧИСЛО
```

ИЛИ

```
НЕВЕРНЫЙ ПОКАЗАТЕЛЬ
```

ЕСЛИ ЧИСЛО ПРЕВЫШАЕТ ДОПУСТИМОЕ, ВЫДАЕТСЯ СООБЩЕНИЕ:

```
ЧИСЛО ПРЕВЫШАЕТ ДОПУСТИМОЕ
```

В СЛУЧАЕ ОШИБКИ, В ПЕРЕМЕННУЮ PRKLR ЗАНОСИТСЯ ПРИЗНАК ОШИБКИ (1 В СТАРШЕМ БАЙТЕ). ПРИ НАЛИЧИИ ОШИБКИ, А ТАКЖЕ ПРИ НАЖАТИИ ТОЛЬКО ОДНОЙ КЛАВИШИ "ВК", ПЕРЕМЕННОЙ, ЗАДАВАЕМОЙ ПАРАМЕТРОМ R, ПРИСВАИВАЕТСЯ ЗНАЧЕНИЕ EMPREAL (СМ.П. 7.1).

ПРОЦЕДУРЫ RDINT И RDREAL ИСПОЛЬЗУЮТСЯ ВНУТРИ СЕБЯ ДЛЯ ВВОДА ТЕКСТА ЧИСЛА ПРОЦЕДУРУ RDTX.

ДЛЯ ПЕРЕКЛЮЧЕНИЯ КЛАВИАТУРЫ В СОСТОЯНИЕ "РУССКИЙ РЕГИСТР", "ЛАТИНСКИЙ РЕГИСТР" ИСПОЛЬЗУЮТСЯ СООТВЕТСТВЕННО ПРОЦЕДУРЫ БЕЗ ПАРАМЕТРОВ WRUS И WLAT, КОТОРЫЕ ОДНОВРЕМЕННО С ПЕРЕКЛЮЧЕНИЕМ ЗАПОМИНАЮТ СОСТОЯНИЕ КЛАВИАТУРЫ В ПЕРЕМЕННОЙ  LATRUS.
