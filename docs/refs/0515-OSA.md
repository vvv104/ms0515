## 1. Начальные сведения

### 1.1. Общие сведения о ПЭВМ

ПЭВМ «Электроника МС0515» включает следующие устройства:

- центральный процессор;
- память (оперативная и постоянная);
- терминал (клавиатура и видеомонитор);
- накопитель для гибких магнитных дисков;
- синтезатор звука.

Процессор осуществляет управление работой ПЭВМ и выполняет все арифметические операции.

В оперативной памяти располагаются все программы, выполняемые ПЭВМ, и данные, используемые программами. Оперативная память используется для временного хранения информации.

Постоянная память предназначена для сохранения информации при отключении питания, необходимой для запуска и функционирования ПЭВМ.

Терминал предназначен для ввода и вывода информации. Ввод информации от пользователя в ПЭВМ осуществляется с помощью клавиатуры. Вывод информации из ПЭВМ осуществляется на экран видеомонитора.

Накопитель для гибких магнитных дисков предназначен для записи и чтения информации с дисков диаметром **133 мм**. Гибкие диски позволяют переносить документы и программы с одной ПЭВМ на другую, хранить информацию, не используемую постоянно на ПЭВМ, делать архивные копии.

Синтезатор звука предназначен для формирования программно управляемых звуковых сигналов, что даёт возможность исполнять музыку с помощью ПЭВМ.

### 1.2. Общие сведения об операционной системе

#### 1.2.1. Что такое операционная система

Операционная система (ОС) — это комплекс программ, которые загружаются при включении ПЭВМ. Они производят диалог с пользователем, осуществляют управление ПЭВМ, её ресурсами (оперативной памятью, местом на диске и т.д.), запускают другие программы на выполнение. Операционная система обеспечивает пользователю и программам удобный способ общения (интерфейс) с устройствами ПЭВМ.

Назначение операционной системы состоит прежде всего в том, чтобы предоставить пользователю удобный интерфейс для работы над файлами. Операционная система выполняет также вспомогательные действия, например, такие как копирование файлов. Кроме того, операционная система осуществляет загрузку в оперативную память программ, передаёт им управление для работы и освобождает занимаемую программами оперативную память при их завершении.

Компоненты ОС приведены в **приложении 1**.

### 1.3. Файлы на дисках

#### 1.3.1. Что такое файл

Информация на магнитных дисках хранится в файлах. Файл — это поименованная область на диске. В файлах могут храниться тексты программ, документы, готовые к выполнению программы и т.п.

Файлы располагаются в логических блоках. Логический блок в системе имеет фиксированный размер **512 (десятичное) байт**. Различают три основных формата данных:

- текстовый;
- объектный;
- отображения памяти.

Текстовые файлы предназначены для чтения человеком. Они состоят из строк символов, причём каждая строка оканчивается двумя специальными символами — «возврат каретки» (ВК) и «перевод строки» (ПС). При редактировании и просмотре текстовых файлов эти специальные символы, как правило, не видны. Файлы, не являющиеся текстовыми, называются двоичными.

Файлы объектного формата состоят из набора данных и машинных кодов. Они являются по существу объектными модулями, полученными в результате трансляции программ, написанных на языке Ассемблера.

Объектные файлы используются в качестве входных файлов для Редактора связей. Выходными файлами Редактора связей являются файлы формата отображения памяти.

Файл формата отображения памяти представляет собой точную копию содержимого памяти после его загрузки. Такой файл требует для своего размещения на диске столько же блоков, сколько он занимает в оперативной памяти.

#### 1.3.2. Имена и типы файлов

Обращение к файлу в операционной системе осуществляется по имени. Имя файла состоит из двух частей, разделённых точкой:

- собственно имени;
- типа файла.

Имя и тип файла представляют собой буквенно-цифровую последовательность, состоящую из символов латинского алфавита, кроме пробела и табуляции. Имя файла имеет длину от 1 до 6 символов, тип файла — до 3 символов. Тип файла не является обязательным. Тип файла обычно указывает его формат или содержимое. Пользователю рекомендуется согласовывать типы своих файлов со стандартными типами файлов операционной системы. Если для входного или выходного файла тип файла не указан, то большинство системных программ присваивает ему соответствующее стандартное значение типа файла.

## 2. Работа с операционной системой

### 2.1. Начальная загрузка ОС

Для загрузки операционной системы в оперативную память выполните следующие действия:

1. установите гибкий диск с ОС в привод;
2. подключите сетевые кабели ПЭВМ и видеомонитора к сети переменного тока напряжением 220 В;
3. установите тумблер включения, расположенный на задней панели ПЭВМ, в положение «включено»;
4. установите тумблер включения, расположенный на задней панели видеомонитора, в положение «включено».

Загружается операционная система. На экран выводится информация, отображающая процесс загрузки ОС. По окончании загрузки ОС выводится:

```
ОСА  Версия 1.0

.SET TT QUIET
дата (дд-мм-гг)?
```

Вводится текущая дата (если необходимо) и имя стартового файла. После этого система выдаёт системную дату, имя тома и владельца диска (если они есть) и **точку** в левой части экрана.

Это означает, что операционная система готова к приёму команд.

Состав носителя ОС приведён в приложении 2.

### 2.2. Диалог пользователя с операционной системой

Когда ОС готова к диалогу с пользователем, она выдаёт на экран приглашение (точку):

```
.
```

Диалог пользователя с ОС осуществляется в форме команд. Каждая команда означает, что ОС должна выполнить то или иное действие, например, напечатать файл или выдать на экран справочник.

Команда ОС состоит из имени команды и, возможно, переключателей и параметров. Имя команды ОС и параметры могут набираться как прописными, так и строчными латинскими буквами. Ввод каждой команды заканчивается нажатием клавиши `<ВК>`.

### 2.3. Обзор команд ОС

Команды ОС — это средство связи пользователя с операционной системой. Команды позволяют управлять работой операционной системы: получать справочную информацию о системе, загружать в оперативную память системные программы на выполнение, назначать физическим устройствам логические имена, выводить на периферийные устройства содержимое одного или нескольких файлов и выполнять ряд других функций.

Ниже приводятся краткие сведения о командах системы — названия и описания назначения команд.

| Команда | Назначение |
|---------|-----------|
| `ASSIGN`     | Назначает логическое имя физическому устройству |
| `BOOT`       | Загружает монитор операционной системы |
| `COPY`       | Выполняет операцию копирования |
| `DATE`       | Установить или распечатать текущую дату |
| `DEASSIGN`   | Отменяет логические имена устройств |
| `DELETE`     | Удаляет файлы с диска |
| `DIRECTORY`  | Выдаёт справочную информацию об устройстве |
| `HELP`       | Выдаёт справочную информацию о командах |
| `INITIALIZE` | Используется для очистки и инициализации справочника тома |
| `INSTALL`    | Указанное устройство добавляется в систему |
| `PRINT`      | Выводит на печать один или более файлов |
| `PROTECT`    | Устанавливает файлу защиту от удаления |
| `R`          | Загружает и запускает файл в формате отображения памяти |
| `REMOVE`     | Удаляет драйвер указанного устройства из системы |
| `RENAME`     | Переименовывает файл |
| `RESET`      | Восстанавливает системные таблицы и очищает память |
| `RUN`        | Загружает и запускает программу на выполнение |
| `SET`        | Позволяет изменить параметры конфигурации системы |
| `SHOW`       | Выдаёт информацию о системе |
| `SQUEEZE`    | Проводит операцию сжатия диска |
| `TYPE`       | Выводит содержимое файлов на терминал |
| `UNPROTECT`  | Отменяет защиту файла |

Приведённый выше перечень команд выводится на терминал по команде `HELP *`.

Цифровые аргументы, используемые в переключателях, система воспринимает как десятичные числа, если не оговорено особо. Такие величины, как адреса памяти, система интерпретирует как восьмеричные числа.

Не рекомендуется в строке команды указывать взаимоисключающие переключатели, например, такие как `PROTECT` и `UNPROTECT`.

Монитор допускает сокращение имён команд и переключателей. Простым и правильным для всех имён является их сокращение до 4‑х символов (до 6‑ти, если переключатель с префиксом `NO`).

Для более подробного ознакомления с действием конкретной команды и списком допустимых переключателей и аргументов для неё следует ввести с терминала команду `HELP` с указанием интересующей команды: `HELP <команда>`.

**Пример.**

```
. HELP SQUEEZE
```

На терминал выводится:

```
SQUEEZE          Проводит операцию сжатия диска

SQUEEZE[/прк]/УСТ

При выполнении операции сжатия система передвигает все
файлы тома к началу, получая одну неиспользованную
область после всех файлов.

Переключатели:
OUTPUT/УСТ   — Сжимает диск на другой диск, где УСТ —
               устройство вывода
QUERY        — Опрашивает пользователя, надо ли выполнять
               указанную операцию
NOQUERY      — Запрещает печать на терминале опрашивающих
               сообщений перед выполнением команды
WAIT         — Разрешает ожидание для продолжения работы

Пример
   SQUEEZE /WAIT DZ0:           Сжимает диск DZ0:
```

### 2.4. Формат команды

Команда операционной системы задаётся с терминала:

- в виде **полной строки**, содержащей достаточную информацию для выполнения указанной команды;
- в виде **краткой строки**. После ввода краткой строки на терминал выводится подсказка пользователю — какую информацию надо ввести.

**Общий формат полной строки:**

```
ком[/прк] вход.спе[/прк] выход.спе[/прк]
```

**Общий формат краткой строки:**

```
ком[/прк]
   подсказка1 ? вход.спе[/прк]
   подсказка2 ? выход.спе[/прк]
```

где `ком` — имя команды; `/прк` — один или несколько переключателей; `вход.спе` — спецификация входного файла; `выход.спе` — спецификация выходного файла; `подсказка1`, `подсказка2` — текст системы пользователю с указанием, какую информацию должен ввести пользователь. Выводится, если в команде опущена спецификация входного или выходного файла либо их устройства.

Спецификация файла имеет формат:

```
уст:имяф.тип
```

где `уст:` — логическое или физическое имя устройства; `имяф.тип` — имя и тип файла.

В строке команды допускается указывать до **шести** входных и до **трёх** выходных файлов. Если команда не помещается на одной строке, с помощью символа `–` можно продолжить её на следующую строку. Количество символов в строке команды не должно превышать **80**. Строка команды должна оканчиваться возвратом каретки.

В строке команды допустимо использовать круглые скобки для краткой записи нескольких спецификаций файлов.

**Примеры:**

```
1) DZ0:(TEST.LBT, TESTA.LST, TESTB.LST)
```

Система интерпретирует такую запись спецификаций как:

```
DZ0:TEST.LBT, DZ0:TESTA.LST, DZ0:TESTB.LST
```

```
2) DZ0:FIL(1,2,3).SYS
```

Эта запись эквивалентна следующей:

```
DZ0:FIL1.SYS, DZ0:FIL2.SYS, DZ0:FIL3.SYS
```

**Примечание.** Существует ограничение при использовании круглых скобок: количество символов полной строки команды после раскрытия круглых скобок не должно превышать 80. Поэтому, если используются имена файлов из шести букв, допустимо указывать не более 5 файлов в строке команды.

### 2.5. Использование в командах конструкций \* и %

Система допускает использование «звёздочек» (`*`) и «процентов» (`%`) вместо имени файла, типа файла или в качестве одного из символов имени файла или типа файла (так называемые встроенные конструкции).

1. **Символ `*` используется вместо имени файла.** Если в команде спецификация файла имеет вид `*.MAC`, то в указанной операции будут использоваться все файлы тома `DZ0` с типом `.MAC`, независимо от имени файла.

*Пример.* Если в строке команды спецификация файла имеет вид `TEST.*`, то в указанной операции будут использоваться все файлы тома `DZ0` с любым типом и именем `TEST`.

2. **Символ `*` используется в качестве имени и типа файла.** Если спецификация файла имеет вид `*.*`, то в указанной операции будут использоваться все файлы тома `DZ0` независимо от имени и типа файла.

3. **Символ `*` используется вместо нескольких символов имени или типа файла.** Если в команде спецификация файла имеет вид `A*B.MAC`, то в указанной операции будут использоваться все файлы тома `DZ0` с типом `.MAC`, у которых имя начинается буквой `A` и оканчивается буквой `B`.

4. **Символ `%` всегда подразумевает один символ имени или типа файла.** Если спецификация входного файла имеет вид `A%.MAC`, то в указанной операции будут использоваться все файлы тома `DZ0` с типом `.MAC`, длина имени у которых **два символа**, при этом первая буква имени файла — `A`, а вторая — любая.

**ТАБЛИЦА 2.1**

| Имя команды | `*`/`%` во входной спецификации | `*`/`%` в выходной спецификации |

| `DIRECTORY`  | × |   |

### 2.6. Редактирование командной строки

Не используя Редактор командной строки (SL), пользователь может изменить введённую строку двумя способами:

- удалить символы слева от курсора с помощью клавиши `<ЗБ>`;
- удалить всю напечатанную строку по `СУ/U` и повторно ввести строку.

Указатель текущего положения — **курсор** (далее в тексте — курсор) размещается в строке на символе, помеченном знаком (в настоящем документе курсор обозначается как `_`).

С помощью SL можно редактировать строку, перемещая курсор по различным позициям, удаляя или вставляя символы. SL доступен для команд системы и для программ пользователя. Для устройства печати SL недоступен.

Если SL не установлен в системе, следует подать команду:

```
INSTALL SL
```

Если после этой команды было сообщение об ошибке, следует подать:

```
SET SL SYSGEN
INSTALL SL
```

чтобы параметр драйвера SL соответствовал текущему монитору.

Если SL установлен в системе, разрешите его использование командой:

```
SET SL ON
```

По окончании работы с SL подайте:

```
SET SL OFF
```

Чтобы при ответе на подсказки системных программ пользователь не мог использовать SL, следует подать команду:

```
SET SL TTYIN
```

Ниже описаны действия служебных клавиш и их комбинаций при работе с SL. Ограничители в командах обозначены `<ВК>`.

**ТАБЛИЦА 2.3 — Действия служебных клавиш и их комбинаций**

| Клавиша / комбинация | Действие |
|----------------------|----------|
| `<ПФ1>` | Используется в комбинации с любой клавишей для многократного повторения её действия |
| `<ПФ2>` | Используется для получения вспомогательной информации после звукового сигнала |
| `← (стрелка влево)` | Перемещает курсор на одну позицию влево |
| `→ (стрелка вправо)` | Перемещает курсор на одну позицию вправо |
| `<ПФ1> ←` | Перемещает курсор в начало строки |
| `<ПФ1> →` | Перемещает курсор в конец строки |
| `↑ (стрелка вверх)` | Воспроизводит на терминале последнюю строку, завершённую возвратом каретки |
| `<ПФ3>` | Удаляет часть строки от курсора до конца строки |
| `<ПФ1> <ПФ3>` | Восстанавливает последнюю удалённую строку |
| `<ЗБ>` | Удаляет символ слева от курсора |
| `<ПФ1> <ЗБ>` | Восстанавливает последний удалённый символ |
| `<ВШ>` | Меняет местами символ, помеченный курсором, и символ справа от курсора |
| `<ПФ1> <ВШ>` | Меняет местами символ, помеченный курсором, и символ слева от курсора |
| `СУ/U` | Удаляет левую часть строки между точкой ввода и курсором |
| `<ПФ1> СУ/U` | Восстанавливает удалённую часть строки |
| `СУ/R` | Воспроизводит на терминале текущую строку |
| `СУ/W` | То же, что и `СУ/R` |
| `<ПФ1> <ВК>` | Удаляет правую часть строки от курсора до последнего символа строки и выполняет команду |
| `<ВК>` | Выполняет команду |

#### 2.6.1. Действие клавиши `<ПФ1>`

Клавиша `<ПФ1>` используется только в комбинации с другими клавишами для усиления функции.

Если нажать какую-либо клавишу без предварительного нажатия клавиши `<ПФ1>`, выполняется обычная функция нажатой клавиши.

Если же нажать клавишу `<ПФ1>` и затем клавишу, действие клавиши будет выполняться многократно. Например, если нажать клавишу `<стрелка влево>`, курсор передвигается на одну позицию влево. Если же нажать `<ПФ1>` и `<стрелка влево>`, курсор передвигается в начало строки.

#### 2.6.2. Действие клавиши `<ПФ2>`

Клавиша `<ПФ2>` используется для получения информации после звукового сигнала. Если нажать клавишу `<ПФ2>`, SL выводит сообщение о последней ошибке. Для возврата к нормальному экрану и выполнения функций SL следует нажать любую клавишу, кроме клавиши `<ПФ2>`.

#### 2.6.3. Перемещение курсора

Клавиша `<стрелка влево>` используется для перемещения курсора на один или более знаков влево, `<стрелка вправо>` — вправо.

Клавиши `<ПФ1>` и `<стрелка влево>` используются для перемещения курсора в начало строки, `<ПФ1>` и `<стрелка вправо>` — в конец строки.

**Примеры:**

1. `COPY DZ0:A.MAC VM:B.MSG_` — два последовательных нажатия клавиши `<стрелка влево>` перемещают курсор на две позиции влево.
2. `DELETE DZ0:FILE.TXT_` — после нажатия 4 раза клавиши `<стрелка вправо>` курсор перемещается на 4 позиции вправо.
3. `RENAME DZ0:A.TXT VM:B.TXT_` — после нажатия клавиш `<ПФ1>` и `<стрелка влево>` курсор перемещается в начало строки.
4. `COPY FIL1.MAC, FIL2.MAC, FIL3.MAC FILES.MAC_` — после нажатия клавиш `<ПФ1>` и `<стрелка вправо>` курсор перемещается в конец строки.

#### 2.6.4. Действие клавиши «стрелка вверх»

Клавиша `<стрелка вверх>` используется в ответ на точку монитора или системной программы для воспроизведения на терминале последней введённой строки, завершённой `<ВК>`.

Пустая строка (состоящая только из `<ВК>`) не считается последней строкой.

Воспроизведённую строку можно отредактировать и выполнить введённую команду. Курсор располагается в конце воспроизведённой строки.

**Пример.**

```
.LINK RTN1, RTN2, RTN3, RTN4, PROGM/EXECUTE/MAP_
```

После нажатия клавиши `<стрелка вверх>` на терминал выводится:

```
.LINK RTN1, RTN2, RTN3, RTN4, PROGM/EXECUTE/MAP_
```

#### 2.6.5. Действие клавиши `<ПФ3>`

Клавиша `<ПФ3>` стирает часть строки от курсора до конца строки.

**Пример.**

```
RENAME FIL1.MAC FIL2.MAC VM:MYFILE.MAC
```

После нажатия клавиши `<ПФ3>` строка имеет вид:

```
RENAME FIL1.MAC FIL2.MAC
```

#### 2.6.6. Действие клавиш `<ПФ1>` и `<ПФ3>` (или `<ПФ1>` и `СУ/U`)

Комбинации `<ПФ1> <ПФ3>` (или `<ПФ1> СУ/U`) восстанавливают только что удалённые символы строки.

**Пример.** Если строка имеет вид `RENAME FIL1.MAC FIL2.MAC`, то после нажатия `<ПФ1> <ПФ3>` строка принимает прежний вид (какой был до нажатия `<ПФ3>`): `RENAME FIL1.MAC FIL2.MAC VM:MYFILE.MAC`.

#### 2.6.7. Действие клавиши `<ЗБ>`

Клавиша `<ЗБ>` удаляет символ слева от курсора.

**Пример.** После нажатия клавиши `<ЗБ>` в строке `COPY A.MAC B.MAC_` получаем: `COPY A.MAC B.MA_`.

Используя клавиши `<ПФ1>` и `<ЗБ>`, можно восстановить последний удалённый символ.

#### 2.6.8. Действие клавиши `<ВШ>`

Клавиша `<ВШ>` меняет местами символ, под которым находится курсор, и символ, стоящий справа от курсора. При этом курсор также перемещается на новую позицию.

**Пример.** Если строка имеет вид `COPY MYFIL1.SAV MYFIL2.SVA_`, то после нажатия клавиши `<ВШ>` получаем: `COPY MYFIL1.SAV MYFIL2.SAV`.

Последовательное нажатие клавиш `<ПФ1>` и `<ВШ>` меняет местами символ, помеченный курсором, и символ, стоящий слева от курсора.

#### 2.6.9. Действие функции `СУ/U`

Функция `СУ/U` удаляет все символы в строке слева от курсора.

**Пример.** Если строка имеет вид `RENAME DZ0:MAIN.MAC VM:SUB1.MAC`, то после нажатия `СУ/U` получаем: `:MAIN.MAC VM:SUB1.MAC`.

Для восстановления удалённых символов следует нажать клавиши `<ПФ1>` и `<СУ/U>`.

#### 2.6.10. Действие клавиш `<ПФ1>` и `<ВК>`

Последовательное нажатие клавиш `<ПФ1>` и `<ВК>` удаляет правую часть строки — от курсора до последнего символа строки — и выполняет команду.

**Пример.** Если строка имеет вид `COPY DZ0:*.MAC DZ0:*.BAC VM:FILES.BAK_`, то после нажатия `<ПФ1> <ВК>` строка принимает вид `COPY DZ0:*.MAC DZ0:*.BAC` и выполняется.

#### 2.6.11. Действие клавиши `<ВК>`

Клавиша `<ВК>` используется для выполнения строки независимо от положения курсора.

#### 2.6.12. Действие функций `СУ/R` и `СУ/W`

Функции `СУ/R` или `СУ/W` используются для воспроизведения на терминале текущей вводимой или последней введённой строки. Эти клавиши используются для проверки строки.

### 2.7. Копирование файлов

Копирование файлов на ПЭВМ «Электроника МС0515» в системе ОСА может быть осуществлено одним из двух способов:

1. непосредственно с диска на диск;
2. с использованием псевдодиска `VM:` в качестве промежуточного устройства.

При копировании первым способом могут быть указаны файлы любого размера, размещаемые на ПЭВМ. Однако такая операция занимает много времени, так как постоянно приходится менять диски.

Второй способ копирования значительно более быстрый. Однако он не подходит для файлов размером более **184 блоков** (максимальная свободная область на `VM:`).

Чтобы операция копирования осуществлялась с ожиданием подтверждения, используется ключ `COPY/WAIT` (режим копирования с ожиданием).

Возможными ответами на вопросы ПЭВМ при копировании файлов могут быть:

1. `Y` — подтверждение указанной операции;
2. `N` — отказ от указанной операции. Если в это время в приводе установлен системный том, на терминал выдаётся точка и ожидается ввод очередной команды монитора. Если установлен не системный том, последует требование установить системный том;
3. Символ, отличный от `Y` и `N`, — вопрос повторяется.

Ниже приводится описание каждого из этих способов.

#### 2.7.1. Копирование файлов без использования VM

Для непосредственного копирования файла с одного тома на другой необходимо выполнить следующие операции:

1. Подать команду копирования:

   ```
   COPY/WAIT DZ:<имяфайл.тип> DZ:
   ```

Ответ: `Установить входной том на DZ0:; Продолжить?`

2. Установить в привод входной том (т.е. том, с которого копируется файл) и ввести `Y`.

Ответ: `Установить выходной том на DZ0:; Продолжить?`

3. Установить в привод выходной том (т.е. том, на который копируется файл) и ввести `Y`. Осуществляется копирование очередной «порции» файла.

4. Если копировалась не последняя «порция» файла, ОС выдаёт: `Установить входной том на DZ0:; Продолжить?` — повторяйте работу, начиная с шага 2.

5. Если файл скопирован полностью, ОС выдаёт:

   ```
   DZ0:<имяфайл.тип> на DZ0:<имяфайл.тип>
   Установить системный том на DZ0:; Продолжить?
   ```

Установить в привод системный том и ввести `Y`. Система отвечает точкой и ожидает ввода следующей команды.

**Примечания:**

1. Для копирования системных файлов (типа `.SYS`, `.BUP`) необходимо в командах копирования указать соответствующий переключатель (более подробную информацию о команде `COPY` даёт команда `HELP COPY`).
2. Для выборочного копирования объектных файлов с одного тома на другой можно воспользоваться командой `COPY/QUERY/WAIT DZ: DZ:`.

#### 2.7.2. Копирование файлов с использованием VM

Копирование файлов с использованием `VM:` осуществляется в два этапа: с входного тома на `VM:` и с `VM:` на выходной том.

Для копирования файла с тома на `VM:` необходимо:

1. Инициализировать `VM:` командой:

   ```
   INITIALIZE/NOQUERY VM:    или    INI/NOQ VM:
   ```

2. Подать команду копирования:

   ```
   COPY/WAIT DZ:<имяфайл.тип> VM:
   ```

Ответ: `Установить входной том на DZ0:; Продолжить?`

3. Установить в привод входной том и ввести `Y`.

Ответ: `Установить выходной том на VM:; Продолжить?`

4. Ввести `Y`. Осуществляется копирование указанного файла на `VM:`.

По окончании копирования выдаётся:

```
DZ0:<имяфайл.тип> на VM:
Установить системный том на DZ0:; Продолжить?
```

5. Установить в привод системный том и ввести `Y`.

Для копирования файла с `VM:` на том необходимо:

1. Подать команду:

   ```
   COPY/WAIT VM:<имяфайл.тип> DZ:
   ```

Ответ: `Установить входной том на VM:; Продолжить?`

2. Ввести `Y`.

Ответ: `Установить выходной том на DZ0:; Продолжить?`

3. Установить в привод выходной том и ввести `Y`. По окончании копирования выдаётся:

   ```
   VM:<имяфайл.тип> на DZ0:
   Установить системный том на DZ0:; Продолжить?
   ```

4. Установить в привод системный том и ввести `Y`.

#### 2.7.3. Копирование системных дисков и получение рабочих систем

Для копирования системных томов используются заранее инициализированные гибкие диски, абсолютно без дефектных блоков. Диски с дефектными блоками в системной (начальной) области непригодны. Инициализация и проверка дисков на дефектные блоки описана в п. 2.7.4.

Для копирования одного системного тома на другой используется команда:

```
COPY/SYSTEM/WAIT DZ0:  DZ0:
```

Весь диалог с системой описан в п. 2.7.1.

По завершении копирования необходимо записать на диск-копию блоки начального загрузчика по команде:

```
COPY/BOOT/WAIT DZ0:MON8SJ DZ0:
```

(см. п. 2.7.1). Копирование системного тома завершено.

При создании рабочей системы, состав которой отличается от поставляемой, выполняются аналогичные действия. Различие лишь в том, что пользователь, осуществляющий выборочное копирование необходимых файлов с разных дисков, использует команду:

```
COPY/SYSTEM/WAIT/QUERY DZ0:  DZ0:
```

и затем записывает на диск-копию начальный загрузчик по команде `COPY/BOOT`.

**Примечание.** Минимальная работоспособная система должна содержать следующие файлы:

```
{ MON8SJ, SWAP, DZ, VM }.SYS,  { PIP, DUP, DIR }.SAV
```

Остальные файлы пользователь включает по своему усмотрению.

#### 2.7.4. Инициализация и проверка дисков на дефектные блоки

Для инициализации справочника гибкого диска необходимо подать команду:

```
INITIALIZE/NOQUERY/WAIT DZ:
```

Ответ: `Установить входной том на DZ:; Продолжить?`

Установить требуемый диск и ввести `Y`. Выполняется инициализация диска, затем выдаётся: `Установить системный том на DZ0:; Продолжить?` — установить системный том и ввести `Y`.

Для проверки диска на дефектные блоки необходимо подать команду:

```
DIRECTORY/BADBLOCKS/WAIT DZ:
```

или

```
DIRECTORY/BADBLOCKS/FILES/WAIT DZ:
```

Ответ: `Установить входной том на DZ:; Продолжить?` — установить проверяемый том в привод и ввести `Y`. По завершении сканирования диска выдаются результаты (сведения о количестве и расположении дефектных блоков), затем — `Установить системный том на DZ0:; Продолжить?`. Установить системный том и ввести `Y`.

Инициализацию и проверку на дефектные блоки можно выполнить одновременно командой `INITIALIZE/BADBLOCKS/NOQUERY`. Кроме того, эта команда позволяет локализовать дефектные блоки, если их немного и они расположены не в системной (начальной) области диска (см. `HELP INITIALIZE/BADBLOCKS`).

Диалог с системой тот же, что и для команд `INITIALIZE/NOQUERY` и `DIRECTORY/BADBLOCKS`.

## 4. Программа форматирования текста

Программа форматирования текста предназначена для получения удобочитаемых текстов в форме, удобной для чтения, распечатки созданных или скорректированных файлов; формат исходного текста позволяет быстро вносить изменения средствами редактирования операционной системы.

### 4.1. Запуск программы

Перед загрузкой и запуском программы необходимо назначить физическому устройству, выбранному для вывода сформатированного текста (в дальнейшем — документа), логическое имя `DOC` командой `ASSIGN`.

Если назначение логического устройства не сделано, то вывод сформатированного текста осуществляется на устройство печати.

Например, для того, чтобы документ был выведен на диск `DZ0:`, нужна команда:

```
ASSIGN DZ0 DOC
```

Программа форматирования текста записана в файле `TFP.SAV`, который рекомендуется размещать на системном устройстве (`SY:`).

Если файл `TFP` находится на системном устройстве, то для загрузки и запуска программы достаточно команды:

```
R TFP
```

Если файл расположен на любом другом устройстве прямого доступа (`DEV:`), необходима команда:

```
RUN DEV:TFP
```

После загрузки и запуска программы на терминал выводится `*`, что означает готовность программы к форматированию очередного документа.

В ответ на `*` нужно указать спецификацию файла, в котором содержится исходный текст. Если в спецификации файла пользователь не указал тип файла или вводится пустая строка (клавиша `<ВК>`), то на терминал выводится версия программы:

```
RUN TFP/SK
?KSC
TFP B03.01
```

**Примечание.** Если в спецификации файла опущено имя устройства, то по умолчанию выбирается устройство `DZ0:`.

По окончании обработки текста файла программа выходит на терминал и ожидает имени очередного файла. Запуск программы и задание спецификации файла можно совместить в одной команде. Например:

```
RUN TFP DZ0:TEXT
```

В результате работы программы создаётся сформатированный текст документа, который размещается в файле `DOC<NAME>.DOC` (`<NAME>` — имя первого входного файла).

### 4.2. Команды

Исходный текст может состоять как из нескольких файлов, так и из одного текстового файла. Текстовая информация будет располагаться в файлах нескольких видов, определяемых директивами:

- форматирования текста;
- оформления страницы;
- описания структуры выводимого текста;
- служебных.

Программа форматирования текста позволяет выводить документы на стандартных листах.

#### 4.2.1. Синтаксис директив форматирования

Все директивы форматирования должны размещаться на отдельных строках, начиная с первой печатной позиции строки. Директивы начинаются с точки (`.`) и имеют следующий формат:

```
.DIR ARG
```

где `.DIR` — идентификатор соответствующей директивы; `ARG` — аргумент директивы.

Аргумент директивы может быть целым десятичным числом, строкой текста или спецификацией файла. Некоторые директивы не требуют аргумента. Для большинства директив, требующих числовой аргумент, по умолчанию принимается значение `1`.

#### 4.2.2. Директивы форматирования текста

##### 4.2.2.1. Директива `.LIN`

Директива `.LIN` имеет числовой аргумент, который определяет количество пустых строк, пропускаемых перед началом следующего фрагмента текста. Под фрагментом понимается текст, расположенный между двумя директивами. Фрагмент, следующий за директивой `.LIN`, выводится **с красной строки**.

Если директива `.LIN` попадает на начало страницы, пропуск строк не выполняется.

При выводе строки выравниваются по длине, дополняясь пробелами между словами. Перенос слов в исходном тексте не рекомендуется.

##### 4.2.2.2. Директива `.BLN`

Директива `.BLN` аналогична `.LIN`. В отличие от `.LIN` вывод фрагмента начинается **с начала строки** (без красной строки).

##### 4.2.2.3. Директива `.SKI`

Директива `.SKI` аналогична `.BLN`. В отличие от `.BLN` пропуск строк производится, даже если следующий фрагмент попадает на начало страницы. Если на текущей странице остаётся строк меньше, чем требует аргумент, предварительно производится переход на новую страницу.

##### 4.2.2.4. Директива `.INT`

Директива `.INT` используется для вывода сформатированного текста с указанным интервалом. Директива имеет числовой аргумент, который определяет количество пустых строк, пропускаемых перед выводом очередной строки.

##### 4.2.2.5. Директива `.SWT`

Директива `.SWT` используется для вывода следующего фрагмента текста без форматирования, включая пустые строки. Числовой аргумент интерпретируется как и в директивах `.BLN` или `.LIN`. Строки следующего фрагмента должны иметь длину, не превышающую одной колонки. В фрагменте, следующем за `.SWT`, использование знаков табуляции недопустимо.

##### 4.2.2.6. Директива `.NOF`

Действие директивы `.NOF` аналогично действию `.SWT` без ограничения на длину строки. Директива `.NOF` используется без аргумента.

**Примечание.** Требуемая длина строки устанавливается монитором командами `SET TT: WIDTH=N` или `SET LP: WIDTH=N` (соответственно для терминала или устройства печати; `N` — длина строки). Длина любой строки исходного текста не должна превышать **126 знаков**.

##### 4.2.2.7. Директива `.MID`

Директива `.MID` используется для вывода текстового аргумента. Строка-аргумент выводится по центру страницы.

##### 4.2.2.8. Директива `.RIT`

Директива `.RIT` используется для вывода текстового аргумента. Строка-аргумент выравнивается по правой границе страницы.

#### 4.2.3. Директивы оформления страниц

Программа форматирования текста автоматически формирует страницы выводимого документа. В оформление страниц документа входят:

- нумерация страниц;
- обозначение документа;
- сформатированный текст документа.

Нумерация страниц осуществляется арабскими цифрами. Номер страницы выводится по центру первой (или единственной) строки. Наличие и содержание обозначения определяются пользователем.

##### 4.2.3.1. Директива `.STL`

Аргумент директивы `.STL` — текстовая строка, используемая в качестве обозначения или наименования документа. Для использования обозначения документа при форматировании титульного листа необходимо, чтобы директиве `.STL` предшествовала директива `.TIT` (п. 4.2.4.1) в тексте исходного документа.

Действие директивы `.STL` может быть отменено только другой директивой `.STL`.

**Примечание.** Чтобы отказаться от вывода обозначения документа, достаточно использовать директиву `.STL` без аргумента.

##### 4.2.3.2. Директива `.PAG`

По директиве `.PAG` производится переход на новую страницу документа. Переход не производится, если директива обрабатывается в начале страницы.

##### 4.2.3.3. Директива `.TES`

По директиве `.TES` производится переход на новую страницу документа, если на текущей странице осталось строк меньше, чем задано числовым аргументом директивы.

#### 4.2.4. Директивы описания структуры документа

Для описания структуры документа используется следующий набор директив:

- титульный лист;
- аннотация;
- содержание;
- разделы и подразделы;
- пункты и подпункты;
- перечисления;
- примечания;
- приложения.

Приложения могут содержать разделы, подразделы и т.п. Использование директив описания структуры облегчает формирование заголовков и обеспечивает автоматический сбор содержания и нумерации разделов, подразделов, пунктов, подпунктов и приложений.

##### 4.2.4.1. Директива `.TIT`

Директива `.TIT` формирует титульный лист документа на четырёх следующих за ней строках. В качестве 4-й строки рекомендуется указывать год издания документа.

##### 4.2.4.2. Директива `.TOC`

Директива `.TOC` используется для указания необходимости сбора содержания. Если необходим сбор содержания, директива `.TOC` должна быть первой в исходном тексте.

При сборе содержания программа форматирования текста выполняет два прохода (просмотра) исходного текста. На первом проходе осуществляется сбор содержания, а на втором — вывод документа и содержания.

В конце первого прохода на терминал выводится сообщение о завершении первого прохода и количестве страниц, которые будет содержать сформатированный документ.

##### 4.2.4.3. Директива `.ANN`

Директива `.ANN` определяет начало аннотации к документу. Фрагменты текста, следующие за директивой (и разделяемые, если надо, директивами форматирования текста), включаются в аннотацию. Ограничителем аннотации является начало одного из разделов, подразделов, пунктов, подпунктов или приложений.

**Примечание.** В аннотации допустимо использование перечислений и примечаний.

##### 4.2.4.4. Директива `.APN`

Директива `.APN` используется для вывода приложения, текстовый аргумент является заголовком приложения. Приложения начинаются с новой страницы.

##### 4.2.4.5. Директива `.CPT`

Директива `.CPT` используется для вывода раздела. Директива `.CPT` аналогична `.APN`.

##### 4.2.4.6. Директива `.HLV`

Директива `.HLV` используется для определения начала подраздела, пункта или подпункта. Интерпретация директивы определяется числовым аргументом (`1` — подраздел, `2` — пункт, `3` — подпункт). Фрагмент текста, следующий за директивой, используется как заголовок.

**Примечание.** Заголовок форматируется аналогично текстовой информации, но не больше длины выходной строки.

Если непосредственно за директивой `.HLV` указать одну из директив `.LIN`, `.BLN`, то форматирование заголовка не производится; в начале выходного фрагмента текста будет проставлена соответствующая нумерация. Содержание номера определяется аналогично нумерации заголовков.

##### 4.2.4.7. Директива `.AND`

Директива `.AND` определяет начало фрагмента текста, который используется как элемент перечисления. Числовой аргумент указывает количество пустых строк перед началом данного элемента перечисления.

Элемент перечисления при выводе дополняется знаком «–» и форматируется аналогично текстовой информации.

##### 4.2.4.8. Директива `.TBL`

Директива `.TBL` является комбинацией директив `.SWT` и `.AND 0` и позволяет заменить последовательность:

```
.SWT
строка
.AND 0
строка
```

на более короткую:

```
.TBL строка
```

##### 4.2.4.9. Директива `.ATT`

Директива `.ATT` определяет начало фрагмента текста примечания. Числовой аргумент не используется. Форматирование производится аналогично текстовой информации.

**Примечание.** В документе тексту примечания предшествует слово «Примечание».

##### 4.2.4.10. Директива `.LST`

Директива `.LST` осуществляет вывод перечня, используя текстовый аргумент как заголовок.

#### 4.2.5. Служебные директивы

##### 4.2.5.1. Директива `.COM`

Директива `.COM` предназначена для внесения комментариев в исходный текст. Строки-аргументы директивы не выводятся в формируемый документ; они выводятся на терминал.

Директива:

```
.COM текст
```

приведёт к выводу на терминал:

```
?TFP-I- текст
```

##### 4.2.5.2. Директива `.CHA`

Аргументом директивы `.CHA` является спецификация файла (см. п. 2.4), в котором находится продолжение исходного текста документа.

По этой директиве обработка текущего файла прекращается и начинается обработка указанного файла. Это даёт возможность размещать исходный текст в нескольких файлах, расположенных, возможно, на различных томах. Длина «цепочки» файлов логически не ограничена.

**Примечание.** Если в спецификации файла отсутствует указание устройства, то по умолчанию выбирается устройство, на котором размещён первый файл выводимого документа.

##### 4.2.5.3. Директива `.CPY`

Аргументом директивы `.CPY` является спецификация файла (см. п. 2.4). Текст, содержащийся в указанном файле, будет включён в формируемый документ.

По директиве `.CPY` обработка текущего файла приостанавливается и начинается обработка указанного файла. По завершении обработки этого файла программа возобновляет обработку первоначального файла со строки, следующей за `.CPY`. Во вторичном файле использование директивы `.CPY` запрещено.

**Примечание.** Если в спецификации файла отсутствует указание устройства, то по умолчанию выбирается устройство, на котором размещён первый файл выводимого документа.

### 4.3. Пример исходного текста документа

В качестве примера приводится начало исходного текста данного документа.

```
.TOC
.COM ПРОГРАММА ФОРМАТИРОВАНИЯ ТЕКСТОВ
.TIT
ОПЕРАЦИОННАЯ СИСТЕМА ОСА
ПРОГРАММА ФОРМАТИРОВАНИЯ ТЕКСТОВ

1991
.PAG
.CPT ПРОГРАММА ФОРМАТИРОВАНИЯ ТЕКСТА
Программа форматирования текста предназначена для получения
текстов в форме, удобной для чтения,
распечатки созданных или сформированных файлов. Формат
исходного текста позволяет быстро вносить изменения
средствами редактирования операционной системы.
.HLV 1 Запуск программы
.LIN
Перед загрузкой и запуском программы необходимо назначить
физическому устройству, выбранному для
вывода сформатированного текста (в дальнейшем
"DOC") командой ASSIGN.
.LIN
Если назначение логического устройства не сделано,
то вывод сформатированного текста осуществляется
на устройство печати.
.LIN
Например, для того, чтобы документ был выведен на диск DZ0,
нужна команда:
.SWT

   ASSIGN DZ0 DOC
.LIN
Программа форматирования текста записана в файле
"TFP.SAV",
который рекомендуется размещать на системном
устройстве (SY).
.LIN
Если файл TFP находится на системном устройстве, то
для загрузки и запуска программы достаточно команды:
.SWT
   R TFP
.LIN
Если файл расположен на любом другом устройстве
прямого доступа (DEV), необходима команда:
.SWT
   RUN DEV:TFP
.LIN
После загрузки и запуска программы на терминал
выводится "*",
что означает готовность программы к форматированию очередного
документа.
```

## 5. Сообщения

### 5.1. Сообщения операционной системы ОСА

Ниже приведены сообщения, выдаваемые операционной системой ОСА.

В сообщениях в угловых скобках указывается информация, которая заменяется при выводе сообщения конкретным значением:

```
имяф.тип  — имя и тип файла
спе       — спецификация файла (уст:имяф.тип)
адр       — адрес
NNNNNN    — число
```

#### Сообщения подсистемы BOOT

- **`?BOOT-F-Нет начального загрузчика на томе`** — на томе отсутствует начальный загрузчик. *Действие:* использовать команду монитора `COPY/BOOT` для записи начального загрузчика на том.

- **`?BOOT-U-Несоответствие вариантов генерации`** — используются несоответствующие варианты генерации драйвера устройства и монитора. Выполнение завершается. *Действие:* проверить соответствие вариантов генерации.

- **`?BOOT-U-Нет драйвера`** — не найден драйвер системного устройства во время загрузки монитора. Выполнение завершается. *Действие:* скопировать драйвер (`XX.SYS`) на системный том и вновь повторить операцию загрузки.

- **`?BOOT-U-Недостаточно памяти`** — объём оперативной памяти не позволяет разместить загружаемый монитор. *Действие:* использовать команду монитора `COPY/BOOT` для записи начального загрузчика на системный том. Проверить наличие памяти на устройстве для размещения монитора.

- **`?BOOT-U-Ошибка В/В`** — ошибка ввода-вывода во время загрузки системы; на системном томе отсутствует начальный загрузчик. *Действие:* использовать команду `COPY/BOOT/UST` для записи начального загрузчика на системный том. Если ошибка повторяется, проверить готовность и исправность оборудования.

- **`?BOOT-U-Нет монитора`** — на системном томе нет монитора с соответствующим данному загрузчику именем. *Действие:* проверить правильность выбора системного тома.

- **`?BOOT-U-Файл свопинга слишком мал`** — размер файла `SWAP.SYS` меньше 26 (десятичных) блоков. *Действие:* скопировать файл `SWAP.SYS` с другого системного тома.

- **`?BOOT-U-Нет SWAP.SYS`** — на загружаемом томе отсутствует файл `SWAP.SYS`. *Действие:* скопировать файл `SWAP.SYS` на системный том. Вновь загрузить систему.

- **`?BOOT-U-Ошибка чтения драйвера`** — аппаратная ошибка чтения драйвера. Драйвер содержит дефектные блоки. *Действие:* проверить готовность и исправность оборудования.

- **`?BOOT-W-TT.SYS нет или недоступен`** — драйвер `TT.SYS` отсутствует на системном томе во время загрузки монитора либо вариант генерации `TT:` не соответствует варианту генерации монитора. *Действие:* записать файл `TT.SYS` на системный том и вновь запустить систему или установить `TT:`. Проверить соответствие вариантов генерации драйвера `TT` и монитора.

#### Сообщения CSI

- **`?CSI-F-Том полон`** — на указанном устройстве нет места для размещения выходного файла, созданного программой пользователя с помощью запроса `.CSIGEN`. *Действие:* увеличить размер свободной области на томе (удалить ненужные файлы; сжать том командой `SQUEEZE`; указать размер выходного файла в команде).

- **`?CSI-F-Файл не найден`** — не найден входной файл, описанный программой пользователя по запросу `.CSIGEN`. *Действие:* проверить поданную команду.

- **`?CSI-F-Недопустимая команда`** — не указано имя выходного файла; длина командной строки превышает 80 символов или командная строка содержит недопустимые символы (например, пробелы); число файлов, указанных в команде, превышает допустимое; длина входной строки в запросе `.STLIN` превышает 88 символов. Сообщение выдаётся, если программа пользователя использовала запрос `.CSIGEN` или `.CSISPC`. *Действие:* проверить поданную команду; убедиться, что длина входной строки в запросе `.STLIN` не превышает 88 символов.

- **`?CSI-F-Недопустимое устройство`** — устройство, указанное в программе пользователя по запросу `.CSIGEN`, не существует, или в системе не установлено обслуживание этого устройства, или отсутствует драйвер устройства. Также — попытка ввести команду `DIRECTORY`, когда `TT.SYS` отсутствует на системном устройстве. *Действие:* проверить поданную команду; скопировать требуемый драйвер на системный том и вновь загрузить систему.

- **`?CSI-F-Файл защищён`** — файл, указанный в программе пользователя по запросу `.CSIGEN`, уже существует и защищён. *Действие:* использовать другое имя для нового файла либо удалить, переименовать или снять защиту существующего файла командой `UNPROTECT`.

#### Сообщения DIR

- **`?DIR-F-Устройство не активно`** — операция ввода-вывода невозможна на указанном устройстве; либо устройство отключено, либо не описано в таблице устройств. *Действие:* проверить правильность включения устройства; установить обслуживание устройства командой `INSTALL`.

- **`?DIR-F-Ошибка чтения справочника`** — ошибка чтения справочника тома. *Действие:* проверить исправность аппаратуры; проверить том на дефектные блоки.

- **`?DIR-F-Файл создан; защищённый файл уже существует <спе>`** — создан незащищённый файл; защищённый файл с тем же именем уже существует. *Действие:* просмотреть листинг справочника без переключателей; удалить или переименовать незащищённый файл, если его имя в справочнике предшествует имени защищённого; либо переименовать или изменить код защиты защищённого файла командой `UNPROTECT`.

- **`?DIR-F-Ошибка входного файла <спе>`** — произошла аппаратная ошибка при чтении входного файла. *Действие:* проверить исправность аппаратуры; проверить том на дефектные блоки.

- **`?DIR-F-Недостаточно памяти`** — недостаточно памяти для получения упорядоченного справочника. *Действие:* использовать драйвер свопинга.

- **`?DIR-F-Недопустимая команда`** — в командной строке обнаружена ошибка. *Действие:* ввести правильную командную строку.

- **`?DIR-F-Недопустимое устройство <уст>`** — операция недопустима на указанном устройстве; устройство недопустимо (например, `TT:`) или в системе не установлено обслуживание указанного устройства. *Действие:* проверить введённую командную строку; использовать `SHOW` для получения списка устройств.

- **`?DIR-F-Недопустимый справочник`** — структура справочника тома устройства не является структурой данной операционной системы. *Действие:* не требуется.

- **`?DIR-F-Недопустимый переключатель /X`** — в командной строке обнаружен недопустимый переключатель. *Действие:* ввести правильную командную строку.

- **`?DIR-F-Ошибка выходного файла <спе>`** — произошла аппаратная ошибка во время записи выходного файла. *Действие:* см. `?DIR-F-Ошибка входного файла <спе>`.

- **`?DIR-F-Выходной файл заполнен`** — выходной файл заполнен; на томе нет места для файла справочника. *Действие:* вывести справочник на устройство печати; указать в команде размер выходного файла.

- **`?DIR-F-Заменяемый файл уже существует <спе>`** — попытка создания заменяемого файла, у которого такое же имя, как у существующего защищённого файла. *Действие:* использовать команду `RENAME/NOPROTECT` для снятия защиты существующего файла или использовать другое имя.

- **`?DIR-F-Недопустимая версия монитора`** — попытка обращения операционной системы к программе `DIR`, не принадлежащей данной операционной системе. *Действие:* использовать программу `DIR` данной операционной системы.

#### Сообщения DUP

- **`?DUP-F-Операция не завершена`** — при использовании переключателя `/WAIT` в ответ на запрос напечатано `N` или нажато `СУ/С`. *Действие:* повторить команду; для выполнения операции нажать `Y`.

- **`?DUP-F-Дефектный блок в системной области <уст>`** — дефектные блоки в системной области диска. *Действие:* сжать диск командой `SQUEEZE`; если ошибка повторяется, заменить диск.

- **`?DUP-F-Канал занят <спе>`** — ошибка при обращении к программе `DUP`. *Действие:* перезагрузить систему и повторить операцию; если ошибка повторяется, создать новую копию `DUP.SAV` и повторить операцию.

- **`?DUP-F-Канал не открыт <спе>`** — см. `?DUP-F-Канал занят`.

- **`?DUP-F-Взаимоисключающие варианты SYSGEN`** — несоответствие вариантов генерации драйвера и монитора. *Действие:* проверить варианты генерации.

- **`?DUP-F-Том полон <спе>`** — недостаточно места на выходном томе для размещения указанного файла или данных. *Действие:* использовать `SQUEEZE` для объединения неиспользуемых областей, либо использовать другой том.

- **`?DUP-F-Справочник полон <спе>`** — нет места в справочнике выходного тома для создания файла. *Действие:* использовать `SQUEEZE` или другой том.

- **`?DUP-F-Ошибка чтения справочника <уст>`** — ошибка чтения справочника входного устройства. *Действие:* проверить исправность аппаратуры; проверить том на дефектные блоки; повторить операцию; если ошибка повторяется, заменить том.

- **`?DUP-F-Ошибка записи в справочник <уст>`** — см. `?DUP-F-Ошибка чтения справочника <уст>`.

- **`?DUP-F-Сбой операционной системы <уст>`** — сбой в работе операционной системы. *Действие:* перезагрузить систему и повторить операцию; при повторении использовать новую копию `DUP.SAV` и драйвера устройства.

- **`?DUP-F-Файл не найден <спе>`** — указанный файл не найден. *Действие:* проверить командную строку; повторить операцию.

- **`?DUP-F-Ошибка чтения <спе>`** — аппаратная ошибка во время операции чтения. *Действие:* проверить аппаратуру; проверить диск на дефектные блоки.

- **`?DUP-F-Недостаточно памяти`** — недостаточно памяти под буферы для выполнения требуемой операции. *Действие:* удалить ненужные драйверы; разрешить свопинг командой `SET USR SWAP`.

- **`?MON-F-Файл защищён`** — файл уже существует и защищён. *Действие:* использовать другое имя или снять защиту командой `UNPROTECT`.

- **`?MON-F-Недопустимое устройство <уст>`** — устройство не обслуживается данной операционной системой.

- **`?MON-F-Файл не найден <спе>`** — входной файл не найден.

- **`?MON-F-Том полон`** — недостаточно места на выходном томе. *Действие:* увеличить свободную область; сжать том командой `SQUEEZE`; указать размер выходного файла.

- **`?MON-F-Недопустимая команда`** — *Действие:* ввести правильную командную строку.

#### Сообщения PIP

- **`?PIP-E-Операция не завершена`** — при использовании переключателя `/WAIT` в ответ на запрос введено `N` или нажато `СУ/С`. *Действие:* для продолжения нажать `Y` и `<ВК>`.

- **`?PIP-E-Существует защищённый файл <спе>`** — на выходном томе уже существует защищённый файл с указанным именем. *Действие:* использовать `UNPROTECT` для снятия защиты существующего файла или использовать другое имя.

- **`?PIP-F-Канал занят`** / **`?PIP-F-Канал не открыт`** — ошибка при обращении к программе `PIP`. *Действие:* перезагрузить систему; при повторении — новую копию `PIP.SAV`.

- **`?PIP-F-Ошибка КС <спе>`** — ошибка контрольной суммы во время копирования по команде `COPY/BINARY`. *Действие:* повторить операцию командой `COPY/IGNORE`.

- **`?PIP-F-Нет места для <спе>`** — на томе недостаточно места для размещения копируемого файла. *Действие:* `SQUEEZE`; указать размер выходного файла; использовать другой том.

- **`?PIP-F-Устройство занято`** — требуемое устройство используется другим заданием.

- **`?PIP-F-Заполнен <уст>`** — в справочнике выходного тома нет места для записи выходного файла. *Действие:* `SQUEEZE` или другой том.

- **`?PIP-F-Ошибка чтения <уст>`** — аппаратная ошибка при чтении справочника.

- **`?PIP-F-Ошибка в/в на <уст>`** — нарушена структура справочника на томе. *Действие:* `DIRECTORY/BADBLOCKS`. Если на томе много дефектных блоков или они в зоне справочника — том непригоден для работы.

- **`?PIP-F-Ошибка обращения к программе PIP`** — см. `?PIP-F-Канал занят`.

- **`?PIP-F-Нет файла <спе>`** — указанный входной файл не найден или нет файлов с указанной датой создания. *Действие:* проверить командную строку.

- **`?PIP-F-Ошибка чтения <спе>`** — аппаратная ошибка при чтении файла.

- **`?PIP-F-Нет памяти`** — недостаточно памяти для выполнения операции (обычно если спецификация содержит `*`). *Действие:* удалить ненужные драйверы; разрешить свопинг `SET USR SWAP`; копировать файлы отдельно.

- **`?PIP-F-Не команда`** — ошибка в командной строке.

- **`?PIP-F-Нет устройства <уст>`** — указано недопустимое или несуществующее устройство.

- **`?PIP-F-Недопустимый справочник`** — *Действие:* `INITIALIZE`.

- **`?PIP-F-Нет переключателя /X`** — недопустимый переключатель.

- **`?PIP-F-Недопустимое имя для <спе>`** — недопустимое имя выходного файла для указанной операции.

- **`?PIP-F-Невозможно установить/снять защиту в программе PIP`** — ошибка при операции в PIP. См. `?PIP-F-Канал занят`.

- **`?PIP-F-Ошибка переименования <спе>`** — недопустимая операция переименования (входной и выходной тома должны совпадать).

- **`?PIP-F-Не дата <спе>`** — ошибка при работе программы `PIP`.

- **`?PIP-F-Ошибка в <спе>`** — спецификация входного файла содержит встроенные конструкции `*`/`%` и не соответствует входной спецификации.

- **`?PIP-F-Невозможно копирование файлов <спе>`** — копирование библиотечных файлов с переключателем `/BINARY` в режиме отображения памяти.

- **`?PIP-F-Ошибка записи <спе>`** — аппаратная ошибка во время операции записи; либо на томе недостаточно места. *Действие:* проверить аппаратуру и защиту записи; `SQUEEZE`; использовать другой том.

- **`?PIP-F-Нет места для <спе>`** — выходной файл заполнен.

- **`?PIP-F-Файл защищён <спе>`** — попытка удаления защищённого файла. *Действие:* `UNPROTECT`.

- **`?PIP-F-Недопустимый размер тома`** — ошибка при определении размера тома на приводе, не поддерживаемом монитором.

- **`?PIP-F-Системная ошибка`** — *Действие:* перезагрузить систему.

- **`?PIP-F-Много выходных файлов`** — определено несколько выходных спецификаций.

- **`?PIP-F-Ошибка верификации <спе>`** — обнаружены различия между входным и выходным файлами после операции `COPY/MULTIVOLUME`. *Действие:* проверить дефектные блоки; повторить копирование; при повторных различиях — заменить выходной том.

- **`?PIP-F-Ошибка ввода`** — попытка обращения к программе `PIP`, не принадлежащей данной системе.

- **`?PIP-I-Нет файла`** — указанный файл не найден.

- **`?PIP-W-Ошибка чтения <спе>`** — аппаратная ошибка при чтении с переключателем `/IGNORE`. *Действие:* не требуется (предупреждение).

- **`?PIP-W-Нет файлов .SYS`** — не указан переключатель `/SYSTEM`. Операция выполняется для всех файлов, кроме файлов с типом `.SYS`.

- **`?PIP-W-На томе существует файл <спе>`** — на устройстве вывода уже существует файл с тем же именем.

- **`?PIP-W-Перезагрузить`** — файлы с типом `.SYS` перемещены, переименованы или удалены на системном томе. *Действие:* если это файлы, с которыми работает система, перезагрузить; иначе игнорировать.

- **`?PIP-F-Код не определён`** — причина возникновения ошибки неизвестна. *Действие:* повторить; при повторении — скопировать новую копию `PIP.SAV`.

- **`?PIP-F-Файл создан; защищённый файл уже существует <спе>`** — см. описание выше.

#### Сообщения RESORC

- **`?RESORC-F-Ошибка чтения справочника`** — ошибка чтения справочника системного устройства. *Действие:* проверить оборудование; проверить системный том на дефектные блоки (`DIRECTORY/BADBLOCKS`).

- **`?RESORC-F-Входная ошибка <имяфайл.тип>`** — *Действие:* проверить системный том на дефектные блоки.

- **`?RESORC-F-Недостаточно памяти`** — *Действие:* освободить часть оперативной памяти.

- **`?RESORC-F-Недопустимый переключатель`** — *Действие:* исправить и ввести командную строку.

- **`?RESORC-F-Системная ошибка`** — сбой при работе запроса `.DSTATUS` или `.LOOKUP`. *Действие:* проверить готовность и исправность оборудования; перезагрузить монитор.

- **`?RESORC-F-Недопустимая версия монитора`** — *Действие:* использовать программу `RESORC` данной операционной системы.

#### Сообщения TFP (программа форматирования текста)

- **`?TFP-F-Не найден <имяфайл.тип>`** — указанный файл отсутствует на томе.

- **`?TFP-F-Недопустимая спецификация файла`** — *Действие:* ввести правильную командную строку.

- **`?TFP-F-LOAD LP` / `LOAD SY` / `LOAD XX`** — не загружен драйвер устройства `XX` или драйвер устройства печати. *Действие:* использовать команду `LOAD` перед выполнением программы.

- **`?TFP-F-Ошибка чтения файла`** — аппаратная ошибка при чтении исходного файла.

- **`?TFP-F-Вложенная директива .CPY игнорируется`** — попытка использовать `.CPY` во вторичном файле.

- **`?TFP-W-Недопустимая директива в строке #NNNNNN PAUSE`** — недопустимая директива в строке `NNNNNN` исходного текста. *Действие:* продолжить выполнение программы (`<ВК>`) — если такие предупреждения недопустимы, прервать выполнение (`СУ/С`) и отредактировать исходный текст.

- **`?TFP-W-Невозможно открыть файл оглавления`** — на системном томе нет свободного места для файла оглавления.

- **`?TFP-I-Конец 1-го прохода: количество страниц — NNNNN`** — информационное сообщение.

### 5.2. Сообщения редактора командной строки

| Сообщение | Причина |
|-----------|---------|
| `Начало строки` | Попытка переслать курсор влево, когда курсор находится в начале строки |
| `Конец строки` | Попытка переслать курсор вправо, когда курсор находится в конце строки |
| `Запрещённый символ` | Использован недопустимый управляющий символ |
| `Запрещено` | Использована недопустимая клавиша |
| `Строки не было` | Попытка использовать клавишу «стрелка вверх», когда введённой строки не существует |
| `Граница строки` | Длина командной строки превышает допустимую |
| `Стирания не было` | Попытка восстановить строку, когда строка отсутствует или не была уничтожена |
| `Команда запрещена` | Введённая команда не поддерживается редактором командной строки |

Действие для всех сообщений — ввести правильную командную строку или использовать допустимую функцию (клавишу).
