## 1. Начальные сведения

### 1.1. Общие сведения о ПЭВМ

ПЭВМ «Электроника МС0515» включает следующие устройства:

- центральный процессор;
- память (оперативная и постоянная);
- терминал (клавиатура и видеомонитор);
- накопитель для гибких магнитных дисков;
- синтезатор звука.

Процессор осуществляет управление работой ПЭВМ и выполняет все арифметические операции.

В оперативной памяти располагаются все программы, выполняемые ПЭВМ, и данные, используемые программами. Оперативная память используется для временного хранения информации.

Постоянная память предназначена для сохранения информации при отключении питания, необходимой для запуска и функционирования ПЭВМ.

Терминал предназначен для ввода и вывода информации. Ввод информации от пользователя в ПЭВМ осуществляется с помощью клавиатуры. Вывод информации из ПЭВМ осуществляется на экран видеомонитора.

Накопитель для гибких магнитных дисков предназначен для записи и чтения информации с дисков диаметром **133 мм**. Гибкие диски позволяют переносить документы и программы с одной ПЭВМ на другую, хранить информацию, не используемую постоянно на ПЭВМ, делать архивные копии.

Синтезатор звука предназначен для формирования программно управляемых звуковых сигналов, что даёт возможность исполнять музыку с помощью ПЭВМ.

### 1.2. Общие сведения об операционной системе

#### 1.2.1. Что такое операционная система

Операционная система (ОС) — это комплекс программ, которые загружаются при включении ПЭВМ. Они производят диалог с пользователем, осуществляют управление ПЭВМ, её ресурсами (оперативной памятью, местом на диске и т.д.), запускают другие программы на выполнение. Операционная система обеспечивает пользователю и программам удобный способ общения (интерфейс) с устройствами ПЭВМ.

Назначение операционной системы состоит прежде всего в том, чтобы предоставить пользователю удобный интерфейс для работы над файлами. Операционная система выполняет также вспомогательные действия, например, такие как копирование файлов. Кроме того, операционная система осуществляет загрузку в оперативную память программ, передаёт им управление для работы и освобождает занимаемую программами оперативную память при их завершении.

Компоненты ОС приведены в **приложении 1**.

### 1.3. Файлы на дисках

#### 1.3.1. Что такое файл

Информация на магнитных дисках хранится в файлах. Файл — это поименованная область на диске. В файлах могут храниться тексты программ, документы, готовые к выполнению программы и т.п.

Файлы располагаются в логических блоках. Логический блок в системе имеет фиксированный размер **512 (десятичное) байт**. Различают три основных формата данных:

- текстовый;
- объектный;
- отображения памяти.

Текстовые файлы предназначены для чтения человеком. Они состоят из строк символов, причём каждая строка оканчивается двумя специальными символами — «возврат каретки» (ВК) и «перевод строки» (ПС). При редактировании и просмотре текстовых файлов эти специальные символы, как правило, не видны. Файлы, не являющиеся текстовыми, называются двоичными.

Файлы объектного формата состоят из набора данных и машинных кодов. Они являются по существу объектными модулями, полученными в результате трансляции программ, написанных на языке Ассемблера.

Объектные файлы используются в качестве входных файлов для Редактора связей. Выходными файлами Редактора связей являются файлы формата отображения памяти.

Файл формата отображения памяти представляет собой точную копию содержимого памяти после его загрузки. Такой файл требует для своего размещения на диске столько же блоков, сколько он занимает в оперативной памяти.

#### 1.3.2. Имена и типы файлов

Обращение к файлу в операционной системе осуществляется по имени. Имя файла состоит из двух частей, разделённых точкой:

- собственно имени;
- типа файла.

Имя и тип файла представляют собой буквенно-цифровую последовательность, состоящую из символов латинского алфавита, кроме пробела и табуляции. Имя файла имеет длину от 1 до 6 символов, тип файла — до 3 символов. Тип файла не является обязательным. Тип файла обычно указывает его формат или содержимое. Пользователю рекомендуется согласовывать типы своих файлов со стандартными типами файлов операционной системы. Если для входного или выходного файла тип файла не указан, то большинство системных программ присваивает ему соответствующее стандартное значение типа файла.

### 1.4. Имена устройств

## 2. Работа с операционной системой

### 2.1. Начальная загрузка ОС

Для загрузки операционной системы в оперативную память выполните следующие действия:

1. установите гибкий диск с ОС в привод;
2. подключите сетевые кабели ПЭВМ и видеомонитора к сети переменного тока напряжением 220 В;
3. установите тумблер включения, расположенный на задней панели ПЭВМ, в положение «включено»;
4. установите тумблер включения, расположенный на задней панели видеомонитора, в положение «включено».

Загружается операционная система. На экран выводится информация, отображающая процесс загрузки ОС. По окончании загрузки ОС выводится:

```
ОСА  Версия 1.0

.SET TT QUIET
Дата (дд-мм-гг)?
```

Вводится текущая дата и — при необходимости — имя стартового файла. После этого система выдаёт системную дату, имя тома и владельца диска, если они есть, и **точку** в левой части экрана:
```
.
```

Это означает, что операционная система готова к приёму команд.

Состав носителя ОС приведён в приложении 2.

### 2.2. Диалог пользователя с операционной системой

Когда ОС готова к диалогу с пользователем, она выдаёт на экран приглашение (точку):

```
.
```

Диалог пользователя с ОС осуществляется в форме команд. Каждая команда означает, что ОС должна выполнить то или иное действие, например, напечатать файл или выдать на экран справочник.

Команда ОС состоит из имени команды и, возможно, переключателей и параметров. Имя команды ОС и параметры могут набираться как прописными, так и строчными латинскими буквами. Ввод каждой команды заканчивается нажатием клавиши `<ВК>`.

### 2.3. Обзор команд ОС

Команды ОС — это средство связи пользователя с операционной системой.

Команды системы позволяют управлять работой операционной системы, т.е. получать справочную информацию о системе, загружать в оперативную память системные программы и программы пользователя, назначать физическим устройствам логические имена, выводить на периферийные устройства содержимое одного или нескольких файлов и выполнять ряд других функций.

Ниже приводятся краткие сведения о командах системы: названия и описания назначения команд.

| Команда | Назначение |
|---------|-----------|
| `ASSIGN`     | Назначает логическое имя физическому устройству |
| `BOOT`       | Загружает монитор операционной системы |
| `COPY`       | Выполняет операцию копирования |
| `DATE`       | Установить или распечатать текущую дату |
| `DEASSIGN`   | Отменяет логическое имя устройства |
| `DELETE`     | Удаляет файлы с диска |
| `DIRECTORY`  | Выдаёт справочную информацию об устройстве |
| `HELP`       | Выдаёт справочную информацию о командах |
| `INITIALIZE` | Используется для очистки и инициализации справочника тома |
| `INSTALL`    | Указанное устройство включается в систему |
| `PRINT`      | Выводит на печать один или более файлов |
| `PROTECT`    | Устанавливает файлу защиту от удаления |
| `R`          | Загружает и запускает файл в формате отображения |
| `REMOVE`     | Удаляет драйвер указанного устройства из системы |
| `RENAME`     | Переименовывает файл |
| `RESET`      | Восстанавливает системные таблицы и очищает область памяти |
| `RUN`        | Загружает и запускает программу на выполнение |
| `SET`        | Позволяет изменить параметры конфигурации системы |
| `SHOW`       | Выдаёт информацию о системе |
| `SQUEEZE`    | Проводит операцию сжатия диска |
| `TYPE`       | Выводит содержимое файлов на терминал |
| `UNPROTECT`  | Отменяет защиту файла |

Для более подробного ознакомления с действием конкретной команды и списком допустимых переключателей и аргументов для неё следует ввести с терминала команду `HELP` с указанием интересующей команды: `HELP <команда>`.

**Пример.**

```
. HELP SQUEEZE
```

На терминал выводится:

```
SQUEEZE          Проводит операцию сжатия диска

SQ[UEEZE][/ПРК] УСТ

При выполнении операции сжатия система передвигает все
файлы тома в начало, получая одну неиспользованную
область после всех файлов.

Переключатели
OUTPUT:УСТ   — Сжимает диск на другой диск, где УСТ —
               устройство вывода
QUERY        — Опрашивает пользователя, надо ли выполнять
               указанную операцию
NOQUERY      — Запрещает печать на терминале опрашивающих
               сообщений перед выполнением команды
WAIT         — Разрешает ожидание для продолжения работы

Пример
   SQUEEZE /WAIT DZ0:           Сжимает диск DZ0:
```

Приведённый выше перечень команд выводится на терминал по команде `HELP *`.

Цифровые аргументы, используемые в переключателях, система воспринимает как десятичные числа, если не оговорено особо. Такие величины, как адреса памяти, система интерпретирует как восьмеричные числа.

Не рекомендуется в строке команды указывать взаимоисключающие переключатели, например, такие как `PROTECT` и `UNPROTECT`.

Монитор допускает сокращение имён команд и переключателей. Простым и правильным для всех имён является их сокращение до 4‑х символов или до 6‑ти символов, если переключатель с префиксом `NO`.

### 2.4. Формат команды

Команда операционной системы задаётся с терминала:

- в виде **полной строки**, содержащей достаточную информацию для выполнения указанной команды;
- в виде **краткой строки**. После ввода краткой строки на терминал выводится подсказка пользователю, какую информацию надо ввести.

**Общий формат полной строки:**

```
ком[/прк] входспф[/прк] выходспф[/прк]
```

**Общий формат краткой строки:**

```
ком[/прк]
   подсказка1 ? входспф[/прк]
   подсказка2 ? выходспф[/прк]
```

где `ком` — имя команды; `/прк` — один или несколько переключателей; `входспф` — спецификация входного файла; `выходспф` — спецификация выходного файла; `подсказка1`, `подсказка2` — текст системы пользователю с указанием, какую информацию должен ввести пользователь. Выводится, если в команде опущена спецификация входного или выходного файла либо их устройства.

Спецификация файла имеет формат:

```
уст:имфайл.тип
```

где `уст:` — логическое или физическое имя устройства; `имфайл.тип` — имя и тип файла.

В строке команды допускается указывать до **шести** входных и до **трёх** выходных файлов. Если команда не помещается на одной строке, с помощью символа `–` можно продолжить её на следующую строку. Количество символов в строке команды не должно превышать **80**. Строка команды должна оканчиваться возвратом каретки.

В строке команды допустимо использовать круглые скобки для краткой записи нескольких спецификаций файлов.

**Примеры:**

```
1) DZ0:(TEST.LST, TESTA.LST, TESTB.LST)
```

Система интерпретирует такую запись спецификаций как:

```
DZ0:TEST.LST, DZ0:TESTA.LST, DZ0:TESTB.LST
```

```
2) DZ0:FIL(1,2,3).SYS
```

Эта запись эквивалентна следующей:

```
DZ0:FIL1.SYS, DZ0:FIL2.SYS, DZ0:FIL3.SYS
```

**Примечание.** Существует, однако, ограничение при использовании круглых скобок - количество символов полной строки команды после раскрытия круглых скобок не должно превышать 80. Поэтому, если используются имена файлов из шести букв, допустимо указывать не более 5 файлов в строке команды.

### 2.5. Использование в командах конструкций \* и %

Система допускает использование конструкций «звёздочка» (`*`) и «процент» (`%`) вместо имени файла, типа файла или в качестве одного из символов имени или типа файла (так называемая встроенная конструкция).

1. **Символ `*` используется вместо имени файла.**
*Пример.* Если в команде спецификация файла имеет вид `*.MAC`, то в указанной операции будут использованы все файлы тома `DZ0` с типом `.MAC`, независимо от имён файлов;

2. **Символ `*` используется вместо типа файла.**
*Пример.* Если в строке команды спецификация файла имеет вид `TEST.*`, то в указанной операции будут использоваться все файлы тома `DZ0` с любым типом и именем `TEST`;

3. **Символ `*` используется в качестве имени и типа файла.**
*Пример.* Если спецификация файла имеет вид `*.*`, то в указанной операции будут использоваться все файлы тома `DZ0`;

4. **Символ `*` используется вместо нескольких символов имени или типа файла.**
*Пример.* Если в команде спецификация файла имеет вид `A*B.MAC`, то в указанной операции будут использоваться все файлы тома `DZ0` с типом `.MAC`, у которых имя начинается буквой `A` и оканчивается буквой `B`.

5. **Символ `%` всегда подразумевает один символ имени или типа входного файла.**
*Пример.* Если спецификация входного файла имеет вид `A%B.MAC`, то система использует в операции те файлы тома `DZ0` с типом `.MAC`, длина имени у которых **три символа**. При этом первая буква имени файла — `A`, третья — `B`.

В табл. 2.1 перечислены все команды, которые допускают использование символов `*` и `%`.

**ТАБЛИЦА 2.1**

| Имя команды | Использование символов `*` и `%` в спецификации входного файла | Использование символов `*` и `%` в спецификации выходного файла |
|-------------|---------|---------|
| `COPY`       | × | × |
| `DELETE`     | × |   |
| `DIRECTORY`  | × |   |
| `HELP`       | × |   |
| `PRINT`      | × |   |
| `PROTECT`    | × |   |
| `RENAME`     | × | × |
| `TYPE`       | × |   |
| `UNPROTECT`  | × |   |

В командах, которые допускают использование символов `*` и `%`, можно опускать отдельные части спецификации файлов, т. к. система присваивает символ `*` пропущенным частям спецификации. В табл. 2.2 символом `*` обозначены части спецификации файла, которые могут быть опущены в допустимых командах.

**ТАБЛИЦА 2.2**

1) `DIRECTORY`

2) `PRINT DZ0:`

Система интерпретирует данную команду как
```
PRINT DZ0:*.LST
```

По этой команде на устройстве печати выводятся все файлы тома `DZ0:` с типом `.LST`.


### 2.6. Редактирование командной строки

Не используя Редактор командной строки (SL), пользователь может изменить введённую строку двумя способами:

- удалить символы слева от курсора с помощью клавиши `<ЗБ>`;
- удалить всю напечатанную строку по `СУ/U` и повторно ввести строку.

Указатель текущего положения — **курсор** (далее в тексте — курсор) размещается в строке за последним обработанным знаком, в настоящем документе обозначается `_`.

С помощью SL можно редактировать строку, перемещая курсор по различным позициям, удаляя или вставляя символы.

SL доступен для команд системы и для программ пользователя и недопустим для устройства печати.

Если SL не установлен в системе, следует подать команду:

```
INSTALL SL
```

Если после этой команды было сообщение об ошибке, следует подать:

```
SET SL SYSGEN
```

затем

```
INSTALL SL
```

чтобы параметры драйвера SL соответствовал текущему монитору.

Если SL установлен в системе, разрешите его использование командой:

```
SET SL ON
```

т. е. пользователь может работать с SL при вводе строки с терминала. По окончании работы с SL следует подать:

```
SET SL OFF
```

Чтобы при ответе на подсказки системных программ пользователь мог использовать SL, следует подать команду:

```
SET SL TTYIN
```

Ниже описаны действия служебных клавиш и их комбинаций при работе с SL. Ограничитель редактируемой строки - `<ВК>`.

**ТАБЛИЦА 2.3 — Действия служебных клавиш и их комбинаций**

| Клавиша / комбинация | Действие |
|----------------------|----------|
| `<ПФ1>` | Используется в комбинации с любой клавишей для многократного повторения действия этой клавиши |
| `<ПФ2>` | Используется для получения вспомогательной информации после звукового сигнала |
| `← (стрелка влево)` | Перемещает курсор на одну позицию влево |
| `→ (стрелка вправо)` | Перемещает курсор на одну позицию вправо |
| `<ПФ1> ←` | Перемещает курсор в начало строки |
| `<ПФ1> →` | Перемещает курсор в конец строки |
| `↑ (стрелка вверх)` | Воспроизводит на терминале последнюю строку, завершённую возвратом каретки |
| `<ПФ3>` | Удаляет часть строки от курсора до конца строки |
| `<ПФ1> <ПФ3>` | Восстанавливает последнюю удалённую строку |
| `<ЗБ>` | Удаляет символ слева от курсора |
| `<ПФ1> <ЗБ>` | Восстанавливает последний удалённый символ |
| `<ВШ>` | Меняет местами символ, помеченный курсором, и символ, стоящий справа от курсора |
| `<ПФ1> <ВШ>` | Меняет местами символ, помеченный курсором, и символ, стоящий слева от курсора |
| `СУ/U` | Удаляет левую часть строки между точкой монитора (или `*` системной программы) и курсором |
| `<ПФ1> СУ/U` | Восстанавливает удалённую часть строки |
| `СУ/R` | Воспроизводит на терминале текущую строку |
| `СУ/W` | То же, что и `СУ/R` |
| `<ПФ1> <ВК>` | Удаляет правую часть строки от курсора до последнего символа строки и выполняет команду |
| `<ВК>` | Выполняет команду |

#### 2.6.1. Действие клавиши `<ПФ1>`

Клавиша `<ПФ1>` используется только в комбинации с другими клавишами для усиления функции.

Если нажать какую-либо клавишу без предварительного нажатия клавиши `<ПФ1>`, выполняется обычная функция нажатой клавиши.

Если же нажать клавишу `<ПФ1>` и затем клавишу, действие клавиши будет выполняться многократно. Например, если нажать клавишу `<стрелка влево>`, курсор передвигается на одну позицию влево. Если же нажать `<ПФ1>` и `<стрелка влево>`, курсор передвигается в начало строки.

#### 2.6.2. Действие клавиши `<ПФ2>`

Клавиша `<ПФ2>` используется для получения информации после звукового сигнала. Если нажать клавишу `<ПФ2>`, SL выводит сообщение о последней ошибке. Для возврата к первоначальному экрану и выполнению функций SL следует нажать любую клавишу, кроме клавиши `<ПФ2>`.

#### 2.6.3. Перемещение курсора

Клавиша `<стрелка влево>` используется для перемещения курсора на один или более знаков влево, `<стрелка вправо>` — вправо.

Клавиши `<ПФ1>` и `<стрелка влево>` используются для перемещения курсора в начало строки, `<ПФ1>` и `<стрелка вправо>` — в конец строки.

**Примеры:**

1) <code>COPY DZ0:A.MAC VM:B.MSG_</code>

   Два последовательных нажатия клавиши `<стрелка влево>` перемещают курсор на две позиции влево.

   <code>COPY DZ0:A.MAC VM:B.MS̲G</code>

2) <code>DELETE D̲Z0:FILE.TXT</code>

   После нажатия 4 раза клавиши `<стрелка вправо>` курсор перемещается на 4 позиции вправо.

   <code>DELETE DZ0:F̲ILE.TXT</code>

3) <code>RENAME DZ0:A.TXT VM:B̲.TXT</code>

   После нажатия клавиш `<ПФ1>` и `<стрелка влево>` курсор перемещается в начало строки.

   <code>R̲ENAME DZ0:A.TXT VM:B.TXT</code>

4) <code>CO̲PY FIL1.MAC, FIL2.MAC, FIL3.MAC FILES.MAC</code>

   После нажатия клавиш `<ПФ1>` и `<стрелка вправо>` курсор перемещается в конец строки.

   <code>COPY FIL1.MAC, FIL2.MAC, FIL3.MAC FILES.MAC_</code>

#### 2.6.4. Действие клавиши «стрелка вверх»

Клавиша `<стрелка вверх>` используется в ответ на точку монитора или системной программы для воспроизведения на терминале последней введённой строки, завершённой `<ВК>`.

Пустая строка (состоящая только из `<ВК>`) не считается последней строкой.

Воспроизведённую строку можно отредактировать и выполнить введённую команду. Курсор располагается в конце воспроизведённой строки.

**Пример.**

```
.LINK RTN1, RTN2, RTN3, RTN4, PROGM/EXECUTE/MAP
.
```

После нажатия клавиши `<стрелка вверх>` на терминал выводится:

```
.LINK RTN1, RTN2, RTN3, RTN4, PROGM/EXECUTE/MAP_
```

#### 2.6.5. Действие клавиши `<ПФ3>`

Клавиша `<ПФ3>` стирает часть строки от курсора до конца строки.

**Пример.**

<code>RENAME FIL1.MAC FIL2.MAC V̲M:MYFILE.MAC</code>

После нажатия клавиши `<ПФ3>` строка имеет вид:

<code>RENAME FIL1.MAC FIL2.MAC_</code>

#### 2.6.6. Действие клавиш `<ПФ1>` и `<ПФ3>` (или `<ПФ1>` и `СУ/U`)

Комбинации `<ПФ1>` и `<ПФ3>` (или `<ПФ1>` и `СУ/U`) восстанавливают все только что удалённые символы строки.

**Пример.** После нажатия клавиши `<ПФ3>` (см. пример п. 2.6.5) строка имеет вид

<code>RENAME FIL1.MAC FIL2.MAC_</code>

После нажатия `<ПФ1>` и `<ПФ3>` строка принимает прежний вид (какой был до нажатия `<ПФ3>`):

<code>RENAME FIL1.MAC FIL2.MAC V̲M:MYFILE.MAC</code>

#### 2.6.7. Действие клавиши `<ЗБ>`

Клавиша `<ЗБ>` удаляет символ слева от курсора.

**Пример.**
<code>COPY A.MAC B.MAC_</code>

После нажатия клавиши `<ЗБ>` получаем строку:

<code>COPY A.MAC B.MA_</code>

Используя клавиши `<ПФ1>` и `<ЗБ>`, можно восстановить последний удалённый символ.

#### 2.6.8. Действие клавиши `<ВШ>`

Клавиша `<ВШ>` меняет местами символ, под которым находится курсор, и символ, стоящий справа от курсора. При этом курсор также перемещается на новую позицию.

**Пример.** Если строка имеет вид:

<code>COPY MYFIL1.SAV MYFIL2.SV̲A</code>

то после нажатия клавиши `<ВШ>` получаем строку:

<code>COPY MYFIL1.SAV MYFIL2.SAV̲</code>

Последовательное нажатие клавиш `<ПФ1>` и `<ВШ>` меняет местами символ, помеченный курсором, и символ, стоящий слева от курсора.

**Пример.** Если строка имеет вид:

<code>CPO̲Y MYFIL1.SAV MYFIL2.SAV</code>

то после нажатия клавиш `<ПФ1>` и `<ВШ>` получаем новую строку:

<code>CO̲PY MYFIL1.SAV MYFIL2.SAV</code>


#### 2.6.9. Действие функции `СУ/U`

Функция `СУ/U` удаляет все символы в строке слева от курсора.

**Пример.** Если строка имеет вид:

<code>RENAME DZ0:M̲AIN.MAC VM:SUB1.MAC</code>

то после нажатия `СУ/U` получаем:

<code>M̲AIN.MAC VM:SUB1.MAC</code>

Для восстановления удалённых символов следует нажать клавиши `<ПФ1>` и `<СУ/U>`.

#### 2.6.10. Действие клавиш `<ПФ1>` и `<ВК>`

Последовательное нажатие клавиш `<ПФ1>` и `<ВК>` удаляет правую часть строки — от курсора до последнего символа строки — и выполняет команду.

**Пример.** Если строка имеет вид:

<code>COPY DZ0:*.MAC DZ0:*.BAC V̲M:FILES.BAK</code>

то после нажатия `<ПФ1>` и `<ВК>` строка принимает вид:

<code>COPY DZ0:*.MAC DZ0:*.BAC_</code>

и выполняется.

#### 2.6.11. Действие клавиши `<ВК>`

Клавиша `<ВК>` используется для выполнения строки независимо от положения курсора.

#### 2.6.12. Действие функций `СУ/R` и `СУ/W`

Функции `СУ/R` или `СУ/W` используются для воспроизведения на терминале текущей вводимой или последней введённой строки. Эти клавиши используются для проверки строки.

### 2.7. Копирование файлов

Копирование файлов на ПЭВМ «Электроника МС0515» в системе ОСА может быть осуществлено одним из двух способов:

1. непосредственно с диска на диск;
2. с использованием псевдодиска `VM:` в качестве промежуточного устройства.

При копировании первым способом могут быть указаны файлы любого размера, размещающиеся на томе. Однако, такая операция занимает много времени, так как постоянно приходится устанавливать в привод входной или выходной том.

Второй способ копирования значительно быстрее. Однако, он не подходит для файлов размером более **104 блоков** (максимальная свободная область на `VM:`).

Чтобы операция копирования осуществлялась с ожиданием подтверждения, используется ключ `COPY/WAIT` (режим копирования с ожиданием).

Возможными ответами на вопросы ПЭВМ при копировании файлов могут быть:

1. `Y` — подтверждение указанной операции;
2. `N` — отказ от указанной операции. Если в это время в приводе установлен системный том, на терминал выдаётся точка и ожидается ввод очередной команды монитора. Если установлен не системный том, последует требование установить системный том;
3. Символ, отличный от `Y` и `N`, — вопрос повторяется.

Ниже приводится описание каждого из этих способов.

#### 2.7.1. Копирование файлов без использования VM

Для непосредственного копирования файла с одного тома на другой необходимо выполнить следующие операции:

1. Подать команду копирования:

   ```
   COPY/WAIT DZ:<имфайл.тип> DZ:
   ```

Ответ:
   ```
   Установить входной том на DZ0:; Продолжить?
   ```

2. Установить в привод входной том (т.е. том, с которого копируется файл) и ввести `Y`

Ответ:
   ```
   Установить выходной том на DZ0:; Продолжить?
   ```

3. Установить в привод выходной том (т.е. том, на который копируется файл) и ввести `Y`. Осуществляется копирование очередной «порции» файла;

4. Если копировалась не последняя «порция» файла, ОС выдаёт сообщение
   ```
   Установить входной том на DZ0:; Продолжить?
   ```

В этом случае следует повторить работу, начиная с 2;

5. Если файл скопирован полностью (т. е. копировалась последния его «порция»), ОС выдаёт сообщение

   ```
   DZ0:<имфайл.тип> на DZ0:<имфайл.тип>
   Установить системный том на DZ0:; Продолжить?
   ```

В этом случае следует установить в привод системный том и ввести `Y`. Система отвечает точкой и ожидает ввода следующей команды пользователя. Для копирования очередного файла повторить работу, начиная с 1.

**Примечания:**

1. Для копирования системных файлов (тип `.SYS`) необходимо указать в команде COPY переключатель /SYS (более подробную информацию о команде `COPY` даёт команда `HELP COPY`).
2. Для выборочного копирования файлов с одного тома на другой можно воспользоваться командой
   ```
   COPY/QUERY/WAIT DZ: DZ:
   ```

#### 2.7.2. Копирование файлов с использованием VM

Копирование файлов с использованием `VM:` осуществляется в два этапа: с входного тома на `VM:` и с `VM:` на выходной том.

Для копирования файла с тома на `VM:` необходимо выполнить следующие операции:

1. Инициализировать `VM:` командой:

   ```
   INITIALIZE/NOQUERY VM:    или    INI/NOQ VM:
   ```

2. Подать команду копирования:

   ```
   COPY/WAIT DZ:<имфайл.тип> VM:
   ```

Ответ:
   ```
   Установить входной том на DZ0:; Продолжить?
   ```

3. Установить в привод входной том и ввести `Y`.

Ответ:
   ```
   Установить выходной том на VM:; Продолжить?
   ```

4. Ввести `Y`. Осуществляется копирование указанного файла на `VM:`. По окончании копирования выдаётся

   ```
   DZ0:<имфайл.тип> на VM:
   Установить системный том на DZ0:; Продолжить?
   ```

5. Установить в привод системный том и ввести `Y`. На терминал выдается точка и ожидается ввод очередной команды пользователя. Для копирования очередного файла повторить работу, начиная с 2.

Для копирования файла с `VM:` на том необходимо выполнить следующие операции:

1. Подать команду:

   ```
   COPY/WAIT VM:<имфайл.тип> DZ:
   ```

Ответ:
   ```
   Установить входной том на VM:; Продолжить?
   ```

2. Ввести `Y`.

Ответ:
   ```
   Установить выходной том на DZ0:; Продолжить?
   ```

3. Установить в привод выходной том и ввести `Y`. Осуществляется копирование указанного файла на том. По окончании копирования выдается сообщение

   ```
   VM:<имфайл.тип> на DZ0:
   Установить системный том на DZ0:; Продолжить?
   ```

4. Установить в привод системный том и ввести `Y`. На терминал выдается точка и ожидается ввод очередной команды пользователя. Для копирования очередного файла повторить работу, начиная с 1.

#### 2.7.3. Копирование системных дисков и получение рабочих систем

Для копирования системных томов используются заранее инициализированные гибкие диски (желательно без дефектных блоков). Диски с дефектными блоками в системной (начальной) области к работе непригодны. Инициализация и проверка дисков на дефектные блоки приведена в п. 2.7.4.

Для копирования одного системного тома на другой используется команда:

   ```
   COPY/SYSTEM/WAIT DZ0:  DZ0:
   ```

Весь диалог с системой описан в п. 2.7.1.

По завершении копирования необходимо записать на диск-копию блоки начального загрузчика по команде

   ```
   COPY/BOOT/WAIT DZ0:MON8SJ DZ0:
   ```

(см. п. 2.7.1). Копирование системного тома завершено.

При создании рабочей системы, состав которой отличается от поставляемой, выполняются аналогичные действия. Различие лишь в том, что пользователь осуществляет выборочное копирование необходимых файлов с разных дисков, используя команду

   ```
   COPY/SYSTEM/WAIT/QUERY DZ0:  DZ0:
   ```

и затем записывает на диск-копию начальный загрузчик по команде `COPY/BOOT`.

**Примечание.** Минимальная работоспособная система должна содержать следующие файлы:

   ```
   (MON8SJ,SWAP,DZ,VM).SYS,  (PIP,DUP,DIR).SAV
   ```

Остальные файлы пользователь включает по своему усмотрению.

#### 2.7.4. Инициализация и проверка дисков на дефектные блоки

Для инициализации справочника гибкого диска необходимо подать команду:

   ```
   INITIALIZE/NOQUERY/WAIT DZ:
   ```

Ответ:
   ```
   Установить входной том на DZ:; Продолжить?
   ```


Установить требуемый диск и ввести `Y`. Выполняется инициализация диска, затем выдаётся

   ```
   Установить системный том на DZ0:; Продолжить?
   ```

Установить системный том и ввести `Y`.

Для проверки диска на дефектные блоки необходимо подать команду:

   ```
   DIRECTORY/BADBLOCKS/WAIT DZ:
   ```

или

   ```
   DIRECTORY/BADBLOCKS/FILES/WAIT DZ:
   ```

Ответ:

   ```
   Установить входной том на DZ:; Продолжить?
   ```

Установить проверяемый том в привод и ввести `Y`. По завершении сканирования диска выдаются результаты - сведения о количестве и расположении дефектных блоков, затем выдается сообщение:

   ```
   Установить системный том на DZ0:; Продолжить?
   ```

Установить системный том и ввести `Y`.

Инициализацию и проверку на дефектные блоки можно выполнить одновременно командой `INITIALIZE/BADBLOCKS/NOQUERY`. Кроме того, эта команда позволяет локализовать дефектные блоки, если их немного и они расположены не в системной (начальной) области диска (см. `HELP INITIALIZE/BADBLOCKS`). Диалог с системой тот же, что и для команд `INITIALIZE/NOQUERY` и `DIRECTORY/BADBLOCKS`.

## 4. Программа форматирования текста

Программа форматирования текста предназначена для получения текстов в форме, удобной для чтения, распечатки созданных или скорректированных файлов. Формат исходного текста позволяет быстро вносить изменения средствами редактирования операционной системы.

### 4.1. Запуск программы

Перед загрузкой и запуском программы необходимо назначить физическому устройству, выбранному для вывода сформатированного текста (в дальнейшем — документа), логическое имя `DOC` командой `ASSIGN`.

Если назначение логического устройства не сделано, то вывод сформатированного текста осуществляется на устройство печати.

Например, для того, чтобы документ был выведен на диск `DZ0:`, нужна команда:

```
ASSIGN DZ0 DOC
```

Программа форматирования текста записана в файле `TFP.SAV`, который рекомендуется размещать на системном устройстве (`SY:`).

Если файл `TFP` находится на системном устройстве, то для загрузки и запуска программы достаточно команды:

```
R TFP
```

Если файл расположен на любом другом устройстве прямого доступа (`DEV:`), необходима команда:

```
RUN DEV:TFP
```

После загрузки и запуска программы на терминал выводится `*`, что означает готовность программы к форматированию очередного документа.

В ответ на `*` нужно указать спецификацию файла, в котором содержится исходный текст. Если в спецификации файла пользователь не указал тип файла, то по умолчанию используется тип `.TFP`. Если вводится пустая строка (клавиша `<ВК>`), то на терминал выводится версия программы:

```
RUN TFP<ВК>
*<ВК>
TFP B03.01
*
```

**Примечание.** Если в спецификации файла опущено имя устройства, то по умолчанию выбирается устройство `DZ0:`.

По окончании обработки текста повторно выводится `*` на терминал. Запуск программы и задание спецификации файла можно совместить в одной команде. Например:

```
RUN TFP DZ0:TEXT
```

В результате работы программы создаётся сформатированный текст документа, который размещается в файле `DOC<NAME>.DOC` (`<NAME>` — имя первого входного файла).

### 4.2. Команды

Исходный текст может размещаться в одном или нескольких файлах и состоит из текстовой информации и директив форматирования. Текстовая информация будет распечатываться в виде, определяемом директивами:

- форматирования текста;
- оформления страниц;
- описания структуры выводимого текста;
- служебными.

Программа форматирования текста позволяет выводить документы на стандартных листах.

#### 4.2.1. Синтаксис директив форматирования

Все директивы форматирования должны размещаться на отдельных строках, начиная с первой печатной позиции строки. Директивы начинаются с точки (`.`) и имеют следующий формат:

```
.DIR ARG
```

где `.DIR` — идентификатор соответствующей директивы; `ARG` — аргумент директивы.

Аргумент директивы может быть целым десятичным числом, строкой текста или спецификацией файла. Некоторые директивы не требуют аргумента. Опущенный числовой аргумент директивы по умолчанию принимается значение `1`.

#### 4.2.2. Директивы форматирования текста

##### 4.2.2.1. Директива `.LIN`

Директиве `.LIN` требуется один числовой аргумент, который определяет количество пустых строк, пропускаемых перед началом следующего фрагмента текста. Под фрагментом понимается текст, расположенный между двумя директивами. Фрагмент, следующий за директивой `.LIN`, выводится **с красной строки**.

Если фрагмент текста попадает на начало страницы, пропуск строк не выполняется. В том случае, когда пропуск строк приводит к переводу на новую страницу, фрагмент начинается с начала этой страницы.

При выводе строки выравниваются по длине, дополняясь пробелами между словами. Перенос слов в исходном тексте не рекомендуется.

##### 4.2.2.2. Директива `.BLN`

Директива `.BLN` аналогична `.LIN`. В отличие от `.LIN` вывод фрагмента начинается **с начала строки** (без красной строки).

##### 4.2.2.3. Директива `.SKI`

Директива `.SKI` аналогична `.BLN`. В отличие от `.BLN` пропуск строк производится, даже если следующий фрагмент попадает на начало страницы. Если на текущей странице осталось строк меньше, чем требует аргумент, предварительно производится переход на новую страницу.

##### 4.2.2.4. Директива `.INT`

Директива `.INT` используется для вывода сформатированного текста с указанным интервалом. Директива имеет числовой аргумент, который определяет количество пустых строк, пропускаемых перед выводом очередной строки.

##### 4.2.2.5. Директива `.SWT`

Директива `.SWT` используется для вывода следующего фрагмента текста без форматирования, включая пустые строки. Числовой аргумент интерпретируется как и в директивах `.BLN` или `.LIN`. Строки следующего фрагмента должны иметь длину, не превышающую ширину колонки. В фрагменте, следующем за `.SWT`, использование знаков табуляции недопустимо.

##### 4.2.2.6. Директива `.NOF`

Действие директивы `.NOF` аналогично действию директивы `.SWT` без ограничения на длину строки и знаки табуляции. Директива `.NOF` используется без аргумента.

**Примечание.** Для установления требуемой длины строки используются команды монитора `SET TT: WIDTH=N` и `SET LP: WIDTH=N` соответственно для терминала или устройства печати (`N` — длина строки). Длина любой строки исходного текста не должна превышать **128 знаков**.

##### 4.2.2.7. Директива `.MID`

Директива `.MID` используется для вывода текстового аргумента. Строка-аргумент выводится по центру страницы.

##### 4.2.2.8. Директива `.RIT`

Директива `.RIT` используется для вывода текстового аргумента. Строка-аргумент выравнивается по правой границе страницы.

#### 4.2.3. Директивы оформления страниц

Программа форматирования текста автоматически формирует страницы выводимого документа. В оформление страниц документа входят:

- нумерация страниц;
- обозначение документа;
- сформатированный текст документа.

Нумерация страниц осуществляется автоматически. Номер страницы выводится по центру первой (или единственной) страницы. Наличие и содержание обозначения определяются пользователем.

##### 4.2.3.1. Директива `.STL`

Аргумент директивы `.STL` — текстовая строка, используемая в качестве обозначения или наименования документа.

Для использования обозначения документа при форматировании титульного листа необходимо, чтобы директива `.STL` предшествовала директиве `.TIT` (п. 4.2.4.1) в тексте исходного документа.

Действие директивы `.STL` может быть изменено (отменено) только другой директивой `.STL`.

**Примечание.** Чтобы отказаться от вывода обозначения документа, достаточно использовать директиву `.STL` без аргумента.

##### 4.2.3.2. Директива `.PAG`

По директиве `.PAG` производится переход на новую страницу документа. Переход не производится, если директива обрабатывается в начале страницы.

##### 4.2.3.3. Директива `.TES`

По директиве `.TES` производится переход на новую страницу документа, если на текущей странице осталось строк меньше, чем задано числовым аргументом директивы.

#### 4.2.4. Директивы описания структуры документа

Для описания структуры документа используется следующий набор директив:

- титульный лист;
- аннотация;
- содержание;
- разделы и подразделы;
- пункты и подпункты;
- перечисления;
- примечания;
- приложения.

Приложения могут содержать разделы, подразделы и т. д.

Использование директив описания структуры облегчает формирование заголовков и обеспечивает автоматический сбор содержания и нумерации разделов, подразделов, пунктов, подпунктов и приложений.

##### 4.2.4.1. Директива `.TIT`

Директива `.TIT` формирует титульный лист документа из четырёх следующих за ней строк.

В качестве 4-й строки рекомендуется указывать год издания документа.

##### 4.2.4.2. Директива `.TOC`

Директива `.TOC` используется для указания необходимости сбора содержания. Если необходим сбор содержания, то директива `.TOC` должна быть первой в исходном тексте.

При сборе содержания программа форматирования текста выполняет два прохода (просмотра) исходного текста. На первом проходе осуществляется сбор содержания, а на втором — вывод документа и содержания.

В конце первого прохода на терминал выводится сообщение о завершении первого прохода и количестве страниц, которое будет содержать сформатированный документ.

##### 4.2.4.3. Директива `.ANN`

Директива `.ANN` определяет начало аннотации к документу. Фрагменты текста, следующие за директивой (и разделенные, если надо, директивами форматирования текста), включаются в аннотацию. Ограничителем аннотации является начало одного из разделов, подразделов, пунктов, подпунктов или приложений.

**Примечание.** В аннотации допустимо использование перечислений и примечаний.

##### 4.2.4.4. Директива `.APN`

Директива `.APN` используется для вывода приложения, текстовый аргумент является заголовком приложения. Приложения начинаются с новой страницы.

##### 4.2.4.5. Директива `.CPT`

Директива `.CPT` используется для вывода раздела. Директива `.CPT` аналогична `.APN`.

##### 4.2.4.6. Директива `.HLV`

Директива `.HLV` используется для определения начала подраздела, пункта или подпункта. Интерпретация директивы определяется числовым аргументом (`1` — подраздел, `2` — пункт, `3` — подпункт). Фрагмент текста, следующий за директивой, используется как заголовок.

**Примечание.** Заголовок форматируется аналогично текстовой информации, но на меньшую длину выходной строки.

Если непосредственно за директивой `.HLV` указать одну из директив `.LIN`, `.BLN`, то форматирование заголовка не производится. В этом случае в начале выводимого фрагмента текста будет проставлена соответствующая нумерация. Содержание номера определяется аналогично нумерации заголовков.

##### 4.2.4.7. Директива `.AND`

Директива `.AND` определяет начало фрагмента текста, который используется как элемент перечисления. Числовой аргумент указывает количество пустых строк перед началом данного элемента перечисления.

Элемент перечисления при выводе дополняется знаком «–» и форматируется аналогично текстовой информации.

##### 4.2.4.8. Директива `.TBL`

Директива `.TBL` является комбинацией директив `.SWT` и `.AND 0` и позволяет заменить последовательность:

```
.SWT
строка
.AND 0
текст
```

на более короткую:

```
.TBL строка
текст
```

##### 4.2.4.9. Директива `.ATT`

Директива `.ATT` определяет начало фрагмента текста примечания. Числовой аргумент не используется. Форматирование производится аналогично текстовой информации.

**Примечание.** В документе тексту примечания предшествует слово «Примечание».

##### 4.2.4.10. Директива `.LST`

Директива `.LST` осуществляет вывод перечня, используя текстовый аргумент как заголовок.

#### 4.2.5. Служебные директивы

##### 4.2.5.1. Директива `.COM`

Директива `.COM` предназначена для внесения комментариев в исходный текст. Строки-аргументы директивы не выводятся в формируемый документ; они выводятся на терминал.

Директива:

```
.COM текст
```

приведёт к выводу на терминал:

```
?TFP-I- текст
```

##### 4.2.5.2. Директива `.CHA`

Аргументом директивы `.CHA` является спецификация файла (см. п. 2.4), в котором находится продолжение исходного текста документа.

По этой директиве обработка текущего файла прекращается и начинается обработка указанного файла. Это даёт возможность размещать исходный текст в нескольких файлах, расположенных, возможно, на различных томах. Длина «цепочки» файлов логически не ограничена.

**Примечание.** Если в спецификации файла отсутствует указание устройства, то по умолчанию выбирается устройство, на котором размещён первый файл выводимого документа.

##### 4.2.5.3. Директива `.CPY`

Аргументом директивы `.CPY` является спецификация файла (см. п. 2.4). Текст, содержащийся в указанном файле, будет включён в формируемый документ.

По директиве `.CPY` обработка текущего файла приостанавливается и начинается обработка указанного файла. По завершении обработки этого файла программа возобновляет обработку первоначального файла со строки, следующей за `.CPY`. Во вторичном файле использование директивы `.CPY` запрещено.

**Примечание.** Если в спецификации файла отсутствует указание устройства, то по умолчанию выбирается устройство, на котором размещён первый файл выводимого документа.

### 4.3. Пример исходного текста документа

В качестве примера приводится начало исходного текста данного документа.

```
.TOC
.COM ПРОГРАММА ФОРМАТИРОВАНИЯ ТЕКСТОВ
.TIT
ОПЕРАЦИОННАЯ СИСТЕМА ОСА
ПРОГРАММА ФОРМАТИРОВАНИЯ ТЕКСТОВ

1991
.PAG
.CPT ПРОГРАММА ФОРМАТИРОВАНИЯ ТЕКСТА
Программа форматирования текста предназначена для получения
текстов в форме, удобной для чтения,
распечатки созданных или сформированных файлов. Формат
исходного текста позволяет быстро вносить изменения
средствами редактирования операционной системы.
.HLV 1 Запуск программы
.LIN
Перед загрузкой и запуском программы необходимо назначить
физическому устройству, выбранному для
вывода сформатированного текста (в дальнейшем
"DOC") командой ASSIGN.
.LIN
Если назначение логического устройства не сделано,
то вывод сформатированного текста осуществляется
на устройство печати.
.LIN
Например, для того, чтобы документ был выведен на диск DZ0,
нужна команда:
.SWT

.LIN
Программа форматирования текста записана в файле

.LIN
```

## 5. Сообщения

### 5.1. Сообщения операционной системы ОСА

Ниже приведены сообщения, выдаваемые операционной системой ОСА.

В сообщениях в угловых скобках указывается информация, которая заменяется при выводе сообщения конкретным значением:

```
уст        — имя устройства
имфайл.тип — имя и тип файла
спф        — спецификация файла (уст:имфайл.тип)
адр        — адрес
NNNNNN     — число
```

`?BOOT-F-Нет начального загрузчика на томе`  
Причина. На томе отсутствует начальный загрузчик.  
Действие. Использовать команду монитора `COPY/BOOT` для записи начального загрузчика на том.

`?BOOT-U-Несовпадение вариантов генерации`  
Причина. Используются несовпадающие варианты генерации драйвера устройства и монитора. Выполнение завершается.  
Действие. Проверить соответствие вариантов генерации.

`?BOOT-U-Нет драйвера`  
Причина. Не найден драйвер системного устройства во время загрузки. Выполнение завершается.  
Действие. Скопировать драйвер (`XX.SYS`) на системный том. Вновь повторить операцию загрузки.

`?BOOT-U-Недостаточно памяти`  
Причина. Объём оперативной памяти не позволяет разместить загружаемый монитор. Попытка загрузить монитор в меньший объём памяти, чем установлено в системе. Выполнение завершается.  
Действие. Использовать команду монитора `COPY/BOOT` для записи начального загрузчика на системный том. Проверить наличие памяти на устройстве для размещения монитора.

`?BOOT-U-Ошибка В/В`  
Причина. Ошибка ввода-вывода во время загрузки системы: на системном томе отсутствует начальный загрузчик. Выполнение завершается.  
Действие. Использовать команду `COPY/BOOT уст` для записи начального загрузчика на системный том. Если ошибка повторяется, проверить готовность и исправность оборудования.

`?BOOT-U-Нет монитора`  
Причина. На системном томе нет монитора с соответствующим данному загрузчику именем. Выполнение завершается.  
Действие. Проверить правильность выбора системного тома.

`?BOOT-U-Файл свопинга слишком мал`  
Причина. Размер файла `SWAP.SYS` меньше 26 (десятичное) блоков. Выполнение завершается.  
Действие. Скопировать файл `SWAP.SYS` с другого системного тома.

`?BOOT-U-Нет SWAP.SYS`  
Причина. На загружаемом томе отсутствует файл `SWAP.SYS`. Выполнение завершается.  
Действие. Скопировать файл `SWAP.SYS` на системный том. Вновь загрузить систему.

`?BOOT-W-Ошибка чтения драйвера`  
Причина. Аппаратная ошибка чтения драйвера. Драйвер содержит дефектные блоки.  
Действие. Проверить готовность и исправность оборудования.

`?BOOT-W-TT.SYS нет или недопустим`  
Причина. Драйвер `TT.SYS` отсутствует на системном томе во время загрузки монитора. Вариант генерации драйвера `TT:` не соответствует варианту генерации монитора.  
Действие. Записать файл `TT.SYS` на системный том и вновь запустить систему для установки `TT:`. Проверить соответствие вариантов генерации драйвера `TT:` и монитора.

`?CSI-F-Том полон`  
Причина. На указанном устройстве нет места для размещения выходного файла, созданного программой пользователя с помощью запроса `.CSIGEN`.  
Действие. Увеличить размер свободной области на томе: удалить или переписать на другой том ненужные файлы, сжать том по команде монитора `SQUEEZE`, указать в командной строке размер выходного файла.

`?CSI-F-Файл не найден`  
Причина. Не найден входной файл, указанный программой пользователя с помощью запроса `.CSIGEN`.  
Действие. Проверить поданную команду.

`?CSI-F-Недопустимая команда`  
Причина. Не указано имя выходного файла: длина командной строки превышает 80 символов, или командная строка содержит недопустимые символы, например, пробелы; число файлов, указанных в команде, превышает допустимое; длина входной строки в запросе `.GTLIN` превышает 80 символов. Сообщение выдаётся в том случае, если программа пользователя использовала запрос `.CSIGEN` или `.CSISPC`.  
Действие. Проверить поданную команду. Убедиться, что длина входной строки в запросе `.GTLIN` не превышает 80 символов.

`?CSI-F-Недопустимое устройство`  
Причина. Устройство, указанное в программе пользователя с помощью запроса `.CSIGEN`, не существует. В системе не установлено обслуживание таких устройств, как `TT:`, возможно, отсутствует соответствующий драйвер. Попытка ввести команду `DIRECTORY`, когда файл `TT.SYS` отсутствует на системном устройстве.  
Действие. Проверить поданную команду. Скопировать требуемый драйвер на системный том и вновь загрузить систему.

`?CSI-F-Файл защищён`  
Причина. Файлы, указанные в программе пользователя с помощью запроса `.CSIGEN`, уже существуют и защищёны.  
Действие. Использовать другое имя для открытия нового файла или удалить, переименовать или изменить уровень защиты существующего файла по команде монитора `UNPROTECT`.

`?DIR-F-Устройство не активно`  
Причина. Операция ввода-вывода невозможна на указанном устройстве или томе; устройство отключено; запрещена запись; устройство не описано в таблице устройств монитора.  
Действие. Проверить правильность включения устройства. Установить обслуживание устройства по команде монитора `INSTALL`.

`?DIR-F-Ошибка чтения справочника`  
Причина. Ошибка чтения справочника тома.  
Действие. Проверить исправность и правильность включения аппаратуры. Проверить диск на дефектные блоки.

`?DIR-F-Файл создан; защищённый файл уже существует <спф>`  
Причина. Создан незащищённый файл. Защищённый файл с тем же именем уже существует.  
Действие. Просмотреть листинг справочника без использования переключателей. Удалить или переименовать незащищённый файл, если его имя в справочнике предшествует имени защищённого файла. Переименовать или изменить код защиты защищённого файла по команде монитора `UNPROTECT`, если его имя в справочнике предшествует имени незащищённого файла.

`?DIR-F-Ошибка входного файла <спф>`  
Причина. Произошла аппаратная ошибка при чтении входного файла.  
Действие. Проверить исправность и правильность включения аппаратуры. Проверить том на дефектные блоки.

`?DIR-F-Недостаточно памяти`  
Причина. Недостаточно памяти для получения упорядоченного справочника.

Действие. Проверить исправность и правильность включения аппаратуры. Проверить том на дефектные блоки. Повторить операцию. Если ошибка повторяется, скопировать максимально возможное число файлов на другой том. Отформатировать том и повторить операцию. Если ошибка повторяется снова, заменить том другим.

`?PIP-F-Ошибка в/в на <уст:>`  
Причина. Нарушена структура справочника на томе.  
Действие. Проверить том и исправность устройства. Повторить операцию. Проверить том на дефектные блоки (`DIRECTORY/BADBLOCKS`). Если на томе есть дефектные блоки в области справочника, он к работе непригоден. Использовать другой том.

`?PIP-F-Ошибка обращения <уст:>`  
Причина. Ошибка при обращении к программе `PIP`.  
Действие. См. `?PIP-F-Канал занят`.

`?PIP-F-Нет файла <спф>`  
Причина. Указанный входной файл не найден или нет файлов с указанной датой создания.  
Действие. Проверить командную строку и сравнить имеющиеся файлы с указанными в командной строке. Повторить операцию.

`?PIP-F-Ошибка чтения <спф>`  
Причина. Аппаратная ошибка во время чтения файла.  
Действие. См. `?PIP-F-Ошибка чтения <уст:>`.

`?PIP-F-Нет памяти`  
Причина. Недостаточно памяти для выполнения требуемой операции (обычно, если спецификация файла содержит конструкцию `*`).  
Действие. Удалить ненужные драйверы устройств. Разрешить свопинг монитора по команде монитора `SET USR SWAP`. Копировать файлы отдельно.

`?PIP-F-Не команда`  
Причина. Ошибка в командной строке.  
Действие. Ввести правильную командную строку.

`?PIP-F-Нет устройства <уст:>`  
Причина. Указано недопустимое или несуществующее устройство.  
Действие. Проверить введённую командную строку. Использовать команду монитора `SHOW` для получения списка устройств, обслуживаемых системой.

`?PIP-F-Недопустимый справочник`  
Причина. Структура справочника тома устройства не является структурой данной операционной системы.  
Действие. Инициализировать том по команде монитора `INITIALIZE`.

`?PIP-F-Нет переключателя /X`  
Причина. В командной строке обнаружен недопустимый переключатель.  
Действие. Ввести правильную командную строку.

`?PIP-F-Недопустимое имя файла`  
Причина. Недопустимое имя выходного файла для указанной операции.  
Действие. Проверить и повторить командную строку.

`?PIP-F-Невозможно установить/снять защиту <спф>`  
Причина. Ошибка при операции (вызове) в программе `PIP`.  
Действие. См. `?PIP-F-Канал занят`.

`?PIP-F-Ошибка переименования <спф>`  
Причина. Недопустимая операция переименования.  
Действие. Проверить введённую командную строку (входной и выходной тома должны совпадать).

`?PIP-F-Не дата <спф>`  
Причина. Ошибка при вызове программы `PIP`.  
Действие. См. `?PIP-F-Канал занят`.

`?PIP-F-Ошибка в <спф>`  
Причина. Спецификация выходного файла содержит встроенную конструкцию `*` и не соответствует входной спецификации.  
Действие. Проверить введённую командную строку.

`?PIP-F-Невозможно копирование файла <спф>`  
Причина. Копирование библиотечных файлов с переключателем `/BINARY`.  
Действие. Копировать в режиме отображения памяти.

`?PIP-F-Ошибка записи <спф>`  
Причина. Аппаратная ошибка во время операции записи. На томе недостаточно места для создания файла.  
Действие. Проверить исправность и правильность включения аппаратуры. Проверить защиту записи. Проверить диск на дефектные блоки. Сжать том по команде монитора `SQUEEZE`. Удалить или записать на другой том ненужные файлы. Указать в командной строке размер выходного файла. Использовать другой том.

`?PIP-F-Нет места для <спф>`  
Причина. Выходной файл заполнен: на томе нет места для файла.  
Действие. Сжать том по команде монитора `SQUEEZE`. Удалить или записать на другой том ненужные файлы. Указать в командной строке размер выходного файла. Использовать другой том.

`?PIP-F-Файл защищён <спф>`  
Причина. Попытка удаления защищённого файла.  
Действие. Отменить защиту файла, используя команду `UNPROTECT`, и повторить команду.

`?PIP-F-Недоступный том`  
Причина. Ошибка при определении размера тома на приводе, который не поддерживается монитором.  
Действие. Установить том на привод с номером, который поддерживается монитором.

`?PIP-F-Системная ошибка`  
Причина. Ошибка в системе.  
Действие. Перезагрузить систему.

`?PIP-F-Много выходных файлов`  
Причина. В командной строке определены несколько выходных спецификаций.  
Действие. Проверить введённую командную строку.

`?PIP-F-Ошибка верификации <спф>`  
Причина. Обнаружены различия между входными и соответствующими выходными данными после операции копирования по команде `COPY/MULTIVOLUME`.  
Действие. Проверить том на дефектные блоки. Повторить операцию копирования. Если различия повторяются, заменить выходной том.

`?PIP-I-Ошибки вызова`  
Причина. Попытка обращения операционной системы к программе `PIP`, не принадлежащей данной системе.  
Действие. Вызвать программу `PIP` данной системы.

`?PIP-I-Нет файла`  
Причина. Указанный файл не найден.  
Действие. Действие не требуется.

`?PIP-W-Ошибка чтения <спф>`  
Причина. Аппаратная ошибка во время операции чтения с переключателем `/IGNORE`.  
Действие. Не требуется. Предупреждающее сообщение.

`?PIP-W-Без файлов .SYS`  
Причина. Не указан переключатель `/SYSTEM`. Операция выполнится для всех файлов, кроме файлов с типом `.SYS`.  
Действие. Использовать переключатель `/SYSTEM`, если необходимо включить в операцию файлы с типом `.SYS`. Предупреждающее сообщение.

`?PIP-W-На томе существует файл <спф>`  
Причина. На устройстве вывода уже существует файл с тем же именем, что и выходной файл.  
Действие. Переименовать файл. Использовать другой том. Предупреждающее сообщение.

`?PIP-W-Перезагрузить`  
Причина. Файлы с типом `.SYS` перемещены, переименованы или удалены на системном томе.  
Действие. Если это файлы, с которыми в данный момент работает система, перезагрузить систему, иначе — сообщение игнорировать. Предупреждающее сообщение.

`?PIP-F-Код не определён`  
Причина. Причина возникновения ошибки не известна системе.  
Действие. Запустить программу ещё раз. При повторении ошибки проанализировать программу или скопировать файл `PIP.SAV` на системный том.

`?PIP-E-Файл создан; защищённый файл уже существует <спф>`  
Причина. Создан незащищённый файл. Защищённый файл с тем же именем уже существует.  
Действие. Просмотреть листинг справочника без использования переключателей. Удалить или переименовать незащищённый файл, если его имя в справочнике предшествует имени защищённого файла. Переименовать или изменить код защиты защищённого файла по команде монитора `UNPROTECT`, если его имя в справочнике предшествует имени незащищённого файла.

`?RESORC-F-Ошибка чтения справочника`  
Причина. Ошибка чтения справочника системного устройства.  
Действие. Проверить готовность и исправность оборудования. Проверить системный том на дефектные блоки, используя команду `DIRECTORY/BADBLOCKS`.

`?RESORC-F-Входная ошибка <имфайл.тип>`  
Причина. Ошибка чтения указанного файла.  
Действие. Проверить системный том на дефектные блоки.

`?RESORC-F-Недостаточно памяти`  
Причина. Недостаточно памяти для работы программы `RESORC`.  
Действие. Освободить часть оперативной памяти. Повторить выполнение операции.

`?RESORC-F-Недоступный переключатель`  
Причина. Переключатель, указанный в командной строке, не является переключателем `RESORC`.  
Действие. Исправить и вновь ввести командную строку.

`?RESORC-F-Системная ошибка`  
Причина. Сбой при работе запроса `.DSTATUS` или `.LOOKUP`. Либо устройство не готово к работе, либо монитор, загруженный в память, повреждён.  
Действие. Проверить готовность и исправность оборудования, перезагрузить монитор.

`?RESORC-F-Недопустимая версия монитора`  
Причина. Попытка обращения операционной системы к программе `RESORC`, не принадлежащей данной системе.  
Действие. Использовать программу `RESORC` данной системы.

`?TFP-F-Не найден файл <имфайл.тип>`  
Причина. Указанный файл отсутствует на томе.  
Действие. Проверить поданную команду.

`?TFP-F-Недопустимая спецификация файла`  
Причина. Указана недопустимая спецификация файла.  
Действие. Проверить поданную команду.

`?TFP-F-"LOAD LP" или "AS XX DOC" и "LOAD XX"`  
Причина. Не загружен драйвер устройства «XX» или драйвер устройства печати.  
Действие. Использовать команду `LOAD` для загрузки драйверов устройств перед выполнением программы.

`?TFP-F-Ошибка чтения файла`  
Причина. Аппаратная ошибка при попытке чтения файла.  
Действие. Проверить правильность функционирования аппаратуры. Повторить операцию.

`?TFP-F-Вложенная директива .CPY игнорируется`  
Причина. Попытка использовать `.CPY` во вторичном файле.  
Действие. Удалить `.CPY` из вторичного файла.

`?TFP-W-Недопустимая директива в строке #NNNNNN`  
`PAUSE --`  
Причина. Недопустимая директива в строке «NNNNNN» исходного текста.  
Действие. Продолжить выполнение программы (нажать `<ВК>`), если текст выводится для проверки. В противном случае прервать выполнение программы (нажать `СУ/С`) и отредактировать исходный текст.

`?TFP-W-Невозможно открыть файл оглавления`  
Причина. На системном томе нет свободного места для файла оглавления.  
Действие. Проверить наличие свободного места на томе, проверить правильность функционирования аппаратуры.

`?TFP-I-Конец 1-го прохода; количество страниц — NNNNN`  
Причина. Конец первого прохода; `NNNNN` страниц распечатки.  
Действие. Информационное сообщение. Действий не требуется.

### 5.2. Сообщения редактора командной строки

Ниже приводятся сообщения, выдаваемые редактором командной строки.

`Начало строки`  
Причина. Попытка переслать курсор влево, когда курсор находится в начале строки.  
Действие. Ввести правильную командную строку.

`Конец строки`  
Причина. Попытка переслать курсор вправо, когда курсор находится в конце строки.  
Действие. Ввести правильную командную строку.

`Запрещённый символ`  
Причина. Использован недопустимый управляющий символ.  
Действие. Ввести допустимый управляющий символ.

`Запрещено`  
Причина. Использована недопустимая клавиша.  
Действие. Нажать допустимую клавишу.

`Строки не было`  
Причина. Попытка использовать клавишу «стрелка вверх», когда введённой строки не существует.  
Действие. Использовать допустимую функцию или команду.

`Граница строки`  
Причина. Попытка ввести командную строку, длина которой превышает допустимую.  
Действие. Ввести командную строку допустимой длины.

`Стираний не было`  
Причина. Попытка восстановить строку, когда строка отсутствует или не была уничтожена.  
Действие. Использовать допустимую функцию или команду.

`Команда запрещена`  
Причина. Введённая команда не поддерживается редактором командной строки.  
Действие. Ввести правильную командную строку.
